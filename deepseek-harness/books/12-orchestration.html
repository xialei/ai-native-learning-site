编排与多 Agent：委派缝、工作流、Ralph

一个 agent 够用，一群 agent 才叫 harness。dsh 的编排栈三层：委派缝（ctx.subagents，多 provider 注册表）、工作流（模型写的 JS 脚本在 worker thread 里 fan out 子 agent）、以及固定策略工具 ralph。每一层都建立在第 4 章的循环之上——子 agent 就是又一个 ReactLoopAgent。

12.1一分钟版本

  • ctx.subagents 是命名 provider 注册表：spawn（新子）/ fork（继承父已完成历史）/ acp / codex / claude-code / dsh-sdk 可共存，按名字选择。
  • 两种子 agent 形态：one-shot run（provider 全权建立→发布→所有权转移）与 continuable child（durable，续聊走消息与冷恢复）。
  • continuable 子 agent 的全部运行时（身份、组合、turn、teardown、冷恢复）归 continuation manager——provider 只贡献「是否带父历史」这一个创建参数，永远看不见子 agent 本体。
  • 工作流 = 模型写的纯 JS 编排脚本，跑在每 run 一个的 worker thread 里，agent()/parallel()/pipeline()/phase()/log() 经 typed 协议调回宿主；「containment, not a security boundary」。
  • ralph 是固定前台循环：每轮一个全新子 agent（无对话种子），跨轮只传一份有界结构化报告（maxRounds 默认 256），共享 workspace 是长期记忆。

typescriptexport interface SubagentProvider {
  name: string                       // 唯一注册名（'spawn' | 'fork' | 'acp'…）
  capabilities: SubagentCapabilities  // 启动期能力声明
  /** 子 agent 是否看到父的已完成 turn 前缀——纯描述性，
      模型工具由此生成真实措辞，不谈工具/服务继承 */
  readonly inheritsParentContext: boolean
  agentRouteDefaults?: { provider: string; model: string }

  /**
   * Establish a ONE-SHOT child and return its handle after publication.
   * Before fulfillment, the provider owns setup and cleans any unpublished
   * partial resources before rejecting. Ownership transfers on fulfillment.
   */
  start(request: ResolvedSubagentStartRequest): Promise<SubagentRun>

  /**
   * OPTIONAL (continuable-creation capability). 方法存在即能力：
   * 服务在无此方法的 provider 上拒绝 continuable 启动。
   * 这是 provider 对 continuable 子的唯一参与——continuation manager
   * 独占身份预留、组合、Agent 创建、prompt 送达、冷恢复、所有权与销毁，
   * provider 永远看不见子的 Agent、handle、turn 或 teardown。
   */
  prepareContinuable?(request: ContinuableCreateRequest): Promise<ContinuableCreateSpec>
}
「方法存在即能力」：optional prepareContinuable 的有无就是 capability 位——不需要额外的 capability 枚举。one-shot 的责任分界画在「发布」这一刻：发布前 provider 全责（含清理半成品），发布后所有权与失败结算归返回的 SubagentRun。这与第 1 章「fulfillment is the single publication and ownership-transfer boundary」的设计一脉相承。

与第 4 章的钩子严丝合缝：sendMessage 的三种目标状态（running → 最近 step 边界 / idle → 启动 turn / absent → 冷恢复）分别对应第 4 章的 inbox 待处理注入、whenIdle/wakeDriver 路径、以及第 5 章的持久化重载。子 agent 的会话是独立的 Session log，parentSession 记录父 session id——发现与时序由两个 session 投影（subagentTimingProjection / subagentIdentityProjection）从日志折叠。 Adjacency（只许直系父子互发）由服务从「exact live sender」派生——模型不能伪造发送者。

12.4工作流：worker thread 里的编排脚本

dsh-workflow 运行模型写的纯 JS 编排脚本，返回一个 run，其结果 resolve 为脚本最终 JSON 值。脚本可用的原语：

原语作用
agent(prompt, opts)fan out 一个子 agent（可带 schema 强制结构化输出）
parallel(thunks)并发并全部完成（barrier）
pipeline(items, ...stages)逐项穿过多阶段，无 barrier
phase(title) / log(msg)进度分组与叙述行
packages/workflow/workflow-worker-thread/README.md — 隔离立场（摘要）
text每个 run 一个 Node worker thread：编排脚本在全新 worker 里执行，
其 agent() 调用经 typed host/worker 协议到达宿主的 subagents。
同步脚本循环不会卡住 harness 事件循环；忽略取消的脚本
可以连 worker 一起终止。

The isolation is containment, not a security boundary —
模型写的脚本与模型既有的 bash 访问同一信任前提，
逃出 node:vm 上下文即恢复 worker 的进程权限。
不要把 worker thread 当真正不受信脚本的沙箱——
敌意代码需要独立进程或容器引擎。
两层隔离声明：worker thread 解决的是可用性（死循环脚本不卡宿主、可强制终止）而非安全性——README 明确划界。安全性走的是第 9 章的沙箱与审批。dsh-workflow 自身不执行任何脚本（「The package ships no execution engine」），dsh-workflow-worker-thread 是当前引擎——换一个隔离策略（独立进程、容器）不需要改 callers 或模型所见。这与 LLM 层（第 7 章）「协议与适配器分离」完全同构。agent() 的每次调用作为 published child run 归属到发起 agent（lifecycle 事件成对：established / settled），父 agent 因此能在会话日志里审计整棵 fan-out 树。

12.5ralph：新鲜 agent 循环

dsh-tool-ralph 是一个模型可调用的固定策略工具，实现在 workflow 脚本 API 之上（packages/workflow/tool-ralph/src/index.ts）：

packages/workflow/tool-ralph/src/index.ts:151 — Ralph 循环脚本（节选）
typescriptphase('Fresh-agent rounds')
for (let round = 1; round <= args.maxRounds; round += 1) {
  const prior = previous === undefined ? '(none — this is the first round)' : JSON.stringify(previous)
  const prompt = [
    'You are one fresh worker in a foreground Ralph loop. You receive no parent '
    + 'conversation and no prior child session. Do not call the ralph tool…',
    'Immutable objective:\n' + args.objective,
    'Ralph round: ' + round + ' of ' + args.maxRounds + '.',
    'The shared workspace and its current working tree are the long-term memory '
    + 'and source of truth. Inspect them before acting… Treat the previous report '
    + 'only as a bounded handoff; confirm it against the workspace.',
    'Previous structured handoff:\n' + prior,
    'Return one report with exact normalized strings…',
  ].join('\n\n')
  const rawReport = await agent(prompt, { schema: reportSchema })
  if (report.status === 'complete') return { status: 'complete', roundsStarted: round, report }
  if (report.status === 'blocked') return { status: 'blocked', roundsStarted: round, report }
  previous = report
}
return { status: 'budget-limited', roundsStarted: args.maxRounds, report: previous }
四个防呆：① 每轮子 agent 是全新的——「no parent conversation and no prior child session」，杜绝上下文腐化在轮间累积；② 跨轮只有一份 bounded 结构化报告（summary/evidence/nextSteps/blocker，超 maxHandoffChars 直接抛错）——记忆外置到共享 workspace，报告只是交接信；③ 报告校验极严：complete 必须有 evidence 且无 nextSteps 且 blocker 为空，blocked 必须有具体 blocker，continue 必须有 nextSteps——「completion and blockers are worker reports, not independent certification」（完成声明不是独立认证，人仍需复核）；④ maxRounds schema 默认 256（非传闻的 64），配 budget-limited 出口。README 明确划定适用场景：「Use it only when the direct human explicitly asks for a Ralph loop… ordinary long-running objectives belong to goal tools, and bounded delegation belongs to subagents or workflows」。

12.7要点

要点 ① 委派缝是注册表不是单实现：进程内与跨进程 provider 共存，模型工具不感知差异；② one-shot 与 continuable 分开建模，continuation manager 独占子的全部运行时，provider 只出创建参数；③ 工作流脚本隔离是 containment 不是 security，安全语义走沙箱/审批；④ ralph 用「新鲜 agent + 有界报告 + 外置记忆」对抗上下文腐化，报告校验与轮数上限防止无限循环。下一步是全书的收束：第 13 章：自制 Harness 路线图。
