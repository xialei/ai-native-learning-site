编排与多 Agent：委派缝、工作流、Ralph

一个 agent 够用，一群 agent 才叫 harness。dsh 的编排栈三层：委派缝（ctx.subagents，多 provider 注册表）、工作流（模型写的 JS 脚本在 PTC Node 进程里 fan out 子 agent）、以及固定策略工具 ralph。每一层都建立在第 4 章的循环之上——子 agent 就是又一个 ReactLoopAgent。

12.1一分钟版本

  • ctx.subagents 是命名 provider 注册表：spawn（新子）/ fork（继承父已完成历史）/ acp / codex / claude-code / dsh-sdk 可共存，按名字选择。
  • 两种子 agent 形态：one-shot run（provider 全权建立→发布→所有权转移）与 continuable child（durable，续聊走消息与冷恢复）。
  • continuable 子 agent 的全部运行时（身份、组合、turn、teardown、冷恢复）归 continuation manager——provider 只贡献「是否带父历史」这一个创建参数，永远看不见子 agent 本体。
  • 工作流 = 模型写的纯 JS 编排脚本，跑在每 run 一个的 PTC Node 进程里（受会话文件沙箱政策约束），agent()/parallel()/pipeline()/phase()/log() 经绑定协议调回宿主；「The VM … is not a security boundary」——网络访问不受文件政策限制。
  • ralph 是固定前台循环：每轮一个全新子 agent（无对话种子），跨轮只传一份有界结构化报告（maxRounds 默认 256），共享 workspace 是长期记忆。

「方法存在即能力」：optional prepareContinuable 的有无就是 capability 位——不需要额外的 capability 枚举。one-shot 的责任分界画在「发布」这一刻：发布前 provider 全责（含清理半成品），发布后所有权与失败结算归返回的 SubagentRun。这延续了第 1 章的「fulfillment is the single publication and ownership-transfer boundary」。

    不在场的直接子从持久化冷恢复。 */

/** 打断一个活跃 continuable 子的当前 turn。同步 void：只是投递打断意图，
    宿主协议侧另有 @Remote('interruptByParent') 的异步面，让父 Agent 离线时子仍可被打断。 */
interrupt(targetSessionId: SessionId, authority: SubagentInterruptAuthority): void
与第 4 章的钩子一一对应：sendMessage 的三种目标状态（running → 最近 step 边界 / idle → 启动 turn / absent → 冷恢复）分别对应第 4 章的 inbox 待处理注入、whenIdle/wakeDriver 路径、以及第 5 章的持久化重载。子 agent 的会话是独立的 Session log，parentSession 记录父 session id——发现与时序由 session 投影从日志折叠（subagentTimingProjection / subagentIdentityProjection；v0.1.5-rc 起新增第三个投影 subagentCatalog：父会话在子发布成功时追加一条 subagent/catalog 事件，直系子目录从这份父有的持久事实折叠，fork 继承前缀不计入）。 Adjacency（只许直系父子互发）由服务从「exact live sender」派生——模型不能伪造发送者。

两个旋钮管两件独立的事：maxDepth 是深度——委托工具没有自己的深度配置时从 settings 取（默认 1 = 只许直系子），显式工具深度（含 provider-managed）优先，resolveMaxDepth（index.ts:248）就是这条规则；深度 0 通过工具关掉委托，改动在下一次委托尝试时生效。maxActiveSubagents 是并发容量——限「共享不间断 continuable 父链的存活子」个数。实现在 continuation-activation.ts:41 的 ActivationPool：进程内一个 Set<symbol> 做槽位，物化（fresh 创建或冷恢复）前 reserve()，超容抛 ACTIVATION_LIMIT_REACHED（浏览器提示路径收到 subagent/delivery-unavailable）。池的继承规则值得记：非 continuable 父开新池且自己不占槽，continuable 后代继承同一池；等待中的父、待投递 inbox、正在停止的 Activation 都占槽；常驻子复用自己的槽；one-shot 父不跨池。满员时不排队——排队会让等待后代的父同时占着自己的槽死锁。槽位是进程本地的，不约束累计会话历史或 token 用量。这延续了第 5 章「状态在日志、进程只是缓存」的立场：容量是活体属性，不是持久事实。

12.4工作流：PTC Node 进程里的编排脚本

dsh-workflow 运行模型写的纯 JS 编排脚本，返回一个 run，其结果 resolve 为脚本最终 JSON 值。脚本可用的原语：

原语作用
agent(prompt, opts)fan out 一个子 agent（可带 schema 强制结构化输出）
parallel(thunks)并发并全部完成（barrier）
pipeline(items, ...stages)逐项穿过多阶段，无 barrier
phase(title) / log(msg)进度分组与叙述行
packages/workflow/workflow-ptc/README.md — 执行与隔离立场（摘要）
text编排脚本在 fresh Node 进程里执行，受调用 Session 的
文件沙箱政策约束；agent() 调用经 PTC 绑定协议到达宿主的
subagents。PTC 进程级限制（堆/输出/终止）由 ptc-runtime
provider 决定，取消立即中止进程与活动子 agent。

The VM retains the documented helper API, but it is
not a security boundary: code that reaches Node remains
subject to the selected OS file policy. The program-visible
environment is empty. Network access is not restricted
by the file policy.
两层隔离声明：PTC 引擎解决的是可用性（脚本跑在受管进程里、取消可连同进程终止）而非安全性——README 明确划界：node:vm 只是护栏，抵达 Node 的代码受所选 OS 文件政策约束。安全性走的是第 9 章的沙箱与审批。dsh-workflow 自身不执行任何脚本（README 原话：「The caller must supply an execution engine, allowing the isolation strategy to change without altering visible behavior.」），dsh-workflow-ptc 是当前引擎——它复用第 6 章 PTC 的那个 fresh-Node-进程运行时，引擎与 PTC 共享同一个执行 provider。这与 LLM 层（第 7 章）「协议与适配器分离」完全同构。agent() 的每次调用作为 published child run 归属到发起 agent，父 agent 因此能在会话日志里审计整棵 fan-out 树。这里有两组生命周期事件，名字不要混：引擎自身发 workflow/start → workflow/agent-start → workflow/agent-end → workflow/end（后两个按 agent.seq 配对，一次 started 调用在每条停止路径上都恰好有一个 end，引擎终止路径上合成的 end 带 'cancelled'（WorkflowStopReason 只有 completed | cancelled | error）；tool-workflow 再把它们落成会话事件 tool-workflow/run-start|agent-start|agent-end|run-end。「established」「settled」是这两组事件的 JSDoc 用词，不是事件名。

12.5ralph：新鲜 agent 循环

dsh-tool-ralph 是一个模型可调用的固定策略工具，实现在 workflow 脚本 API 之上（packages/workflow/tool-ralph/src/index.ts）：

packages/workflow/tool-ralph/src/index.ts:151 — Ralph 循环脚本（节选）
typescriptphase('Fresh-agent rounds')
for (let round = 1; round <= args.maxRounds; round += 1) {
  const prior = previous === undefined ? '(none — this is the first round)' : JSON.stringify(previous)
  const prompt = [
    'You are one fresh worker in a foreground Ralph loop. You receive no parent '
    + 'conversation and no prior child session. Do not call the ralph tool…',
    'Immutable objective:\n' + args.objective,
    'Ralph round: ' + round + ' of ' + args.maxRounds + '.',
    'The shared workspace and its current working tree are the long-term memory '
    + 'and source of truth. Inspect them before acting… Treat the previous report '
    + 'only as a bounded handoff; confirm it against the workspace.',
    'Previous structured handoff:\n' + prior,
    'Return one report with exact normalized strings…',
  ].join('\n\n')
  const rawReport = await agent(prompt, { schema: reportSchema })
  // …rawReport 为 null 时返回 round-failed（脚本原文，此处略过）…
  const report = validateReport(rawReport)   // ← 报告校验入口，防呆③ 就是它
  if (report.status === 'complete') return { status: 'complete', roundsStarted: round, report }
  if (report.status === 'blocked') return { status: 'blocked', roundsStarted: round, report }
  previous = report
}
return { status: 'budget-limited', roundsStarted: args.maxRounds, report: previous }
四个防呆：① 每轮子 agent 是全新的——「no parent conversation and no prior child session」，杜绝上下文腐化在轮间累积；② 跨轮只有一份 bounded 结构化报告（summary/evidence/nextSteps/blocker，超 maxHandoffChars 直接抛错）——记忆外置到共享 workspace，报告只是交接信；③ 报告校验极严：complete 必须有 evidence 且无 nextSteps 且 blocker 为空，blocked 必须有具体 blocker，continue 必须有 nextSteps——「completion and blockers are worker reports, not independent certification」（完成声明不是独立认证，人仍需复核）；④ maxRounds schema 默认 256，但 base bundle 行和全部出厂预设都把它配成 64 且 disabled: true（「Off by default… An overlay row restores it」——工具描述把 ralph 限制在人类显式要求的运行里，overlay 行可恢复），配 budget-limited 出口。README 明确划定适用场景：「Use it only when the direct human explicitly asks for a Ralph loop… ordinary long-running objectives belong to goal tools, and bounded delegation belongs to subagents or workflows」。

12.7要点

要点 ① 委派缝是注册表不是单实现：进程内与跨进程 provider 共存，模型工具不感知差异；② one-shot 与 continuable 分开建模，continuation manager 独占子的全部运行时，provider 只出创建参数；③ 委托的两个旋钮分开管深度与并发容量，容量是进程本地的槽位协议，满员不排队；④ 工作流脚本隔离是 containment 不是 security，安全语义走沙箱/审批；⑤ ralph 用「新鲜 agent + 有界报告 + 外置记忆」对抗上下文腐化，报告校验与轮数上限防止无限循环。下一步是全书的收束：第 13 章：自制 Harness 路线图。
