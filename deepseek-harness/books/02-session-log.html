会话日志：一条 append-only 事件流是唯一事实

问题：同一个会话，模型要读、人要看、崩了要恢复、fork 要切——一份状态怎么同时服务这四个消费者还不互相打架？dsh 的答案是「只有一条 append-only 的 SessionEvent 日志，其余全是投影」。本章回答四个问题：日志里能记什么（①）、日志怎么变成模型历史（②）、新增模型可见输入的第一步是什么（③）、格式演进怎么保证旧日志还能读（④）。2.1 摆问题，2.2–2.6 逐个作答，2.7 收尾回收。

2.1问题：一份状态，四个消费者

先摆出设计会话状态时绕不开的四个问题：

  • ① 日志里能记什么？模型的请求历史、token 计账、工具调用原文、每次失败尝试……哪些该进持久日志、哪些只是进程内转瞬即逝？分界线画在哪里？
  • ② 日志怎么变成模型历史？日志是事件流，模型要的是有序消息数组——中间的折叠规则是什么？增量怎么做才不退化为每次全量重算？
  • ③ 新增一种模型可见输入，第一步做什么？文件变更通知、子目录 AGENTS.md、被 offload 的图……想让模型看到新东西，从哪里开始、不破坏既有消费者？
  • ④ 格式演进怎么不弄坏旧日志？运行时升级了，事件词汇表变了、结构变了，三个月前落盘的会话还能读吗？谁决定要不要升版本号？

四个问题共享同一个前提：一切消费方向（模型请求、UI 转录、崩溃恢复、fork）必须能从同一份持久数据重建，且互不相同步也互不矛盾。dsh 对这四个问题的回答分别是：类型化的 SessionEventMap 词汇表（2.2）＋五类表面事件的投影规则（2.3）＋ O(新节点) 增量折叠（2.4）＋「Model-visible means logged」铁律（2.5）＋ ignorable 逐事件标注与版本递增规则（2.6）。

四个问题，四节答案：① 词汇表 → 2.2；② 投影 → 2.3 摆表面资格、2.4 看折叠实现；③ 铁律 → 2.5；④ 演进 → 2.6。2.7 收尾把答案收回来。

2.2① 核心事件词汇表

核心 SessionEventMap 定义在 packages/core/session/src/types.ts（SESSION_FORMAT_VERSION = 4，types.ts:89）。每个事件都带精确的契约注释，摘录关键部分：

packages/core/session/src/types.ts — SessionEventMap（节选）
typescriptexport interface SessionEventMap {
  /** Opens turn `turn` before the loop claims queued input or runs pre-step. */
  'turn/start': { turn: number }

  /**
   * Closes turn `turn` with the TurnEndReason that ended it. A turn
   * with no entered step has no `step/start` or `step/end`. The loop does not
   * await a flush at turn boundaries: `dsh-session-checkpoint-policy` owns the
   * per-request durability checkpoint, and consumers that read storage after
   * `whenIdle()` flush themselves.
   */
  'turn/end': { turn: number; reason: TurnEndReason }

  /** Opens step `step` of turn `turn` — one model call plus the tool executions it requested. */
  'step/start': { turn: number; step: number }
  'step/end': { turn: number; step: number }

  /**
   * A user-role message on the model-visible surface: a direct human prompt,
   * a synthetic `agent.inject()` context (file-change notices, subdir
   * AGENTS.md, skill content, cron notifications, …), or an entered goal
   * continuation round. All three project their `content` verbatim;
   * `source` tells them apart.
   */
  'user/message': UserMessage

  /**
   * An incremental agent session change admitted at the named turn and step.
   * V4 新增的第五种表面事件：developer 角色消息，当前承载工具的
   * tool-addition / tool-removal 块。addition 只存 toolName（模式来自
   * headerSeq 引用的历史 request/header），removal 只存工具名。
   */
  'developer/message': {
    turn: number
    step: number
    message: DeveloperMessage
    /** Earlier request/header defining every tool addition; required exactly when additions are present. */
    headerSeq?: SessionSeq
  }

  /**
   * The rendered system prompt on the model-visible surface. The loop appends
   * the first one as surface node 0 before the step's first `user/message`.
   * A prepared in-history route can append nonempty changes in a continuing
   * series. An incapable route or new series normalizes text to the first
   * system node. Normalization empties nonempty later nodes, then rewrites
   * the head if needed. An empty rendering always clears all active system
   * nodes, leaving no older instructions model-visible.
   */
  'system/message': { turn: number; step: number; message: SystemMessage }

  /**
   * Assembled assistant message for one step. Carries the step's `usage`
   * when the adapter reported token accounting. A turn cancelled mid-stream
   * finalizes its delivered text/reasoning prefix as this event with
   * `interrupted: true`; undispatched tool calls are absent.
   */
  'assistant/message': {
    turn: number
    step: number
    message: AssistantMessage
    /** Exact timed model stream, compacted without joining delta boundaries. */
    stream: AssistantStreamRecord[]
    usage?: TokenUsage
    interrupted?: true
  }

  /**
   * One model attempt that committed no surface message: a failed, retried,
   * cancelled, or stream-error attempt that reached settlement — without
   * fabricating model-visible history.
   */
  'assistant/attempt': { turn: number; step: number; stream: AssistantStreamRecord[] }

  /**
   * The model requested one tool invocation: `name` with the raw `arguments`
   * JSON string exactly as the model produced it (unparsed).
   */
  'tool/call': { turn: number; step: number; callId: ToolCallId; name: string; arguments: string }

  /**
   * A completed tool call's model-facing result, optional internal failure
   * identity, and optional tool-private `meta` presentation payload. `meta`
   * is opaque to the core (the producing tool owns its shape and reads it
   * back in `presentResult`) but MUST be JSON-serializable: `Session.append`
   * runtime-validates all event data with `isJsonValue`.
   */
  'tool/result': {
    turn: number
    step: number
    message: ToolResultMessage
    /** Optional failure identity, outside model content; allowed only when the message has isError: true. */
    error?: { name: string; code: string; reason?: string }
    meta?: JsonValue
  }

  /**
   * Full header for the next request, appended inside its step before
   * dispatch. Log-only; the latest snapshot reconstructs the request header.
   */
  'request/header': {
    header: EpochHeader
    reason: RequestHeaderReason  // 'initial' | 'resume' | 'change' | 'series'
    startsSeries?: true
  }

  /**
   * Route metadata for the next request, logged only when the route or
   * capacity or system prompt update mode changes. Not part of request
   * reconstruction or header equality.
   */
  'request/context': RequestContext

  /**
   * Marks the end of a constructor seed (resume, fork, or replay). Events
   * before it have smaller seq values and came from the seed; this lifecycle
   * produced none of them. The Session constructor is the only legitimate
   * writer.
   */
  'session/end-seed': { inherited?: true }
}
设计要点：① assistant/message 把产生它的完整计时流内嵌进来——输出与 token 记账同进同出，没有独立的 usage 记录；② tool/call 保存模型产出的原始未解析 JSON 字符串；③ request/header / request/context / session/end-seed 是 log-only 事件，只服务审计与重建，不上表面。
V4 新增的两件事：① developer/message 事件与 DeveloperMessage（role 'developer'）——工具的动态增删第一次有了模型可见的持久位置（types.ts:311），配套两个新内容块 tool-addition / tool-removal（llm/src/types.ts:116/:128）；② tool/result 事件里的 ToolResultMessage 从「user 角色 + tool-result 包装块」升为一等 tool 角色消息（role 'tool'，携带 toolCallId/isError，message.ts:173）。v3 的 ContentBlockMap 里的 tool-result 块在 V4 已删除——块的九成员表见 2.6 的 Map 总表。

2.3② 表面（Surface）：五类事件 + 两种入场方式

不是所有事件都进入「模型可见历史」。表面资格由两个类型精确刻画（packages/core/session/src/types.ts:439）：

packages/core/session/src/types.ts:439
typescript/** 只有这五类事件产生 LLM 消息、可以出现在有序表面上。 */
export type SurfaceEventType =
  | 'system/message'
  | 'developer/message'
  | 'user/message'
  | 'assistant/message'
  | 'tool/result'

/**
 * 一个表面事件如何进入有序表面。只在 SurfaceEventType 上有效。
 * - 'append'：追加到尾部 —— 系统/用户/助手/工具消息的常规路径。
 * - { op: 'replace', startSeq, endSeq }：替换表面节点 [startSeq, endSeq]
 *   （闭区间）为当前节点。节点的 sourceEventSeqs 必须包含所有被遮蔽的
 *   表面节点。由 compaction 使用；任何做表面替换的生产者都可用。
 */
export type SurfaceOp =
  | 'append'
  | { op: 'replace'; startSeq: SessionSeq; endSeq: SessionSeq }
为什么这么严：注释明确说 surfaceOp 在消息类事件上强制存在、在 log-only 事件上禁止存在，编译器在 Session.append() 调用点强制执行。assistant/message 内嵌流、不能携带 sourceEventSeqs。类别成员的两次扩张都是「影响重建语义」的 bump：v3 把 system/message 提升为表面事件（系统提示词成为日志中可见的节点，SurfaceOp.replace 端点同时规范化为 startSeq/endSeq）；V4 又把 developer/message 提为第五类——工具增删现在以 developer 角色出现在历史里。空内容的 system/developer 节点保留表面位置但不派生消息（surface.ts:145 附近的派生分支），developer 事件与 developer 角色必须同时出现，缺一即拒（surface.ts:180）。

事件信封上有两个关键字段（同文件）：

packages/core/session/src/types.ts — SessionEvent 信封（节选）
typescriptexport type SessionEvent<T extends SessionEventType = SessionEventType> = {
  [K in SessionEventType]: {
    type: K
    /** Monotonic sequence number within the session. */
    seq: SessionSeq
    /** Unix epoch milliseconds. */
    time: number
    data: SessionEventMap[K]
    /**
     * Marks an event a reader may safely skip when it does not recognize
     * `type`. Absent means required: a reader meeting an unrecognized type
     * without this marker MUST refuse to reconstruct the session instead of
     * silently dropping the event, because an unrecognized required event may
     * change how the rest of the log is interpreted.
     */
    ignorable?: true
  } & /* surfaceOp + sourceEventSeqs 仅存在于 SurfaceEventType 变体上 */
}
设计哲学 ignorable 的默认值是「必需」：忘写标记的代价是过度拒绝（不方便），而默认可跳过的代价是静默续读一个被掏空的会话（正确性事故）。宁可不方便，不可不正确。

2.4② 投影：deriveMessages() 如何从日志得到模型历史

模型历史从不单独存储，它是对表面节点的折叠。核心实现带一个精细的增量缓存（packages/core/session/src/index.ts）：

packages/core/session/src/index.ts — deriveMessages()（节选）
typescript  /** The derived-message cache: frozen projections, extended per unseen node. */
  private derived: Message[] = []
  /** Surface position (nodes projected) the cache has reached. */
  private derivedNodes = 0
  /** {@link SurfaceManager.contentGeneration} the cache was built under. */
  private derivedGeneration = 0

  /**
   * Derive the LLM message history by walking the ordered sequences of
   * message-producing events maintained by `surfaceOp` markers. The
   * surface is the single source of derived history: every message-producing
   * append records its `surfaceOp`, so a raw event with no marker (a chunk, a
   * turn boundary) is correctly absent, and a compaction `replace` deletes the
   * shadowed nodes from the derivation.
   *
   * CACHED: pure tail growth costs O(new nodes); a replacement or message
   * projection ({@link SessionSurface.contentGeneration}) rebuilds. The
   * returned array is a fresh snapshot per call; the `Message` objects in
   * it are SHARED and **deep-frozen**. Unchanged content reuses frozen
   * event data; projected blocks are frozen derived copies. Consumers
   * cannot mutate the log through either form.
   */
  deriveMessages(): Message[] {
    const surface = this.surface
    const nodes = surface.nodes
    const generation = surface.contentGeneration
    if (generation !== this.derivedGeneration) {
      this.derived = []
      this.derivedNodes = 0
      this.derivedGeneration = generation
    }
    for (const seq of nodes.slice(this.derivedNodes)) {
      const msg = this.deriveEventMessage(this.log[seq]!)
      // 空内容的 assistant/message（只承载 usage 的 max-tokens step）
      // 派生为 null，不进入转录。
      if (msg) this.derived.push(msg)
    }
    this.derivedNodes = nodes.length
    return [...this.derived]
  }
三个不变量：① 没带 surfaceOp 的裸事件（chunk、回合边界）天然缺席历史；② compaction 的 replace 会把被遮蔽节点从派生中删除（通过 contentGeneration 使缓存失效重建——替换和插件侧的消息投影共用这一个计数）；③ 返回数组每次是新快照，里面的 Message 对象是共享且深冻结的——消费者拿到的历史不可变，日志也不可能被改。

②里那句「插件侧的消息投影」是 v0.1.6 wave 落地的新机制，值得单独说清楚。image/offload 这类事件的模型可见效果不能靠默认派生规则得到——它需要把某个 user/message / tool/result 节点里的部分 image block 换成占位文本。会话子系统为此提供了 SessionMessageProjection { type, project(event, context) → ReadonlyMap<SessionSeq, Message> }：插件用 sessions.registerMessageProjection() 注册自己事件类型的纯解释器（重复 type 直接抛错；dispose 后再用该事件的会话会拒绝继续派生——fail-closed）。注册表在 known-event-types.ts 的 MESSAGE_PROJECTION_EVENT_TYPES 里列硬要求：声明进 SessionEventMap 的事件若标了 @messageProjection，没有对应解释器时 append/restore/fold 直接报错。折叠入口 foldSurface 返回值多了 projectedMessages，deriveEventMessage(event, projectedMessages?) 优先查这张表——离线读者（fork、detached replay）必须显式传入同前缀的投影，否则读到的是原始内容。这使得「被 offload 的图」在所有读路径上一致地变回占位符，而不需要任何人重写日志。

顺带的 API 卫生 同一个 wave 把同步读日志的三个入口 eventAt() / snapshotEvents() / ownEvents() 标了 @deprecated——「Existing logic may remain unmigrated for now, but new calls are prohibited」（存量逻辑可暂不迁移，新调用禁止），指向设计笔记 2026-09-09-deprecate-synchronous-session-event-reads。语义取代者分别是：增量表面节点（surface.nodes）、投影与分页。讽刺的是 image-offload 自己还在用 eventAt()——带着 waiver 注释「Existing Session history read; migration deferred」。自家园丁也逃不过存量。

2.5③ Model-visible means logged

这是整个会话子系统的第一不变量（docs/architecture.md）：

铁律 任何到达模型请求的内容，都必须能从日志重建——运行时有不变量断言强制这一点。所以「新增一种模型可见输入」的第一步永远是：扩展 SessionEventMap，然后从日志渲染。若默认派生规则表达不了效果（比如把图换成占位符），再加一个插件自有的 SessionMessageProjection 纯解释器（§2.4）。反过来，文件变更通知、子目录 AGENTS.md、skill 内容、cron 通知这些 agent.inject() 注入物，最终都以 user/message（带区分用的 source）落日志。

这条铁律带来的直接收益：fork、resume、转录、遥测、持久化全部从同一份持久结算（assistant/message 与 assistant/attempt）派生，彼此不可能不一致。唯一的例外是 UI 的增量渲染——它消费进程内的 agent/assistant-stream live 事件，而进程崩溃时未结算的流不会留下任何持久痕迹（这是有意为之：宁缺勿假）。

2.6④ 格式版本与演进规则

SESSION_FORMAT_VERSION = 4（packages/core/session/src/types.ts:89）。它上方注释给出了版本号何时递增的完整决策规则，值得全文细读：

packages/core/session/src/types.ts — 版本号递增规则（注释节选）
text/**
 * Current logical Session format version, stamped into every newly written
 * SessionHeader. The version is a single monotonic integer with no
 * major/minor split. Whether a bump is needed is decided by what the WRITER
 * emits, never by what a newer reader can accept: bump exactly when an older
 * runtime could no longer handle a new log with full semantic correctness
 * ("parses without error" is not correctness — silently skipping content
 * that shapes reconstruction is a wrong read). Only structural changes reach
 * that bar: the header shape, the SessionEvent envelope, core event
 * semantics, or the surface mechanism (the SurfaceEventType set and
 * SurfaceOp variants). Adding an ordinary event type does not bump — the
 * per-event ignorable guard covers vocabulary growth instead. When in
 * doubt, bump: a near-identity upgrade step is almost free, a missed bump
 * makes older runtimes read new logs wrong silently.
 */
三个要点：① 由写入方决定是否 bump，而不是读取方的宽容度；② 「能解析」不等于「读对了」——跳过影响重建语义的内容就是错误读取；③ 普通加事件类型不触发 bump，靠 ignorable 兜底；拿不准就 bump，因为近似恒等的迁移步骤几乎免费。v2 → v3、v3 → v4 两次 bump 都是现成例子：v3 把系统提示词升为表面事件、SurfaceOp 端点改名；V4 新增 developer 角色与工具增删块、tool-result 块退役（内容结构变化，影响重建语义）。JSONL 命名规则与完整迁移链在第 5 章展开。

与 role 扩张配套的是一条退役：v3 的 EpochHeader.system（把系统提示词文本存进请求头）在 V4 里保留为类型占位 system?: never，标 @persistenceReserved（types.ts:246 附近）——头里不再有系统提示词，它属于 surface 节点 0 的 system/message 事件。占位字段的意义是「谁敢再写这个键，编译期就报错」，而不是兼容期宽容。

配套的是一组 branded ID（SessionId、SessionSeq、SessionLogOffset、ToolCallId…）——不同 ID 类型互相不可赋值，把「拿错 ID」从运行时 bug 变成编译错误。

2.7收尾：四个问题的答案

答案回收 ① 日志记什么 → 类型化 SessionEventMap 词汇表：边界事件、五类表面事件（V4 起 system/developer/user/assistant/tool）、工具调用原文、请求头快照，外加插件合并事件；token 计账内嵌在 assistant/message 里。② 模型历史 → 表面节点的折叠：deriveMessages() 带 O(新节点) 增量缓存，replace 靠 contentGeneration 失效重建。③ 新增模型可见输入 → 先扩 SessionEventMap（铁律「Model-visible means logged」），默认派生不够再加插件自有投影。④ 演进 → 写入方决定 bump；ignorable 管词汇表增长，结构变化才升版本号；v3→v4 的迁移包（只改头声明 + 显式子会话证据 + liftToolResult）是最新样本。下一步进入 第 3 章：一次对话的完整生命周期。

最后把 2.6 留下的 v3 → v4 迁移补完整。packages/session/session-format-v3-to-v4 的迁移声明是只有头的（migration.ts:14 注释原话 "Header-only migration declaration; body restoration requires explicit child evidence"）——migrateHeader 只把 version 3 改写成 4 并校验头，createStage() 直接抛 SessionFormatUnsupportedMigrationError。因为 V4 引入了「父/子目录代际」概念（子 agent 会话自己成了持久代际文件），体迁移必须由调用方显式给出该父会话的历史子代际证据（createSessionFormatV3ToV4(children)，无子会话也要传空数组）。体转换三件事：liftToolResult 把 v3 的 user 角色 tool-result 包装块升为一等 tool 角色消息（tool-role.ts:36，包装不匹配即拒，不静默截断）；migrateV3EventContent 改写内容标签并拒绝退役的 tool-result 内容（cbb4df8750）；未知插件来源加 plugin: 前缀命名空间。这体现了 2.6 的原则：宁可显式失败，不静默给出一个看起来能读的会话。
