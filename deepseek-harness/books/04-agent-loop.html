Agent 循环实现：ReactLoopAgent 的并发模型

第 3 章沿时间轴走了一遍 turn/step；这一章换个视角，看循环的「操作系统层」：三态 Phase 状态机、三种消息注入、唤醒闩锁、维护窗口，以及每个 Agent 独享的 Scope——这些机制让 steer/inject/cancel 在任何时刻都语义明确。

4.1一分钟版本

  • 循环类是 ReactLoopAgent（packages/core/agent-loop/src/agent.ts），实现 Agent 接口，ctx 键 ctx.agentLoop。
  • Phase 三态：idle（无活动）→ running（kick 驱动中，有 AbortController + turn/step 计数）→ maintenance（维护任务独占）。
  • 三种注入 API：followup（next-turn + 唤醒）、steer（next-step + 唤醒）、inject（next-step、不唤醒）。
  • 唤醒不丢失：running/maintenance/aborted 期间到达的 wake 被闩锁（wakeRequested），收敛后重放。
  • 每个 Agent 有自己的 Scope（createScope(loopCtx, this)），scope 级注册在驱动器退出后被回卷。

图 4-1 — Phase 状态机。状态经 setPhase() 变更，对外只发布一次 agent/status 事件（状态未变则不发布）。
关键不变量：驱动器（kick）在进入前拥有 running phase、退出后才交还 idle；status getter 把 maintenance 也归为对外可见的 'idle'——维护中不接活，但也不算「在跑 turn」。取消（cancel）通过 AbortController 传递 cause，AbortController 由每次唤醒新建，因此取消天然限定在当前活动内。

4.3用代码看：send() 与三种注入

三个公开 API 都是同一个 send 原语的便捷形式。注意 wakingAfterAbort 的捕获点——在 splice 之前，这样 splice 观察者里的重入 cancel 无法改写分类（packages/core/agent-loop/src/agent.ts:127）：

packages/core/agent-loop/src/agent.ts
typescript  send(message: UserMessage, target: InboxTarget, wakeup: boolean): void {
    // 唤醒型输入不能加入已被中止的活动，所以改投下一回合。
    // 在插入前捕获，避免 splice 观察者里的重入 cancel 重新分类。
    const wakingAfterAbort = wakeup && this.phase.kind !== 'idle' && this.phase.abort.signal.aborted
    const resolvedTarget = wakingAfterAbort ? 'next-turn' : target
    this.inbox.splice(resolvedTarget, Infinity, 0, [message])
    if (wakeup) this.wakeDriver(wakingAfterAbort)
  }

  followup(input: UserMessage): void {
    this.send(input, 'next-turn', true)
  }

  steer(input: UserMessage): void {
    this.send(input, 'next-step', true)
  }

  inject(input: UserMessage): void {
    this.send(input, 'next-step', false)
  }

  cancel(cause: AgentCancelCause, options: CancelOptions = {}): void {
    if (!options.keepInbox) {
      this.inbox.clear()
      if (this.phase.kind !== 'idle') this.phase.wakeRequested = false
    }
    if (this.phase.kind !== 'idle') this.phase.abort.abort(cause)
  }
APItarget唤醒？语义
followupnext-turn是本回合结束后开启新回合（对话的下一句）
steernext-step是下一步立刻看到（用户打断纠正方向）
injectnext-step否安静排队，等别的消息来唤醒（文件变更通知、skill 内容等）
为什么 abort 后要重分类：唤醒型消息若落在一个已中止的 running 活动里，它不会被消费——放到 next-turn 保证它在下一个回合边界出现，而不是消失在旧活动的收尾里。而 cancel({keepInbox: true}) 保留队列只中止活动，正是「打断当前动作、保留排队输入」的组合拳。

4.4用代码看：wakeDriver() 的闩锁

唤醒在「没人在听」时会丢吗？不会——被闩住等重放（packages/core/agent-loop/src/agent.ts:191）：

packages/core/agent-loop/src/agent.ts — wakeDriver()
typescript  /**
   * Start one driver, or latch its wake behind maintenance or an aborted
   * activity. A wake sent while idle always opens its turn boundary, even
   * when its message was cleared; only a latched replay is suppressed when
   * the queue no longer holds the wake.
   */
  private wakeDriver(wakeAfterAbort = false): void {
    if (this.phase.kind !== 'idle') {
      // Maintenance 与 aborted 驱动器无法送达唤醒：闩起来在收敛点重放。
      // 存活中的驱动器自己认领排队工作；disposal 永不闩锁，
      // 因此 teardown 不必等待任何模型回合。
      const reason = this.phase.abort.signal.reason as AgentCancelCause | undefined
      if (reason?.kind !== 'disposed' && (this.phase.kind === 'maintenance' || wakeAfterAbort)) {
        this.phase.wakeRequested = true
      }
      return
    }
    const driver = Promise.withResolvers<void>()
    this.activityDone = driver.promise
    this.setPhase({
      kind: 'running',
      abort: new AbortController(),
      turn: this.phase.lastTurn,
      step: 0,
      wakeRequested: false,
    })
    this.loopCtx.agents.withInitiator(this, () => this.kick()).then(driver.resolve, driver.reject)
  }

  async whenIdle(): Promise<void> {
    let activity: Promise<void>
    do {
      await (activity = this.activityDone)
    } while (activity !== this.activityDone)   // 等待期间又有新活动？继续等
  }
三个细节：① 闩锁只在 maintenance 或「唤醒落在已中止活动」时设置，且 disposed 原因永不闩锁——卸载不等模型回合；② whenIdle() 的 do-while 是防竞态写法：等待期间 activityDone 被换成新活动的 Promise，就继续等新的那个；③ 每次唤醒都新建 AbortController + 新 running phase，phase.turn 从 lastTurn 续起。

4.5用代码看：kick() 与驱动的收尾

packages/core/agent-loop/src/agent.ts:222
typescript  private async kick(): Promise<void> {
    try {
      while (await this.turn()) {}      // turn() 返回 true = 还有排队输入，继续
    } catch (_error) {
      // 已报告的失败与取消在驱动器边界被收纳。
    } finally {
      if (this.phase.kind === 'running') {
        const { turn, wakeRequested } = this.phase
        this.setPhase({ kind: 'idle', lastTurn: turn })
        if (wakeRequested && this.inbox.hasPending) this.wakeDriver()  // 闩锁重放
      }
    }
  }

失败如何「在活体边界被报告」？throwError 先以 agent/error（emit，不等待）发布，再重新抛出交给 kick 的 catch：

packages/core/agent-loop/src/agent.ts — throwError()
typescript  private throwError(error: unknown): never {
    const turn = this.phase.kind === 'running' ? this.phase.turn : this.phase.lastTurn
    const step = this.phase.kind === 'running' ? this.phase.step : 0
    this.dispatch.emit('agent/error', { turn, step, error })
    throw error
  }
containment 三层：错误先变成 turn/end {reason: error} 的持久事实，再变成 agent/error 的 live 广播，最后在 kick 边界被吞掉（不再向上炸栈）——驱动器永不因为一次失败而死亡，whenIdle() 的等待者也总能等到收敛。

4.6Agent 级 Scope：每个循环实例自己的注册边界

构造函数里两行决定了「每个 Agent 是一个隔离的注册世界」（packages/core/agent-loop/src/agent.ts:106）：

packages/core/agent-loop/src/agent.ts — 构造函数（节选）
typescript    this.dispatch = agentEvents(loopCtx, this)   // 融合派发器：热路径零分配
    this.inbox = new Inbox(session, {
      inserted: (message) => { this.dispatch.emit('agent/inbox/inserted', { message }) },
      discarded: (message) => { this.dispatch.emit('agent/inbox/discarded', { message }) },
      claimed: (message, turn) => { this.dispatch.emit('agent/inbox/claimed', { message, turn }) },
    })
    const lastTurn = this.loopCtx.sessionProjections.stateOf(session, 'turnBoundary')?.lastTurn ?? 0
    this.phase = { kind: 'idle', lastTurn }    // ← 从持久投影恢复回合计数
    this.scope = createScope(loopCtx, this)
    this.ctx = this.scope.ctx.extend({ agent: this })
    this.runtimeContext = new RuntimeContextProjection(this.ctx, session)
三个事实：① 热路径派发器 agentEvents(loopCtx, this) 构造一次、复用终生（注释原话：hot-path dispatches never allocate）；② 回合计数 lastTurn 不是内存猜的，而是从 turnBoundary 持久投影单元读的——重启后回合号继续递增；③ this.ctx 在 scope 的 ctx 上扩展了 agent: this，所以工具、pre-step 监听器拿到的 exec.agent / payload.agent 就是这个实例。scope 的注册（第 8 章详述）在驱动器退出后被生命周期所有者回卷。

4.8要点

要点 ① Phase 三态 + 每活动独立 AbortController = 取消语义可推理；② followup/steer/inject 三个 API 是同一 send 原语的坐标组合，abort 后的唤醒自动重分类；③ 唤醒闩锁保证「没有任何输入会静默丢失」（除 disposed）；④ 错误被三层收容：持久 turn/end → live agent/error → 驱动器边界吞掉。下一步进入 第 5 章：持久化与崩溃恢复。
