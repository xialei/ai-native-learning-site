自制 Harness 路线图：从 MVP 到完整生态

读完 12 章源码，最后回答一个问题：如果从零写你自己的 harness，该按什么顺序长出什么？这一章先讲清 dsh 对外的三张面孔（CLI profile / SDK / Web），再把「能力缝配方」提炼成可复用的清单，最后给一条按不变量排序的路线图。

13.1一分钟版本

  • dsh 的应用形态由 profile bundle 决定：dsh --profile web|headless|acp|sdk 都叠在 dsh-base 之上；bundle 只是「可安装的 patch 层」，不引入第二种启动机制。
  • SDK 是跨进程面孔：newline 分隔的 JSON-RPC over stdio，三个请求方法 + 四个通知；TypeScript 与 Python 客户端互为设计孪生，驱动同一套协议。
  • SDK 客户端 spawn 一个完整运行时子进程（同版本强校验、--profile sdk、有序 patch），高层 DeepSeekHarness 管生命周期，低层 HarnessClient 管 wire。
  • Web host 是纯路由注册表：exact → 最长前缀 → 唯一 fallback 座位；「knows no harness concepts and serves no files」，dist 与 /api 都属于注册方插件。
  • 自制路线图：append-only 日志 → 循环 → 工具缝 → LLM 适配层 → 沙箱/审批 → 压缩 → 编排 → 对外面孔。每一步都先立不变量，再长功能。

13.2profile bundle：一个内核，五张面孔

第 1 章说过 dsh 是「组合出来的应用」。这份组合清单本身也是仓库的一部分——packages/bundle/ 里每个包声明 dsh.bundle.patch，启动器把它们叠成命名 profile：

bundle形态一句话
dsh-base共享内核模型接入、全套工具、持久会话、安全默认值；所有 base 系 profile 的第一层
dsh-web-app浏览器 GUItokenized 启动 URL → 签名 cookie；有意不支持绑全部网卡
dsh-headless一次性 CLI跑完打印答案即退出，不开端口，exit code 表达成败
dsh-acp-appACP stdio自动化专用，挂 ACP bridge
dsh-sdk-appSDK stdio挂 JSON-RPC server；--help 不占 stdin/stdout
dsh-sdk-minimal独立 SDK唯一不用 base 的 bundle——一棵完整独立插件树
注意 sdk-minimal 的存在理由：SDK 运行时要被别的程序以子进程方式批量拉起，最贵的就是无关插件的激活。它证明 base 本身也是「组合选择」而非必然——当你的 harness 只需要会话+循环+一个适配器时，可以整棵树换掉。这对自制 harness 是重要启示：内核也要能被整个替换，前提是缝足够稳定。

13.3SDK：把整个 runtime 交给别的进程

packages/sdk/README.md — 组说明（节选）
textThis group lets another process drive a complete DeepSeek Harness runtime:
the JSON-RPC wire protocol defines the messages, the server plugin serves
external clients over stdio, and the TypeScript and Python clients launch
`dsh` with a named profile and ordered patches.

The TypeScript client is the design twin of the Python SDK
(python/sdk), which speaks the same protocol.

协议本身小得出奇——三个客户端→服务端请求，四个服务端→客户端通知：

packages/sdk/protocol/src/types.ts:107 — 两张方法表（全文节选）
ts/** Server-to-client notifications by JSON-RPC method name. */
export interface HarnessSdkNotificationMap {
  'session.event': SessionEventNotification
  'session.status': SessionStatusNotification
  'subagent.started': SubagentStartedNotification
  'subagent.finished': SubagentFinishedNotification
}

/** Client-to-server request methods with their param and result shapes. */
export interface HarnessSdkRequestMap {
  'initialize': { params: InitializeParams; result: InitializeResult }
  'session/prompt': { params: SessionPromptParams; result: SessionPromptResult }
  'shutdown': { params: undefined; result: Record<string, never> }
}
注意 session/prompt 返回的只是 messageId（入队回执），不是答案；答案经 session.event 通知流回来——wire 上没有「同步等答案」的概念，这和第 2 章「日志是事件流不是快照」一脉相承。而 session.event 的载荷就是第 2 章的完整 SessionEvent 信封，SDK 没有发明第二种事件形状。

传输层一句话：newline 分隔 JSON-RPC 2.0，带 id+method 是请求，只有 id 是响应，只有 method 是通知；坏行忽略，handler 抛错变成 -32603 错误帧（packages/sdk/protocol/src/transport.ts:1）。

客户端怎么启动运行时

packages/sdk/client/src/launch.ts:128 — resolveDshLaunch()（节选）
tsexport function resolveDshLaunch(
  options: HarnessClientOptions = {},
  callerCwd: string = process.cwd(),
): RuntimeProcessOptions {
  const profile = options.profile ?? 'sdk'
  const dshLaunch = options.dshBin === undefined
    ? installedDshNodeLaunch()
    : { nodeArgs: [resolve(callerCwd, options.dshBin)], patches: [], environment: {} }
  const patches = [
    ...dshLaunch.patches,
    ...(options.patches ?? []).map(path => resolve(callerCwd, path)),
  ]
  ...
  return {
    command: process.execPath,
    args: [...dshLaunch.nodeArgs, '--profile', profile, ...patches.flatMap(path => ['--patch', path])],
    ...
  }
}
两个防呆值得抄：① 同版本强校验——resolveDshBinFromManifests 发现 dsh 与 SDK client 版本不一致直接抛（launch.ts:59，错误文本就是「requires the same dsh version」），协议与运行时一起演进，拒绝默默错配；② cwd 只在客户端解析一次——api.ts:38 的注释明说相对 cwd 会被子进程再解析一次，「a relative value would double-resolve (e.g. worker → worker/worker)」，所以进 wire 前先 resolve()。

高层与低层

packages/sdk/client/src/api.ts:22 — DeepSeekHarness（节选）
ts/**
 * Reusable SDK for running DeepSeek Harness agent turns in a runtime

 * child is reaped.
 */
export class DeepSeekHarness implements AsyncDisposable {
  ...
  run(input: string | SdkPromptContentBlock[], options?: RunOptions): Promise<RunResult> {
    return this.session(options?.sessionId).run(input, options)
  }
}
分层很干净：HarnessClient（client.ts）只管子进程与 wire——spawn、握手、订阅分发、EOF → SIGTERM → SIGKILL 阶梯回收，并保留 stderr 尾部 400 行用于诊断意外死亡（STDERR_TAIL_LIMIT）；DeepSeekHarness（api.ts）在其上给「run 一句话→等 idle→拿 finalResponse + 全部事件」的 convenience，错误分类是三个具名类：TransportClosedError / RequestTimeoutError / SdkProtocolError（后者注释点名「a session/prompt response without accepted: true」）。SDK 子进程直接 spawn 而不走 dsh-subprocess 服务——client.ts:8 注释自称「the seam's documented exception」，因为客户端运行在 harness 上下文之外。
闭环 第 12 章的 dsh-sdk 子 agent provider 就是这个客户端的仓库内用户：每个委派子 = 一个全新完整运行时子进程 + initialize 握手 + 提交任务 + 从 session events 读答案，父进程只拿最终文本或安全错误。一条协议同时服务外部 embedding 与内部委派，这就是「缝」的复利。

13.4Web host：纯路由注册表

packages/host/webserver/src/index.ts:1 — 模块注释（全文）
ts/**
 * @deepseek-ai/dsh-host-webserver — node:http route registration with optional
 * gzip, index injection, and one fallback seat. It knows no harness concepts
 * and serves no files; the composing application owns dist serving. Electron
 * uses file:// plus IPC instead, and this package never prints the URL.
 * Route handlers retain direct response ownership.
 */
packages/host/webserver/src/index.ts:165 — register() 与两个「唯一座位」（节选）
ts  /**
   * Register a named route. Duplicate (kind, path) throws — route patterns are
   * a composition-level contract, so a collision is a misconfiguration.
   */
  register(route: WebRoute): () => void {
    const table = route.kind === 'exact' ? this.exact : this.prefixes
    if (table.has(route.path)) {
      throw new Error(`webserver: duplicate ${route.kind} route "${route.path}"`)
    }
    table.set(route.path, route)
    return () => { table.delete(route.path) }
  }

  registerFallback(handler: WebRoute['handler']): () => void {
    if (this.fallback !== undefined) {
      throw new Error('webserver: fallback already registered')
    }
    this.fallback = handler
匹配顺序固定：exact 全表 → 最长前缀 → fallback。三个「唯一性」都 fail-loud：重复路由抛、重复 upgrade 路由抛（「one socket can have only one protocol owner」）、第二个 fallback 抛（「two fallbacks cannot compose」）。同时注释把安全姿态说死：host 只接受 127.0.0.1 与 0.0.0.0 两个值，server 自身不带 TLS、认证或 origin 策略——这些都是组成层（web-app 的 tokenized URL + 签名 cookie）的事。自制 harness 记住这个分工：传输层不管身份，身份是应用 bundle 的插件。

index 注入也值得一瞥：webserver/index-inject 事件收集结构化行（global/script/script-src/script-preload/style/html 六种），同一张表既渲染进服务的 index.html，也随 boot payload 发给静态 worker 部署——「Anything not expressible as a row stays on tapIndex」（injections.ts:1 模块注释）。

13.5能力缝配方：一条能抄的清单

把第 9/10/12 章的缝放在一起看，dsh 每加一条能力缝的套路高度一致：

#步骤dsh 中的证据
1先写模块注释定义契约，再写代码subagent/fs/web/jobs 的 README 与 index.ts 头注释都是契约文本
2Service Definition：ctx 键 + 类型 + 事件名，declaration merging 挂进 cordisdeclare module '@deepseek-ai/cordis'（webserver/src/index.ts:22）
3多实现共存：注册表 + 唯一名 + 重复注册 fail-loudsubagents 命名表、webserver duplicate route 抛、shell 挂两个 executor 抛
4稳定错误码，按 code 路由不解析 messageLlmFailure、FsError、SandboxUnavailableError
5结构类型解耦：跨包依赖靠形状不靠 importEscalationApprover「结构学但不依赖」；provider 方法存在即能力
6事件即审计：状态变化发事件，事件流可断言approval/asked+decided 成对、compaction 三段编舞、fs/write-intent
7companion 插件自证：包自带 ./invariant 校验自己的事件契约runtime-diagnostics/invariants 注册表（docs/subsystems/invariants.md）
8fail-closed 优先：缺依赖报错而不是降级SANDBOX_UNAVAILABLE、web UNAVAILABLE/AMBIGUOUS、fs-sandbox 写拒绝
文档也是架构 docs/subsystems/ 有 52 份子系统文档，每个包 README 都有固定小节（Use this package / Understand the implementation / Known Limitations and Deferred Work / Dev Note）。dsh 把「写清楚契约」当成与「写对代码」同级的工程活动——自制 harness 时把这条抄走，成本最低、收益最大。

13.6自制路线图：八个里程碑

按「不变量优先」排序，每步先立不变量再长功能。括号内是 dsh 对应物：

步里程碑先立的不变量dsh 对应
1append-only 会话日志事件只追加、可回放、可校验第 2 章 session log / seq
2agent 循环 + 工具调用turn 边界清晰、每步可中止第 4 章 ReactLoopAgent
3持久化 + 冷恢复重启后能从日志重建全部状态第 5 章 storage/冷恢复
4LLM 适配层稳定错误码 + 可重试分类第 7 章 LlmFailure/retry
5工具缝 + 多 provider注册表语义、重复注册报错第 6/10 章 tools/shell/fs/web
6沙箱 + 审批fail-closed、审计成对、可升级第 9 章 sandbox/approval
7上下文压缩事件可替换、检查点来源可追溯第 11 章 compaction
8编排 + 对外面孔子 agent 复用同一循环；对外只走缝第 12/13 章 subagents/SDK/Web
顺序的根据：1–3 是「日志即真相」的地基（第 1 章 MVP 论断的展开——没有 durable 日志，后面一切恢复/审计/委派都是空中楼阁）；4–5 让能力可插拔；6 在能力变成破坏力之前补上闸门；7 解决长会话的物理极限；8 才是把同一内核翻新成不同面孔。若你只有一周，做 1+2；若只有一月，做到 5；要进生产，6 不可跳过。

13.7要点

要点 ① profile bundle 让「换应用形态」成为换 patch 而非换内核，sdk-minimal 证明内核本身也可整体替换；② SDK 协议刻意最小（3 请求 + 4 通知），事件直接复用 SessionEvent，不发明第二种 wire 形状；③ Web host 是零 harness 词汇的纯路由表，安全归组成层；④ 能力缝配方八条——契约先行、注册表、稳定错误码、结构类型、事件审计、companion 自证、fail-closed——是本书 13 章真正想让你带走的可复用资产；⑤ 路线图八个里程碑按不变量排序，MVP = 日志 + 循环。
