一次对话的完整生命周期：从 inbox 到 turn/end

第 2 章看了「日志里有什么」，这一章看「日志是怎么被写出来的」：一条消息如何被认领、被 pre-step 决策、被派发给模型、触发工具、又如何收尾。掌握这条时序，你就掌握了 dsh 的主干道。

3.1一分钟版本

  • step = 一次模型请求 + 它触发的全部工具调用；turn = 零或多步（第一个输入被认领前打开，无事可欠时关闭）；round = 外层策略迭代（goal round、Ralph round）。
  • 输入经唯一的 inbox 进入驱动器。消息可立即唤醒；注入型上下文在 inbox 里等下一班车。
  • agent/pre-step waterfall 决定模型看见什么：改写消息、追加上下文、或直接 reject。
  • 每个 step 把「Prompt 段 + 工具 schema + 从日志派生的历史」组装成请求，流式接收，结算为 assistant/message 或 assistant/attempt。
  • 有工具调用 → 执行 → 结果回填 → 可能再来一步；没有 → agent/turn-stopping（serial）→ turn/end。

3.3用代码看：preStep() —— 决策点

step 的第一步永远是「认领 + 决策」。注意默认决策如何把运行时投影出的上下文（renderContextSections）追加到认领的消息后面（packages/core/agent-loop/src/agent.ts:240）：

packages/core/agent-loop/src/agent.ts
typescript  private async preStep(target: InboxTarget, position: { turn: number; step: number }): Promise<PreparedStep> {
    if (this.phase.kind !== 'running') throw new Error(`agent "${this.id}": pre-step outside running phase`)
    const signal = this.phase.abort.signal
    const claimed = this.inbox.claim(target, position.turn)
    const assembly = await this.loopCtx.systemPrompt.assemble(assembleContextFor(this, signal))
    signal.throwIfAborted()
    const sections = renderContextSections(assembly)
    const context = this.runtimeContext.project(joinContextSections(sections), sections)
    const decision = await this.dispatch.waterfall(
      'agent/pre-step', { messages: claimed, ...position, signal },
      (): Promise<PreStepDecision> => Promise.resolve<PreStepDecision>({
        kind: 'enter',
        messages: context === undefined ? claimed : [...claimed, context],
      }),
    )
    signal.throwIfAborted()
    return decision.kind === 'reject' ? decision : { ...decision, assembly }
  }
决策类型（packages/core/agent/src/runtime-types.ts:112）： 
export type PreStepDecision =
  | { kind: 'reject' }
  | {
    kind: 'enter'
    messages: UserMessage[]
    /** 在本 step 被接纳的消息之前，开启一个独立的模型消息系列。 */
    startsRequestSeries?: true
  }
要点：被拒绝或被改写为空的首个认领，仍会关闭一个「零 step」的持久 turn——日志记录这次尝试，但不花模型调用。enter 还可以用 startsRequestSeries 开启新的请求序列（循环随之记录新的 request/header，reason 为 series）。改写下游 enter 决策的监听器必须展开它：{ ...decision, messages }，保住决策的其他字段。

3.4用代码看：turn() —— 骨架循环

packages/core/agent-loop/src/agent.ts:269 — turn()
typescript  private async turn(): Promise<boolean> {
    // ... phase 校验省略
    const phase = this.phase
    const { signal } = phase.abort
    signal.throwIfAborted()
    const turn = phase.turn + 1
    this.session.append('turn/start', { turn })
    phase.turn = turn
    let turnEnds: TurnEndReason | null = null
    let target: InboxTarget = 'next-turn'
    try {
      while (true) {
        signal.throwIfAborted()
        const step = phase.step + 1
        const decision = await this.preStep(target, { turn, step })
        if (decision.kind === 'reject') {
          turnEnds = { kind: 'blocked' }
          return false
        }
        if (turnEnds && decision.messages.length === 0) break
        // 被移除的唤醒消息或改写为空的 enter 仍拥有回合边界，但不花模型调用。
        if (phase.step === 0 && decision.messages.length === 0) {
          turnEnds = { kind: 'completed' }
          return false
        }
        signal.throwIfAborted()
        this.session.append('step/start', { turn, step })
        phase.step = step
        try {
          // max-tokens 是粘滞的：任何一步触顶后，后续正常完成的
          // 步骤不得把回合结局降级。
          const stepEnd = await this.step(decision)
          if (turnEnds === null || turnEnds.kind !== 'max-tokens') turnEnds = stepEnd
        } finally {
          this.session.append('step/end', { turn, step })
        }
        signal.throwIfAborted()
        if (turnEnds && this.inbox.nextStep.length === 0) {
          await this.dispatch.serial('agent/turn-stopping', { turn, signal })
          signal.throwIfAborted()
        }
        if (turnEnds && this.inbox.nextStep.length === 0) break
        target = 'next-step'
      }
    } catch (error: unknown) {
      if (signal.aborted) {
        turnEnds = { kind: 'aborted', reason: signal.reason as AgentCancelCause }
        throw error
      }
      // 所有失败都是结构化的：LlmError 保留事实，其余扁平化为
      // errorChain 文本 + UNKNOWN 码。
      turnEnds = {
        kind: 'error',
        error: error instanceof LlmError
          ? error.failure
          : { message: errorChain(error), code: 'UNKNOWN' },
      }
      this.throwError(error)
    } finally {
      this.session.append('turn/end', { turn, reason: turnEnds! })
    }
    return this.inbox.hasPending()   // 还有排队输入 → 换新 AbortController 再来一回合
  }
细节：① turnEnds 的 max-tokens 粘滞语义在两处体现：step 返回后不覆盖已有的 max-tokens 结果；② agent/turn-stopping 只在「回合要结束且无 next-step」时以 serial 模式派发——它是没有 next() 的收口点（例如 Claude Code 的 Stop hook 桥在这里把 deny 转成 steer()，强制再走一步；plan-mode 不走这里，它拦在 agent/pre-step）；③ 出错时 LlmError 保留其 failure，其他错误扁平化为 errorChain 文本、code 为 UNKNOWN；④ finally 里无条件写 turn/end，所以崩溃前的最后一次尝试也会留下回合结束记录（如果进程没死）。

3.5用代码看：step() —— 一次模型请求的一生

packages/core/agent-loop/src/agent.ts:352 — step()（节选）
typescript  private async step(decision: Extract<PreparedStep, { kind: 'enter' }>): Promise<StepEndReason | null> {
    const { turn, step, abort: { signal } } = this.phase
    const { assembly } = decision
    const renderedPrompt = renderPrompt(assembly)
    let firstAttempt = true
    while (true) {                       // ← 每次重试/继续都重新 prepareRequest + buildRequest
      const { config, preparedCall } = await this.prepareRequest(turn, step, signal)
      const startsRequestSeries = firstAttempt && decision.startsRequestSeries === true
      const commits = this.systemPrompt.project(renderedPrompt, {
        inHistory: preparedCall?.systemPromptUpdate === 'in-history',
        startsSeries: startsRequestSeries
          || this.requestSurfaceGeneration !== this.session.surface.replaceGeneration
          || this.toolsChanged(assembly.tools),
      })
      for (const { message, intent } of commits) {
        // 系统提示词是表面事件（v3）：新提示词 append 为节点 0 或替换旧节点。
        this.session.append('system/message', { turn, step, message }, intent)
      }
      if (firstAttempt) {
        for (const message of decision.messages) {
          this.session.append('user/message', message, { surfaceOp: 'append' })
        }
      }
      firstAttempt = false
      const request = this.buildRequest(config, preparedCall, assembly.tools, startsRequestSeries, signal)
      const live = new AssistantStreamAttempt(...)
      let started = false
      try {
        const stream = preparedCall?.stream(request) ?? this.loopCtx.llm.stream(request)
        signal.throwIfAborted()
        live.start()
        started = true
        for await (const chunk of stream) {
          signal.throwIfAborted()
          live.push(chunk)
        }
        signal.throwIfAborted()
      } catch (error) {
        if (!started) throw error
        if (signal.aborted) {
          const content = live.interruptedBlocks()
          if (content.length > 0) {
            // 中断流：已送达的 text/reasoning 前缀结算为 interrupted 消息
            live.settle('assistant/message', () => this.session.append('assistant/message', {
              turn, step,
              message: createAssistantMessage({ content, source: {...} }),
              interrupted: true,
              stream: live.stream,
            }, { surfaceOp: 'append' }).seq)
          } else {
            live.settle('assistant/attempt', () => this.session.append('assistant/attempt', { turn, step, stream: live.stream }).seq)
          }
        } else {
          live.settle('assistant/attempt', ...)
        }
        throw error
      }
      try {
        const finish = live.finish
        if (finish.kind === 'error' || finish.kind === 'aborted') {
          // 失败的尝试 → assistant/attempt（不伪造模型历史）
          live.settle('assistant/attempt', ...)
          const action = await this.dispatch.waterfall(
            'agent/request-error', { turn, step, provider: request.provider, failure: finish.failure, retryPolicy: preparedCall?.retryPolicy, signal },
            () => Promise.resolve<RequestErrorAction>(undefined),
          )
          if (action?.kind !== 'retry') {
            throw new LlmError(finish.failure.message, finish.failure.code, finish.failure)
          }
          continue                          // ← 重试由监听器决定，循环只认 {kind:'retry'}
        }
        // 成功：结算为 assistant/message 并上表面
        live.settle('assistant/message', () => this.session.append('assistant/message', {
          turn, step, message,
          ...live.usage === undefined ? {} : { usage: live.usage },
          stream: live.stream,
        }, { surfaceOp: 'append' }).seq)
        if (finish.kind === 'max-tokens') return { kind: 'max-tokens' }
        const toolCalls = message.content.filter(b => b.type === 'tool-call')
        if (toolCalls.length === 0) return { kind: 'completed' }
        const { concluded } = await executeToolCalls(this.loopCtx, turn, step, toolCalls, signal,
          context => this.inbox.splice('next-step', this.inbox.nextStep.length, 0, [context]),
        )
        return concluded ? { kind: 'completed' } : null
      } catch (error) {
        if (!live.ended) live.abandon()
        throw error
      }
    }
  }
结算规则：① 流成功 → 完整压缩流作为一条 assistant/message 落日志（含 usage 与完整 stream 记录）；② 错误/重试/取消且无可见内容 → assistant/attempt（只留流记录，不产生模型历史）；③ 中断但已输出前缀 → 前缀结算为 interrupted: true 的消息。注意 v3 的两个新细节：系统提示词在每次请求前由 SystemPromptProjection.project() 决定是否补写 system/message 表面事件（新系列或工具集变化时才追加/替换，内容没变不重复落日志）；user/message 只在首个尝试前落一次，重试不重复认领的消息。第 7 章会看到与 retry 策略插件的配合。

3.6请求头折叠：request/header 的四种 reason

每次派发前，循环用 buildRequest 组装冻结请求，并决定是否追加一条 request/header（packages/core/agent-loop/src/agent.ts:553）：

packages/core/agent-loop/src/agent.ts — buildRequest()（节选）
typescript    const surfaceGeneration = session.surface.replaceGeneration
    const header = canonicalHeader({
      config,
      ...preparedCall === undefined ? {} : { adapterDefaults: preparedCall.adapterDefaults },
      ...tools.length > 0 ? { tools } : {},
    })
    const baseline = this.session.requestHeader()
    const startsSeries = startsRequestSeries
      || this.requestSurfaceGeneration !== surfaceGeneration
    if (!this.requestHeaderLogged) {
      this.session.append('request/header', { header, reason: baseline === undefined ? 'initial' : 'resume' })
      this.requestHeaderLogged = true
    } else if (baseline === undefined || !headerEquals(baseline, header)) {
      this.session.append('request/header', {
        header, reason: 'change',
        ...startsSeries ? { startsSeries: true } : {},
      })
    } else if (startsSeries) {
      // 头未变但系列重启 → reason 'series'
      this.session.append('request/header', { header, reason: 'series' })
    }
reason何时写入
initial会话首次派发（此前没有持久 header）
resume进程重启后首次派发（有持久 header，本实例未记录过）
changecanonical header 与基线不相等（模型、adapter 默认值或工具集变了）
seriesheader 未变，但 pre-step 以 startsRequestSeries 或表面重写开启了新系列
用途：请求头 + request/context 是 KV-cache 命中分析与「为什么这个 step 换了模型」审计的数据来源。v3 里 header 不再包含 system——系统提示词降为派生历史的一部分（表面节点 0 的 system/message，见 3.5 节），prompt 段变化改由 system/message 追加/替换呈现，不再触发 change；header 只剩 config、adapterDefaults 与 tools。

3.7Inbox：认领与拼接

inbox 是持久的：它的每次拼接都写成 agent/inbox/spliced 会话事件，重启后重放即可恢复排队消息（packages/core/agent/src/types.ts:87）：

packages/core/agent/src/types.ts — inbox 拼接事件
typescript  'agent/inbox/spliced': {
    target: InboxTarget          // 'next-turn' | 'next-step'
    start: number
    removedCount?: number
    inserted: UserMessage[]
    outcome?: 'canceled'
  }
  • claim(target, turn)：取走全部 next-step 消息；target 为 next-turn 时额外取走一个 next-turn 消息，随后发布被认领通知。
  • steer（next-step + 立即唤醒）vs inject（next-step、不唤醒）：注入物安静排队，等下一个 step 的 claim。
  • followup（next-turn + 唤醒）：在回合边界之后开启新回合。
  • 每个回合续期用全新的 AbortController，取消不会跨回合泄漏。

3.8要点

要点 ① turn/step 两层结构，step 才花钱（模型调用），turn 可以零 step 关闭；② pre-step 是「模型看见什么」的守门人；③ 流式尝试只有两种持久结局——committed 的 assistant/message 或 settled 的 assistant/attempt，不存在第三种；④ request/header 四种 reason 记录了请求配置的完整演化史。下一步进入 第 4 章：Agent 循环的并发模型。
