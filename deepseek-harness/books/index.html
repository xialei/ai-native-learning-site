0这本书讲什么

DeepSeek Harness（命令 dsh）是 DeepSeek 开源的 AI Coding Agent 运行时：一个终端里跑的编码代理，有会话持久化、工具系统、权限沙箱、子代理编排，也能以 SDK / Web UI / ACP 三种形态被集成。它和「提示词 + 循环」的玩具 demo 之间隔着一整层工程——而这层工程正是这本书的主题。

三个贯穿全书的设计决定：

  • 一切皆插件。内核只有一个插件框架 Cordis：LLM 适配器、会话存储、工具、Agent 循环、权限、压缩——全都是挂在同一个容器上的插件，没有特权核心。
  • 会话日志是唯一事实。模型看见什么，日志里就有什么（"Model-visible means logged"）。消息历史、工具结果、压缩摘要，全部是对同一条 append-only 事件流的投影。
  • 能力缝（capability seam）是扩展点。每个可替换的能力都由「服务定义 + 服务提供者 + 消费者」三方构成，换掉中间那方就能换实现——沙箱、Web 搜索、子代理后端皆如此。

读完这本书，你应该能：读懂 dsh 的任意一条执行路径（从一次 turn/start 到一个工具结果落盘）；解释每个设计取舍背后的原因；以及按第 13 章的路线图，动手搭一个自己的 Harness。

全书词表

各章反复出现的术语收拢在这里，按学习路径顺序排列。「详见」指向讲得最透的章节；读正文遇到陌生词，先回来查这一张表。

术语含义详见
Cordis（插件框架）vendor 进仓库的插件框架，只提供三件事：ctx 服务仓库、类型化事件总线、可逆副作用（ctx.effect()）；LLM 适配器、会话存储、工具、循环全是挂在上面的插件01
profile / bundle装配叠层：bundle 按固定顺序叠加配置行，profile patch → home patch → --patch 逐层覆盖，同 id 后写者整行替换01
能力缝（capability seam）每个可替换能力由三个角色构成：Service Definition 声明接口、Service Provider 提供实现（可替换）、Consumer 消费——换掉中间那方就换实现01
SessionEvent（会话事件）会话日志里的事件：append-only、带单调递增 seq 与类型化 data；模型历史、UI 转录、崩溃恢复全由它重建02
投影 / 表面（surface）从日志重建视图的机制：只有 system/user/assistant 消息与 tool/result 四类事件能出现在有序表面上，deriveMessages() 把表面折叠成 LLM 消息历史02
Model-visible means logged（模型可见即已记录）会话铁律：模型看见什么，日志里就有什么；重建遇到不认识的事件类型，宁可拒绝也不静默丢内容02
turn / stepstep = 一次模型请求 + 它触发的全部工具调用；turn = 零或多步。只有 step 花钱（模型调用），turn 可以零 step 关闭03
inbox（收件箱）每个 agent 独享的持久输入队列：消息在这里等认领，每次拼接本身也写成 agent/inbox/spliced 会话事件，重启重放即可恢复03
agent/pre-step（步前决策点）每个 step 开头的决策点 waterfall：改写消息、追加上下文，或直接 reject——「模型看见什么」的守门人03
Phase（三态状态机）ReactLoopAgent 的「操作系统层」：idle（无活动）→ running（kick 驱动中）→ maintenance（维护任务独占），让注入与取消在任何时刻语义明确04
followup / steer / inject三种消息注入 API：followup 进下一轮并唤醒、steer 进本步并唤醒、inject 进本步但不唤醒；注入型上下文在 inbox 里等下一班车04
SessionHandle / 崩溃恢复存储缝返回的句柄契约：append 尽力而为、flush 才是持久性屏障；进程被 kill 后由 interruptedTurnClosers 给未完成的工具调用合成确定错误、补全收尾事件05
ToolDefinition（工具定义）工具的定义样板：schema + 强制的 canonical output 声明 + execute(args, exec)，走五段管线（pre-execute 审批 → 单调守卫 → execute 包装 → 工具体 → post-execute 定稿）06
PTC（Programmatic Tool Calling，程序化工具调用）dsh 最有特色的模式之一：模型只调唯一的 run_code，在代码里编排所有工具，把 N 次模型往返压成 1 次往返 + 1 段程序，权限模型不变06
StreamChunk（流分片）流式协议的封闭词汇表：7 种 chunk，适配器把 SSE（Server-Sent Events）翻译成它们，循环聚合成块、工具调用与 usage07
LlmFailure（LLM 统一失败类型）所有供应商失败统一成稳定机器路由码（AUTH/RATE_LIMIT/SERVER/…），永不靠解析 message 文本路由；重试由独立插件按供应商声明的策略执行07
persona（人格段）部署方人格前缀/后缀：用「同名遮蔽」实现身份替换——换掉人格而版面结构不动，是可被 composition 替换的槽位08
Scope（作用域）不透明对象 + 父链：注册视图沿链向下继承（子 scope 看得见祖先的层），事件准入门沿链向上，决定「这条注册只影响哪个 agent」08
fail-closed / SandboxMode安全两条轴（文件沙箱、审批）都默认拒绝而非放行；沙箱三模式 read-only / workspace-write / danger-full-access 只管文件效果，网络与进程可见性明确排除在词汇表外09
审批审计对（approval audit pair）每次 ask 在日志里留下 approval/asked + approval/decided 成对事件，且必须落在 open turn 内——turn 是日志的重放边界09
jobs / MCP 缝ctx.jobs 是后台作业注册表：作业归属启动它的 agent session，完成以会话内通知送达而非轮询；MCP（Model Context Protocol）每条配置一个外部 server 连接，工具与资源经注册表进入10
CompactionEngine（压缩引擎）压缩缝：压缩不是删除，而是选一段表面范围、用摘要节点替换它的表面位置，原始事件原封不动留在日志里11
影子定价（shadow pricing）compaction/prune 事件紧跟计量（metering）注释的协议：纯消费者 O(1) 对账，启发式与路由定价各管折叠与决策11
continuable 子代理（可续聊子代理）ctx.subagents 委派缝里的 durable 子 agent 形态：续聊走消息与冷恢复，全部运行时归 continuation manager，provider 只贡献一个创建参数12
Workflow / Ralph编排栈的上层原语：前者是模型写的纯 JS 编排脚本，在 PTC Node 进程里 fan out 子代理；后者是固定前台循环，每轮全新子代理、跨轮只传有界结构化报告12
SDK / JSON-RPCdsh 的跨进程接口形态：newline 分隔的 JSON-RPC over stdio，TypeScript 与 Python 客户端结构对等，驱动同一套协议13
