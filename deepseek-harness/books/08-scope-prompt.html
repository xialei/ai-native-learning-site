System Prompt 组装与 Scope：谁在哪个作用域里说了什么

系统提示词不是一段写死的字符串，而是每次模型请求前由注册表动态组装的产物；而决定「这条注册只影响这一个 agent」的机制，是 dsh 自己的 Scope 原语。这一章把两个半场（prompt 组装 / scope 机制）讲透。

8.1一分钟版本

  • ctx.systemPrompt（packages/core/system-prompt）是注册表服务：插件往里塞四类输入——sections（系统提示词段落）、contexts（动态运行时上下文）、tool providers（工具 schema）、variables（{{变量}}）。
  • 每次 pre-step 调 assemble()：合并全局层与该 agent 的 scope 层 → 排序 → 跑 system-prompt/assemble waterfall → 得到 PromptAssembly。
  • 段落顺序由中央常量表 SECTION_ORDERS 分配——所有插件共用同一份「哪里放什么」的分配表，避免两处重复占用同一个顺序。
  • 动态上下文不进 system prompt，而是作为 plugin 来源的 user/message 快照追加进历史——所以 KV 缓存前缀保持稳定，只有变化时才追加新快照。
  • Scope 是不透明对象 + 父链：注册视图沿链向下继承（子 scope 看得见祖先的层），事件准入门沿链向上（祖先的监听器收得到子孙的事件，反之不行）。

8.2四类输入与 PromptAssembly

packages/core/system-prompt/src/index.ts:53 — PromptSection / PromptContext / PromptAssembly
typescriptexport interface PromptSection {
  /** 唯一名字——重复注册直接抛错 */
  readonly name: string
  /** 段落按 order 升序拼接；同 order 按名字码元序 */
  readonly order: number
  /** 静态文本或每次组装时求值的 provider；文本可含 {{变量}} */
  readonly text: string | ((context: AssembleContext) => string)
  /** 视为完整系统提示词：组装照跑（工具/变量仍解析），随后恢复本段为唯一段落 */
  readonly complete?: boolean
}

export interface PromptContext {
  /** 唯一名字——重复注册直接抛错 */
  readonly name: string
  /** 动态上下文也按 order 升序拼接 */
  readonly order: number
  readonly text: string | ((context: AssembleContext) => string)
}

export interface PromptAssembly {
  sections: AssembledSection[]      // 渲染成 system prompt
  contexts: AssembledContext[]      // 渲染成 user/message 快照
  tools: ToolSchema[]               // 已按 toolOrder 排成规范顺序
  variables: Record<string, string | undefined>
}
system prompt 与 runtime context 是两条管道：sections 渲染进每次请求的 system 字段；contexts 渲染成一条特殊的 user 消息——「Current runtime context. This snapshot supersedes earlier runtime-context snapshots.」——追加到会话历史里。为什么分开？system prompt 改一个字就击穿前缀缓存；而快照追加只会延长历史，旧消息永不变。这是第 11 章 warm-prefix 缓存的先决条件。

typescriptexport interface Config {
  /** Persona prose rendered as the `deployment:persona-prefix` section. */
  prefix: string
  /** Persona suffix template rendered after first-party guidance. */
  suffix?: string
  /** Make the prefix the complete system prompt, suppressing the suffix and every other section. */
  complete?: boolean
  /** Suppress dynamic runtime-context snapshots for this persona's agent scope. */
  includeRuntimeContext?: boolean
}

export function apply(ctx: Context, config: Config): void {
  ctx.effect(() => ctx.systemPrompt.section({
    name: PERSONA_PREFIX_SECTION,
    order: ctx.systemPrompt.getSectionOrder('DEPLOYMENT_PERSONA_PREFIX'),
    text: config.prefix,
    ...config.complete ? { complete: true } : {},
  }), 'persona.section()')
  ctx.effect(() => ctx.systemPrompt.section({
    name: PERSONA_SUFFIX_SECTION,
    order: ctx.systemPrompt.getSectionOrder('DEPLOYMENT_PERSONA_SUFFIX'),
    text: config.suffix ?? '',
  }), 'persona.suffix()')
  if (!(config.includeRuntimeContext ?? true)) ctx.systemPrompt.suppressRuntimeContext()
}
两种「换人格」：prefix 替换 persona 前缀段，其余段落照常；complete: true 把整条系统提示词换成这段话（组装仍跑 waterfall 以解析工具/变量，然后恢复该段为唯一段落，同时压制后缀段；两个 complete 同时生效直接抛错）。行包还可以用 includeRuntimeContext: false 关掉动态运行时上下文快照。子 agent 的 applyChildComposition 用同一招给每个孩子装 deployment:persona-prefix——替换而非重复，靠的就是同名字段。

8.5渲染与严格插值

packages/core/system-prompt/src/index.ts:280 / :304 — renderPrompt / joinContextSections
typescriptexport function renderPrompt(assembly: PromptAssembly): string {
  return assembly.sections
    .map(section => section.interpolate === false ? section.text : interpolate(section, assembly.variables, 'section'))
    .filter(text => text.length > 0)
    .join('\n\n')
}

// renderContextSnapshot(assembly) 就是 joinContextSections(renderContextSections(assembly))
export function joinContextSections(sections: readonly ContextSnapshotSection[]): string {
  const body = sections.map(section => section.text).join('\n\n')
  if (body.length === 0) return ''
  return `Current runtime context. This snapshot supersedes earlier runtime-context snapshots.\n\n${body}`
}
插值是严格的：变量名必须匹配 /^[a-z][a-z0-9_]*$/；未注册的名字抛错（并打印全部已注册变量）；注册了但本次组装无值的也抛错——{{name}} 拼错不会静默留白，组装时直接抛错。替换后的值不再二次扫描，孤立的 {{ 若后文无 }} 视为字面散文。工具顺序同理严格：toolOrder 必须恰好含一个 <unlisted-tools> 哨兵（未列出的工具按字典序插在那儿），列出未注册的名字在组装时抛错。PromptSection 还有一个 interpolate?: boolean（默认 true）：置 false 的段落跳过插值、按字面文本渲染——目前唯一的用户是 dsh-tools 的 tools:sdk 段（tools/src/index.ts:880），那里渲染的是生成代码（SDK 使用示例），正文的 {} 不能被变量语法误伤。

8.6快照投影：只在变化时追加

快照消息的提交由循环侧的 RuntimeContextProjection 跟踪（packages/core/agent-loop/src/runtime-context.ts）：

packages/core/agent-loop/src/runtime-context.ts
typescriptconst SOURCE = '@deepseek-ai/dsh-system-prompt'
const CLEARED = 'Current runtime context: none. Earlier runtime-context snapshots no longer apply.'

function isOwned(message: UserMessage): boolean {
  return message.source.kind === 'plugin' && message.source.plugin === SOURCE
}

export class RuntimeContextProjection {
  /** undefined = 从未有快照；null = 当前无保留快照 */
  private retained: { seq: SessionSeq; text: string | undefined } | null | undefined

  project(current: string, sections: readonly ContextSnapshotSection[]): UserMessage | undefined {
    if (this.retained === undefined && current.length === 0) return
    const snapshot = current.length === 0 ? CLEARED : current
    if (this.retained?.text === snapshot) return   // 内容没变 → 不追加
    return createUserMessage({
      content: [{ type: 'text', text: snapshot }],
      // 清空标记没有可归属的贡献了
      source: sections.length === 0
        ? { kind: 'plugin', plugin: SOURCE }
        : { kind: 'plugin', plugin: SOURCE, form: 'snapshot', sections },
    })
  }
}
三个细节：① 归属权靠 source.plugin 标记——投影只认自己来源的消息，重启时倒序扫日志即可恢复 retained；② surface 替换事件（第 2 章 SurfaceOp.replace）引用了保留快照的 seq 时，retained 置 null，下轮会补一条新快照；③ 变空时不是静默消失，而是写一句 CLEARED——模型永远能「看见」上下文被撤销这件事——仍然满足第 2 章的「model-visible means logged」。

父子如何接上：第 4 章讲过 agent 构造时 createScope(loopCtx, this)；子 agent 由 applyChildComposition 先 composeFrom(childCtx, parent.ctx) 继承父 preset 的注册，再挂自己的 persona / delegation 上下文 / 工具限制。绑定是一次性的：已经有父链的 key 再 bind 直接抛错，代码注释写明「没有开放的改链路径」（scope/index.ts:64）。但并非完全不可改——bindScopeParent() 返回一个 ScopeParentBinding 句柄，只有拿到它的那个 binder 能调用 rebind(parent) 把 key 挂到新父下；rebind 走同一套 cycle 检查，且契约上只在「旧父下没有任何产物被保留」时合法——也就是 blank-session 重建注册世界的场景。所以准确的表述是：祖先链不能被别人改，唯一的改动入口握在最初的 binder 手里，且它要自己保证会话里没留下旧父的痕迹（这条关系看不到会话记录了什么，只能靠持有者守约）。

8.10要点

要点 ① 系统提示词是组装产物不是常量——四类输入（sections/contexts/tools/variables）各有管道；② 版面由中央 SECTION_ORDERS 表权威分配，插件只报名字不抢数字；③ 会变的政策走 user 快照，保住 KV 缓存前缀；④ persona 拆成 prefix/suffix 两段、靠同名遮蔽替换，complete 靠恢复机制独占；⑤ Scope 用一条 parent 链同时定义注册继承（向下）与事件准入（向上）。下一步看这些机制最敏感的应用：第 9 章：沙箱与审批。
