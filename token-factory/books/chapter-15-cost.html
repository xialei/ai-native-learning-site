Token 成本核算与商业化

【重点章】全书的工程成果在这一章折算成钱。成本侧给一张完整的清单（GPU 折旧到电费到人力），产出侧给每百万 token 的核算方法，中间夹着三个常被漏算的成本项（空闲、碎片、模型驻留）。最后讲商业化：按 token、按时长、按服务等级三种计费的适用场景，以及 API 服务与企业私有化两条路的经济结构差异。

成本清单：钱的去处

把一座工厂的月度成本全部列出来。凡是只算 GPU 的成本模型，误差通常在 40% 以上：

自建与租赁的选择是这套清单上最大的单变量。粗判据：负载稳定（年利用率 50% 以上）、有长周期确定性（三年以上）、有运维能力——自建摊薄后更便宜；负载波动大或技术迭代风险高（模型架构换代可能让这批卡贬值）——租赁或混合。混合形态很常见：基线负载自建、峰值与实验负载租用。

每百万 token 的成本核算

核心公式一行，全部难度在分子分母的口径：

每百万 token 成本 = 月度完全成本 ÷ 月度合格 token 产出（按输入输出分列）

完全成本 = 算力折旧 + 电力 + 机房网络 + 存储 + 运维人力 + 软件许可
合格产出 = 有效产能口径（第 2 章）：SLA 达标的合格请求的 token

把第 1 章的实验升级成完整版核算（示意结构，数字全部换成你自己的）：

三个常被漏算的成本项

核算口径不完整，商务决策就会错。三个高频漏项：

空闲成本。利用率 65% 意味着 35% 的 GPU 小时在空转，但折旧一分不少。空闲成本要么通过混部（第 10 章）变废为宝，要么在核算里显式计入——按利用率折算的"影子单价"让每个业务方看见低峰期的钱。夜间利用率长期低于两成的工厂，空闲成本通常能覆盖一整条优化线的预算。

碎片化成本：调度碎片让"看起来有空位"的请求进不来（一台机剩 2 卡装不下 TP=4 的实例），这些被浪费的产能以"可分配但不可用"的形态存在。碎片率可从调度日志统计（分配失败但总空闲充足的次数），缓解手段是预留整块空间 + 实例规格的档位设计（第 10 章的实例池思想）。

模型驻留成本：冷门模型的实例常年占卡，每次偶发请求都让它保持温热。驻留成本 = 实例 GPU 小时 × 长期利用率（往往不到 5%）。治理手段：冷门模型按需拉起（接受冷启动延迟）、多个小模型合池（牺牲些微隔离换利用率）、或与业务方共同承担。把驻留成本算清楚，"我们想加一个模型"的请求会自动经历一次必要性审查。

计费模式

对外（或对内）收费有三种主流模式，适配不同的业务结构：

按 token 计费：最贴近成本结构（你的成本就是按 token 产生的），输入输出分价、缓存命中折扣（prefix 命中的输入按折扣计——省下的 prefill 成本返还给调用方，激励业务方优化提示词结构）。折扣幅度的业界参照是 10 倍：头部 API 对缓存命中的输入定价约为未命中的十分之一（如 Claude Sonnet 每百万 token 0.3 美元对 3 美元），这个量级说明缓存命中省下的 prefill 成本之大——也解释了为什么第 9 章把缓存感知路由当作网关层最值钱的优化。来源：Anthropic/OpenAI 公开定价页（2025）；llm-d Blog《KV-Cache Wins You Can See》, 2025-09-24（10× 论证）适合 API 型业务与内部市场化结算。

按时长/并发计费：包实例、包并发位，收益可预测。适合 SLA 要求硬、预算制的企业客户。注意要配超量条款，否则大客户的突发全由工厂吸收。

按服务等级计费：同样的 token，不同的 SLA 与优先级不同价。这是把第 11 章的等级体系货币化，也是混部工厂利润率的关键来源——同产能下，高等级token 的边际收益可以数倍于低等级。

三种模式常组合使用（等级定价 + token 量折扣）。定价的底线来自本章的核算（单位成本 × 目标毛利），上限来自替代品（云 API 同模型价格）——两条线之间是你的定价空间，工厂的运营水平决定这个空间有多宽。

本章小结

成本清单五类（算力、电力、机房、存储、人力），只算算力会低估四成。单位成本 = 完全成本 ÷ 合格产出，输入输出分列。三个隐形成本项——空闲、碎片、模型驻留——是治理的靶子。计费三模式（token、时长、等级）按客户结构组合，定价空间夹在成本线与替代品价格之间。
