策略动物园：从 ACT 到 Diffusion

数据就位，现在轮到「学习」本身。lerobot 的 policies/ 目录下有二十余种策略，但它们都遵守同一个契约：输入观测 dict，输出动作。本章先读这个契约（PreTrainedPolicy），再深读两个经典——ACT（transformer 序列翻译）与 Diffusion Policy（迭代去噪），把「action chunk 从哪来、训练 loss 怎么算、推理时怎么消费」三件事彻底看清。

5.1PreTrainedPolicy：所有策略的统一契约

不管网络结构多花哨，每个策略都要回答同样三个问题：看到观测选什么动作（select_action）、预测一段动作（predict_action_chunk）、给一批数据算多大 loss（forward）。基类（src/lerobot/policies/pretrained.py:61）把它们钉死为抽象方法：

读法：forward 服务训练循环，select_action 服务 30 Hz 的执行循环（第 3 章 record_loop 与第 11 章机器人跑 policy 都调它）。两者之间的桥就是 action chunk：predict_action_chunk 一次算出未来几十步动作，select_action 负责把这段动作「一点点放出去」——用队列缓存，或者做时序集成（5.3）。基类还提供 from_pretrained（safetensors 加载 + 强制 eval 模式，pretrained.py:147）与 drop_queued_actions（pretrained.py:230，中途换指令时强制丢弃缓存队列），这些细节在部署章（11）会再次出现。

5.2ACT：把模仿学习变成序列翻译

ACT（Action Chunking Transformer，modeling_act.py:42）的直觉：与其每帧猜一个动作，不如把「一段演示」当成一次序列到序列的翻译——观测是原文，未来 100 步动作是译文。网络由三块组成（modeling_act.py:260）：

读法：推理时（不复用 VAE 编码器）latent 取零向量，整个网络就是「一个普通 transformer 把多相机图像 token + 关节状态 token 翻译成 100 步动作」。训练时才启用 VAE 支路：把真实动作序列也编码进 latent（modeling_act.py:409-453，重参数化采样），迫使模型从「当前观测」就能猜出一个合理的 latent——这正是 CVAE 的标准玩法，用来表达「同一观测可以有几种合理做法」的多模态性。loss 由两部分组成（modeling_act.py:145-164）：L1 重建损失 + KL 散度（kl_weight=10，configuration_act.py:123）。
源码注 configuration_act.py:108-111：默认 n_decoder_layers=1——注释明说原论文实现是 7 层，但因一个 bug 只有第一层生效，lerobot 为复现原效果保持 1 层。读论文数值（参数量、层数）时务必核对源码，这类「论文与代码不一致」在机器人学习领域并不罕见。

5.3两种消费模式：action queue 与时序集成

ACT 一次吐 100 步动作，但环境每步只接受一个。怎么放？lerobot 给了两种答案。默认是队列模式——预测一次，排队慢慢执行：

src/lerobot/policies/act/modeling_act.py:102 — select_action 的队列逻辑（节选）
python@torch.no_grad()
def select_action(self, batch):
    self.eval()
    # Action queue logic for n_action_steps > 1. When the action_queue is depleted,
    # populate it by querying the policy.
    if len(self._action_queue) == 0:
        actions = self.predict_action_chunk(batch)[:, : self.config.n_action_steps]
        # (batch, steps, dim) → (steps, batch, dim)，逐步出队
        self._action_queue.extend(actions.transpose(0, 1))
    return self._action_queue.popleft()

另一种是时序集成——每步都重新推理，把「历史所有 chunk 在当前时刻的预测」做指数加权平均。权重公式（modeling_act.py:170-179）：wᵢ = exp(-m·i)，i 是「这条预测距它被做出的时刻过了多久」：

图 5.1：三种 chunk 放行方式。① 省算力但执行期间开环；② 每步闭环推理、平滑但贵；③ diffusion 的折中——预测长窗、执行半窗。插值实现见第 6 章的 flow matching（6.3）与 7.1 的 π0。另有一条书中未展开的支线：lerobot 的 evo1 策略通过 rtc_processor 支持 RTC（real-time chunking）——在去噪循环里按已执行动作做引导重规划，可对照 flow_matching.py 的 denoise_step 自行阅读。
两种模式的选择：队列模式（①）下 n_action_steps=100，意味着连续 100 步没有任何新观测参与决策——对结构化场景够用、算力友好。时序集成（②）强制 n_action_steps=1（configuration_act.py:138 有断言），等于每步都看世界再决策，代价是 GPU 一直在线。原论文默认 temporal_ensemble_coeff=0.01：偏信旧预测，实验表明过度偏信新预测会抵消 action chunking 本身的平滑收益（modeling_act.py:179 注释引 PR #319）。

5.4Diffusion Policy：把动作生成变成迭代去噪

ACT 对「同一观测多种做法」的处理靠 CVAE latent，Diffusion Policy 则干脆把「生成动作序列」建模成从纯噪声逐步去噪出一段轨迹。先用一句话建立直觉：训练时，拿一条真实轨迹，随机加一点噪声，让网络看着「加噪后的轨迹 + 噪声等级」预测当初加进去的那份噪声——练一万次后网络就学会了「怎样把噪声变成动作」；推理时反着来，从纯噪声出发，反复问网络「这里的噪声长什么样」并减掉，几十步后就「洗」出一段干净轨迹（这正是本节标题的「迭代去噪」）。模型本体是条件 1D U-Net（时间维做卷积，动作维度当通道），条件（状态 + 图像特征）拼成 global_cond 用 FiLM（特征级线性调制：用条件向量对网络每层的输出做逐通道的缩放与平移，是最常用的条件注入手法）注入。推理循环（modeling_diffusion.py:234）：

src/lerobot/policies/diffusion/modeling_diffusion.py:234 — conditional_sample（节选）
pythondef conditional_sample(self, batch_size, global_cond=None, noise=None) -> Tensor:
    # Sample prior: 从纯噪声出发，形状 (B, horizon, action_dim)
    sample = noise if noise is not None else torch.randn(
        size=(batch_size, self.config.horizon, self.config.action_feature.shape[0]), ...)

    self.noise_scheduler.set_timesteps(self.num_inference_steps)
    for t in self.noise_scheduler.timesteps:
        model_output = self.unet(sample, t, global_cond=global_cond)
        # Compute previous sample: x_t -> x_{t-1}
        sample = self.noise_scheduler.step(model_output, t, sample).prev_sample
    return sample

读法：训练是「加噪 → 预测噪声 → MSE」（一步前向，很快）；推理是「从噪声迭代去噪 num_inference_steps 次」（默认等于训练步数 100，configuration_diffusion.py:149）。两头的不对称是所有 diffusion 系模型的共性，也是它部署比 ACT 慢的根源——ACT 推理是单次前向，diffusion 推理是 100 次。scheduler 支持 DDPM/DDIM 两种（modeling_diffusion.py:176），DDIM 步数可调小提速。默认超参（configuration_diffusion.py:104-118）：n_obs_steps=2（观测历史两帧）、horizon=64、n_action_steps=32——注意它和 ACT 的 chunk_size=100 完全不同量级，第 4 章 delta_timestamps 的取窗参数必须与之匹配。

三条线在第 3 章见过的 lerobot-train（scripts/lerobot_train.py:385 的 train(TrainPipelineConfig)）汇合。组装逻辑藏在 factory 里：make_policy 按名字实例化策略 → 从数据集 metadata 拿 features 与 stats → 生成配套的 pre/post processor（归一化用 4.5 的 stats.json）：

延伸 每个 checkpoint 目录里除了 model.safetensors 和 config.json，还存着 pre/post processor 的配置（pretrained.py 的 HubMixin 序列化）。这意味着「策略 + 归一化」必须整体搬运——只拷权重不拷 processor 配置，是新手部署失败的第一大原因。
