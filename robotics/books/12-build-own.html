实战路线：六个里程碑从零到一

前 11 章是「零件」，本章是「装配图」：把硬件、数据、策略、仿真、部署串成一条可执行的项目路线。每个里程碑给出目标、命令、验收标准与常见翻车点——按此推进，一个人 + 一台 SO-101 + 一张消费级 GPU，六周可以走完全程。

12.1路线总览

真机线里程碑 训练 / 微调里程碑 持续迭代
图 12.1：六里程碑。每个都是「能演示的最小闭环」——不要在 M3 之前调模型，不要在 M5 之前优化部署。

12.2M1 硬件点亮（第 2 章）

目标：两条总线、一路相机，全部可控可读
bash# 找到串口
lerobot-find-port
# 逐个设置舵机 ID（先只接一个舵机，脚本交互式引导）
lerobot-setup-motors --robot.type=so101_follower --robot.port=/dev/ttyUSB0
# 标定中位/限位
lerobot-calibrate --robot.type=so101_follower --robot.port=/dev/ttyUSB0
验收：robot.get_observation() 能返回全部关节角度与相机帧；robot.send_action() 能让每个关节动。常见翻车：供电不足（舵机抖动/复位）——主从臂都要独立供电，别从 USB 借电（具体规格见 SO-ARM100 官方 BOM）；ID 冲突——逐个接舵机设置，别一把全接。

12.3M2 遥操作与数据采集（第 3-4 章）

目标：一键录制，50 集合格示范（命令对照 lerobot_record.py:22 官方示例）
bashlerobot-record \
  --robot.type=so101_follower --robot.port=/dev/ttyUSB0 \
  --robot.cameras="{laptop: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
  --teleop.type=so101_leader --teleop.port=/dev/ttyUSB1 \
  --dataset.repo_id=${USER}/pick_place --dataset.num_episodes=50 \
  --dataset.single_task="Grab the cube" --display_data=true
验收：LeRobotDataset 目录里有 videos/ + data/ 分片，replay 一集肉眼检查无跳变。数据质量三原则：①固定场景（光照/物体位置变化要「有意为之」，别意外抖动）；②每集之间重置到位（episode 结束的静止帧别录太多）；③宁缺毋滥——10 集干净示范胜过 50 集抽风。常见翻车：fps 与硬件实际吞吐不匹配（相机掉帧导致时间戳漂移）——先用 --display_data 观察实时流再开录。

12.4M3 模仿学习上身（第 5 章）

目标：ACT 在真机复现示范任务，成功率 > 80%
bash# 训练（单卡 4090 约半天；lerobot_train.py 官方示例即此形态）
lerobot-train \
  --dataset.repo_id=${USER}/pick_place --policy.type=act \
  --output_dir=outputs/act_pick_place
# 真机评估：lerobot-rollout 是部署策略的统一入口（lerobot-rollout.py docstring）；
# lerobot-eval 是仿真评估器，必须带 --env.type（如 pusht），真机路线用不到
lerobot-rollout \
  --strategy.type=base --policy.path=outputs/act_pick_place/checkpoints/005000/pretrained_model \
  # 目录名 = 训练步数。train 默认 steps=100000 / save_freq=20000，
  # 这里的 005000 假设你训练时显式传了 --steps=5000
  --robot.type=so101_follower --robot.port=/dev/ttyUSB0 \
  --task="Grab the cube" --duration=30
验收：先在训练集样本上核对 loss 收敛、预测动作与真值曲线重叠，再用 rollout 连续 20 次尝试计成功率（--interactive=true 可随时 /stop 急停）。调参次序：先查数据（4.5 节的 stats 是否合理）→ 再调 chunk_size 与训练步数 → 最后才动网络超参。常见翻车：camera key 与数据集对不上（observation.images.* 命名不一致）；训练用 bfloat16 但推理设备不支持——回 float32。

12.5M4 仿真 RL（第 8-10 章）

目标：LiftCube PPO 收敛，成功率达 90%+
bash# 训练（RTX GPU，几分钟到几十分钟）——3.0 起脚本在 scripts/reinforcement_learning/ 直下
./isaaclab.sh -p scripts/reinforcement_learning/train.py \
  --task IsaacContrib-Lift-Cube-Franka --num_envs 4096 --headless --rl_library rsl_rl
# 回放验证
./isaaclab.sh -p scripts/reinforcement_learning/play.py \
  --task IsaacContrib-Lift-Cube-Franka --num_envs 64 --checkpoint .../model_1500.pt
注：3.0 重组了脚本布局——train.py / play.py 从 scripts/reinforcement_learning/rsl_rl/ 上移到 scripts/reinforcement_learning/，且成为多 RL 库统一入口（--rl_library 选择后端）。--rl_library 在 contrib 任务上是必填的：dispatch 只在任务注册了 default_agent 时才自动推断（dispatch.py:128-135 找不到就报「argument is required: --rl_library」并退出码 2），而 IsaacContrib-Lift-Cube-Franka 的 gym.register 没有这个键；Isaac-Lift-Franka（core 新任务）带 default_agent="rsl_rl"，才可以省略。gym id 按任务代次取用：contrib 经典任务无 -v0 后缀，core 新任务是 Isaac-Lift-Franka。入口均经 isaaclab.sh -p 调用。
验收：TensorBoard 里 Episode_Reward 逐项爬升、success rate 曲线过 0.9；play 回放肉眼确认抓稳不抖。不收敛排查次序：先看 10.7 节调试锦囊（哪段接力棒断了）→ 检查观测是否缺关键信息（object position 没进 obs？）→ 降低任务难度（缩短初始距离）再逐步放开。常见翻车：第一次装 Isaac Sim 就想训练——先用 GUI 模式跑通一个内置任务，确认驱动与显存没问题。

12.6M5 VLA 微调（第 6-7 章）

目标：SmolVLA 在你的 50 集数据上微调并真机执行语言指令
bash# 微调（单卡一晚，默认冻结视觉塔只训动作专家）
lerobot-train \
  --dataset.repo_id=${USER}/pick_place \
  --policy.path=lerobot/smolvla_base
# 真机跑：同步推理用 lerobot-rollout（M3 已示范），异步推理栈走下面两个进程（第 11 章详读）
python -m lerobot.async_inference.policy_server --host=127.0.0.1 --port=8080 --fps=30
python -m lerobot.async_inference.robot_client \
  --robot.type=so101_follower --server_address=127.0.0.1:8080 \
  --policy_type=smolvla --pretrained_name_or_path=${USER}/smolvla_pick_place \
  --actions_per_chunk=50
# --actions_per_chunk 无默认值（configs.py:119），必须显式给
# 注意：SUPPORTED_ROBOTS 目前是 so100/so101/bi_so/omx follower（constants.py:29）
验收：换语言指令（"把方块放到左边"）仍能执行——这是 VLA 相对 ACT 的核心增量。关键开关：50 集小数据务必用 freeze_vision_encoder + train_expert_only（6.5 节）——解冻视觉塔几乎必然过拟合；先 smolvla_base 后试 pi0（7.1 节）。常见翻车：语言 prompt 与录制时的 task 字段不一致（训练 "pick the cube" 推理 "抓方块"）；显存 OOM——降 batch 或开梯度检查点，别硬扛。

12.7M6 部署与迭代（第 11 章）

上线后的迭代回路：

监控什么：①队列健康度（--debug_visualize_queue_size=True 打印的队列长度曲线，见 11.2——长期贴 0 说明推理跟不上，长期爆满说明 chunk 过大）；②网络延迟（receive_actions 日志里的 server_to_client_latency）；③成功率按指令分桶统计——泛化短板一目了然。数据飞轮：失败案例 → 回 M2 补录同类场景 → 回 M5/M3 增量微调。这是具身智能产品化的核心循环。
里程碑纪律 每个里程碑只做该里程碑的事：M1 阶段不调参、M2 阶段不改网络、M4 阶段不碰真机。跳步的最大代价不是时间，而是出了问题不知道该回哪一层查。
