VLA 前沿：π0、UnifoLM-VLA 与 Prismatic 底座

SmolVLA 用 450M 证明了小模型可行；这一章往两端走——Physical Intelligence 的 π0（3B PaliGemma + 300M 专家，openpi 官方 PyTorch 移植）代表「预训练为王」的路线；NVIDIA 的 UnifoLM-VLA 用 DiT 做动作头代表「结构解耦」的路线；而 Stanford 的 Prismatic 展示这些模型的地基是怎么打出来的。读完你就有了给自研 VLA 选型的完整坐标系。

7.1π0：大 VLM + 小专家的「力量举」版

π0 的移植版（modeling_pi0.py 注明「a direct port of the OpenPI implementation」）结构与 SmolVLA 同构，但两个骨干都换成了 Gemma 系（configuration_pi0.py:31）：

            paligemma_config, action_expert_config,
            use_adarms=[False, False],            # ADA-RMS 条件门控，π0 默认关
            precision=config.dtype, image_size=config.image_resolution[0],  # 224
            ...)

        self.action_in_proj  = nn.Linear(config.max_action_dim, action_expert_config.width)
        self.action_out_proj = nn.Linear(action_expert_config.width, config.max_action_dim)
        self.state_proj      = nn.Linear(config.max_state_dim, action_expert_config.width)
与 SmolVLA 的三点不同：①体量——PaliGemma 是 3B 级 VLM（SigLIP 400M 视觉塔 + Gemma 2B 语言塔），动作专家是 300M Gemma（gemma_300m：width=1024、depth=18，modeling_pi0.py:163），专家/VLM 比例约 1:10，比 SmolVLA 的 0.75 更「悬殊」——π0 的赌注是感知能力全部来自预训练，动作头不需要大。②逐层手工 attention——compute_layer_complete（:78）不用 transformers 的现成注意力，而是手动 QKV 投影、RoPE、eager attention，把两栈 token 拼在一起算注意力再切开：这样双栈的 K/V 可以直接互见（比 cross-attn 的注入更彻底）。③混合精度分割——整体 bfloat16，但视觉塔、多模态投影器、各 LayerNorm 强制留 float32（params_to_keep_float32，:258），防止冻结参数参与前向时的 dtype 抖动触发优化器报错。

训练目标与 SmolVLA 完全一致（:592）：

一个细节体现血统：π0 的 suffix 里 state 是单独 token 且另起 attention 段（att_masks += [1]，:548），前缀/后缀间靠掩码单向流动；推理时同样 prefix KV 缓存一次（:680，注意还 clone_past_key_values 了——每个去噪步克隆一份缓存，因为 π0 的手工 attention 会原地写入），欧拉 10 步（num_inference_steps=10）。默认微调超参也来自 openpi：lr=2.5e-5、cosine 衰减到 2.5e-6、warmup 1000 步（configuration_pi0.py:90）。如果你读过 SmolVLA 那章，「读 π0」只需对号入座——flow matching 部分两份代码逐行同源，差异全在骨干与工程细节。

7.2UnifoLM-VLA：把动作头换成一个 DiT

lerobot 里的 VLA 把动作专家缝在 VLM 内部（共享层/互看 K/V）。UnifoLM-VLA（NVIDIA + 复旦贡献）走另一条路：VLM 只当特征提取器，动作生成完全外包给一个独立的 DiT（Diffusion Transformer）：

src/unifolm_vla/model/framework/unifolm_vla.py:19 — 框架组装（节选）
python@FRAMEWORK_REGISTRY.register("unifolm_vla")
class Unifolm_VLA(baseframework):
    def __init__(self, config=None, **kwargs):
        self.qwen_vl_interface = get_vlm_model(config=self.config)   # Qwen2.5-VL
        # DiT 的 cross_attention_dim 跟着 VLM 隐藏宽度走 —— 两个模块解耦的唯一定点
        self.config.framework.action_model.diffusion_model_cfg.cross_attention_dim = \
            self.qwen_vl_interface.model.config.hidden_size
        self.action_model: FlowmatchingActionHead = get_action_model(config=self.config)
src/unifolm_vla/model/framework/unifolm_vla.py:37 — 训练 forward：VLM 出特征，DiT 出损失
pythondef forward(self, qwen_inputs, **kwargs):
    with torch.autocast("cuda", dtype=torch.bfloat16):
        qwenvl_outputs = self.qwen_vl_interface(input_ids=..., pixel_values=..., output_hidden_states=True)
        last_hidden = qwenvl_outputs.hidden_states[-1]      # [B, L, H] —— 只要最后一层隐状态

    with torch.autocast("cuda", dtype=torch.float32):
        repeated = self.config.trainer.get("repeated_diffusion_steps", 4)
        # 同一观测重复 4 次：4 个不同 (noise, t) 配对 —— 提升流匹配样本效率
        action_loss = self.action_model(
            last_hidden.repeat(repeated, 1, 1),
            actions.repeat(repeated, 1, 1),
            state.repeat(repeated, 1, 1),
        )
    return {"action_loss": action_loss}

图 7.1：UnifoLM-VLA 的「特征服务器 + 动作引擎」解耦。VLM 整体（含语言塔）都可作为冻结底座，DiT 头从零训练；repeated_diffusion_steps=4 让每个样本贡献 4 组流匹配监督。
读法：与 π0/SmolVLA 的「VLM 层内互看」相比，这种解耦有得有失——得到的是模块自由度（DiT-B 768 宽 12 头 / DiT-L 1536 宽 32 头两档任选，DiTConfig，DiT_ActionHeader.py:130；换 VLM 骨干只需对齐一个 hidden_size）与训练便宜（VLM 前向一次缓存特征，DiT 反复迭代不碰它）；失去的是端到端联合微调时的深度耦合。还有两处独特的工程选择：①时间不连续采样，而是 t×1000 离散成桶号再进正弦编码（:205）——继承自 GR00T N1.5 的动作头血统（文件头注明）；②future_tokens——32 个可学习 token 混进序列，给 DiT 一组「任务占位符」，推理时与训练时行为一致。方向约定注意：它的插值是 (1-t)·noise + t·actions，t=1 是动作、t=0 是噪声——与 π0 的记号恰好相反，读代码时别绕晕。

7.3Prismatic：VLM 本身怎么炼成

上面两节的 VLM 底座（PaliGemma、Qwen2.5-VL、SmolVLM2）都来自预训练。但「VLM 怎么预训练」值得一章体量的好奇——Prismatic VLMs（Stanford，OpenVLA 的视觉-语言底座）把这个过程做成了可复现的实验矩阵：

prismatic/models/vlms/prismatic.py:38 — 三件套结构（节选）
pythonclass PrismaticVLM(VLM):
    def __init__(self, model_id, vision_backbone, llm_backbone,
                 enable_mixed_precision_training=True, arch_specifier="gelu-mlp"):
        # 视觉塔：CLIP / DINOv2 / SigLIP，或双塔融合（prismatic/models/backbones/vision/__init__.py）
        # 语言塔：LLaMA / Vicuña / Mistral …（LLMBackbone）
        if arch_specifier == "linear":
            self.projector = LinearProjector(vision_backbone.embed_dim, llm_backbone.embed_dim)
        elif arch_specifier.endswith("fused-gelu-mlp"):
            self.projector = FusedMLPProjector(...)     # 双塔特征拼接后的 MLP
        elif arch_specifier.endswith("gelu-mlp"):
            self.projector = MLPProjector(...)          # 2 层 GELU MLP
        self.all_module_keys = ["vision_backbone", "llm_backbone", "projector"]
prismatic/models/vlms/prismatic.py:122 — 两阶段训练的冻结策略（节选）
pythondef freeze_backbones(self, stage: str) -> None:
    # "align"    → 冻视觉塔 + 冻语言塔，只训 projector（1 层 MLP 学「翻译」）
    if stage == "align":
        self.vision_backbone.requires_grad_(False)
        self.llm_backbone.requires_grad_(False)
        self.projector.requires_grad_(True)
    # "finetune" → 视觉塔仍冻；projector + 语言塔一起训
    elif stage == "finetune":
        self.vision_backbone.requires_grad_(False)
        self.llm_backbone.requires_grad_(True)
        self.projector.requires_grad_(True)
为什么给机器人书写这一节：①OpenVLA——机器人圈最有名的开源 VLA——的动作模型就是一个 7B Prismatic VLM 加动作头，其「双塔视觉」（DINOv2+SigLIP 融合）正是从 Prismatic 的对照实验里选出来的；②双塔的直觉值得记住：CLIP/SigLIP 的特征「像语言」（语义对齐），DINOv2 的特征「像眼睛」（空间结构好）——机器人既要知道「这是个杯子」也要知道「杯子在哪几像素」，融合两塔（FusedMLPProjector 把 2×embed_dim 拼接投影，nn_utils.py:37）在 VQA 上小胜单塔，这就是 OpenVLA 选它的原因。③两阶段训练配方（align 只训投影层 → finetune 解冻语言塔）就是后来所有 VLA（含 π0 的 finetune 模式）默认遵从的成本结构：视觉塔永远冻结，贵的部分不动。models/registry.py 里 20+ 组配方可查（CLIP 单塔/DINOCLIP/DINOSigLIP × Vicuña 7B/13B × 一阶段/多阶段）。

7.4三种 VLA 路线对比与选型

SmolVLA（第 6 章）π0UnifoLM-VLA
VLM 底座SmolVLM2-500M 截 16 层PaliGemma 3B（SigLIP+Gemma 2B）Qwen2.5-VL 3B/7B
动作专家Gemma 式 0.75× 宽度，与 VLM 层数对齐Gemma 300M，手工逐层互见 attention独立 DiT-B/L，cross-attn 读 VLM
耦合方式逐层 K/V 注入（半耦合）拼 token 联合 attention（全耦合）特征后处理（完全解耦）
动作生成flow matching，连续时间flow matching，连续时间flow matching，1000 桶离散时间
插值方向t=0 动作 → t=1 噪声（π0/SmolVLA）｜t=0 噪声 → t=1 动作（UnifoLM，反向记号）
训练技巧Beta(1.5,1) 时间采样同左 + 梯度检查点+ repeated_diffusion_steps=4
适合场景单卡微调、真机部署大数据集、追求泛化上限换底座/做消融的研究场景
选型心得：三者共享同一数学内核（直线流匹配 + MSE 学速度场），差别全在「VLM 与动作头绑得多紧、谁负责感知、预训练借多少力」。经验法则：数据少 → 冻结面大（SmolVLA/π0 的 train_expert_only）；数据多 → 全耦合端到端（π0 全量微调模式）；想换骨干做研究 → 解耦（UnifoLM）。lerobot 的 policies/ 里还有 pi05、groot、wall_x、xvla 等后来者，接口一致，读完本章源码迁移成本都很低。
回顾 三章模型线到此收束：第 5 章的接口卡（forward / select_action / predict_action_chunk）+ 第 4 章的数据 schema + 本章的三种架构 = 具身智能「学习侧」的完整拼图。接下来换到「环境侧」：不是让机器人在真机上试错，而是在 Isaac Lab 里并行跑 4096 个世界。
