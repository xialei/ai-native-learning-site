SmolVLA：当 VLM 学会动手

第 5 章的策略「看」到的是像素，但不「理解」语言——你说「把杯子放到盘子上」，ACT 听不懂。VLA（Vision-Language-Action）把预训练 VLM 的语言与视觉理解嫁接到动作生成上。本章以 SmolVLA（最小而全：SmolVLM2-500M 主干 + ×0.75 动作专家 + 流匹配）为标本问下去：双塔怎么搭？一次前向怎么撑起十步去噪？流匹配的训练与推理各长什么样？单卡微调的经济学靠哪几个开关？6.1 总览作答，6.2–6.4 逐层拆解，6.5 收尾。

6.1① 总览：VLM 主干 + 动作专家 + 流匹配

一个 VLA 要回答的问题是：语言指令进来、机器人动作出去，中间的知识从哪来、动作怎么生成。SmolVLA 的答案是三件套——VLM 主干供理解、动作专家出动作、流匹配当生成器。先看结构。SmolVLAPolicy 是包在 VLAFlowMatching 外面的一层皮，后者才是网络本体。源码里自带的架构注释说明了全部结构：

src/lerobot/policies/smolvla/modeling_smolvla.py:466 — VLAFlowMatching 结构注释（摘录）

VLM 塔（前缀，一次前向） 动作专家塔（每去噪步执行）
图 6.1：双塔分工——「看懂」交给 VLM 塔（一次前向缓存 KV），「动手」交给小专家塔（每个去噪步只跑它）。这就是 VLA 推理能压到消费级显卡的关键：贵的部分不重复算。
为什么是「专家」而不是第二个大模型：核心一句话——理解不发生在专家的权重里，它发生在 VLM 的 KV cache 里，专家只是个「读缓存的小查询器」，所以天然可以窄。三个源码事实撑起这句话：① 专家从 config 随机初始化、不加载 VLM 权重（smolvlm_with_expert.py:118 的 AutoModel.from_config，出生时对图像语言一无所知）；② 它连词表都没有（:138 embed_tokens = None），输入是 action_in_proj/state_proj 投影进来的连续向量（modeling_smolvla.py:511-512）——它对世界的全部理解只能来自每层 cross-attention 读 VLM 的 KV cache（:122-135 把 VLM 维度的 K/V 投影进专家的小空间），它不是知识的容器，是知识的查询器，查询器不需要跟知识库一样大；③ 它要学的函数输出低维低熵（50 步 × 几十维连续速度场），而 VLM 学的「看懂+听懂」来自数十亿 token 预训练——容量分配跟着难度走。另外，专家是每个去噪步都跑的（6.2 的循环 ×10），循环体必须小，第二个 500M 大模型直接让「prefix 算一次、suffix 十次便宜循环」的消费级显卡经济学破产。

「共享结构但宽度更窄」不矛盾——这是两个独立的旋钮：结构（同）= 块的拓扑（RMSNorm、RoPE、GQA、16 层堆叠，num_vlm_layers=16），复用结构是省去重新设计调参——这种 block 已被 VLM 预训练验证过会收敛；宽度（窄）= 每层 hidden_size = int(hidden_size * expert_width_multiplier)（配置默认 0.75，configuration_smolvla.py:98），纯容量旋钮。还有个佐证细节：self_attn_every_n_layers=2——专家塔每隔一层才保留一次对自己的 self-attention，其余层纯 cross-attention；suffix 就是一个噪声动作块（约 50 个 token），自己人之间没什么好交互的，主要信息得从 prefix 拿——真正独立的第二个语言模型绝不会这么设计。参数量约 450M，微调时只训专家一半，显存进一步减半。这套「大模型管理解、小专家管动手」不是 SmolVLA 的发明：7.1 的 π0 同款——3B PaliGemma 冻结出 KV，≈300M 的 flow-matching 动作专家每步去噪时跑；SmolVLA 把这个比例推得更极端。锚点：宽度乘法器 smolvlm_with_expert.py:110；cross-attn 重塑 smolvlm_with_expert.py:122-135。
KV cache 是什么：transformer 注意力用到的 Key/Value 向量。若每步重算整个前缀序列的 K/V，代价随序列长度平方增长；把它们缓存起来（use_cache=True），后续只需算新 token 的注意力——这里即「VLM 看一遍图像和指令，缓存理解结果；十步去噪每步只跑小专家塔」。不熟悉的话记住结论即可：贵的部分只算一次，便宜的部分反复用。

6.2② prefix 与 suffix：一次前向，十步去噪

知道整体是双塔，接下来该问：十步去噪每步都要跑一次网络，为什么 VLM 主干不会被算十遍？答案在 prefix 与 suffix 的切分。embed_prefix 把图像、语言、状态编码成一个 token 序列；embed_suffix 把「噪声动作块 + 时间步」编码成另一个序列。推理时 prefix 只算一次：

src/lerobot/policies/smolvla/modeling_smolvla.py:775 — denoise_step（节选）
pythondef denoise_step(self, prefix_pad_masks, past_key_values, x_t, timestep):
    """Apply one denoising step of the noise `x_t` at a given timestep."""
    suffix_embs, ... = self.embed_suffix(x_t, timestep)      # 噪声动作 + 时间 → token
    outputs_embeds, _ = self.vlm_with_expert.forward(
        inputs_embeds=[None, suffix_embs],                 # prefix 不再输入
        past_key_values=past_key_values,                    # 读缓存
    )
    if past_key_values is not None:
        # Self-attention layers append suffix K/V in place; restore the prefix for the next step.
        past_key_values.crop(prefix_len)                   # 弹出本轮 suffix 的 KV，保缓存纯净
    suffix_out = outputs_embeds[1][:, -self.config.chunk_size:]
    v_t = self.action_out_proj(suffix_out)
    return v_t
读法：去噪循环的每一步，真正变的是 suffix（当前噪声动作块 x_t 与时间步 t）；prefix（看到的与听到的）完全不变。所以把 prefix 的 KV 缓存起来、每步只前向 suffix——10 步去噪的总成本 ≈ 1 次完整前向 + 10 次小专家前向。crop(prefix_len) 是个容易忽略的细节：self-attention 会把 suffix 的 KV 追加进缓存，若不裁掉，下一步的注意力会「看到」上一步的噪声动作，污染生成过程。

6.3③ 流匹配：训练一行公式，推理一个欧拉循环

去噪十步，每一步「噪声怎么变动作」的规则就是流匹配要学的东西。它比 diffusion 更直接：不再学「噪声是什么」，直接学速度场。训练前向只有两行核心公式：

pythondef euler_integrate(denoise_fn, noise, num_steps, ...):
    """Forward-Euler integration of a velocity field from t=1 (noise) to t=0 (actions).
    This is the openpi sampling loop: dt = -1/num_steps, time = 1.0 + step*dt,
    x_t ← x_t + dt * v_t, with the optional real-time-chunking (RTC) guidance hook."""
    dt = -1.0 / num_steps
    x_t = noise                                    # t=1：纯噪声
    for step in range(num_steps):
        time = 1.0 + step * dt                    # 1.0 → 0.0 均匀下降
        v_t = denoise_fn(x_t, time_tensor)
        x_t = x_t + dt * v_t                       # 沿速度场走一小步
    return x_t                                     # t=0：动作块
扩散 / 流匹配路径 训练与推理的对比重点
图 6.2：流匹配一句话——「训练时已知两端学方向（MSE），推理时只知道方向走欧拉」。与第 5 章 diffusion 对比：目标从「噪声 ε」换成「速度 u_t」，去噪步数从 100 降到 10。
读法：x_t = t·noise + (1−t)·actions 把「噪声→动作」的路修成直线，任意 t 处的真速度恒为 noise − actions。模型只要学会「在任意位置指对方向」，推理时就能从纯噪声一路走直线到动作。与 diffusion 的两个实用差异：① 推理步数少一个数量级（10 vs 100），实时机器人控制买得起；② 时间步采样用 Beta 分布（sample_time_beta，α=1.5 偏向大 t，flow_matching.py:54）——噪声端的插值点更「陌生」，多练。π0、π05、SmolVLA 共用这套 euler_integrate（flow_matching.py 注释：openpi 衍生策略历史上各带一份拷贝，现已收敛为公共实现），还预留了 RTC 钩子（rtc_processor 参数，目前由 evo1 策略实际接入）。

6.5收尾：小 VLA 的完整标本

6.1 开头的三个问题，答案收拢：双塔是「VLM 塔供理解、专家塔出动作」，专家经 cross-attn 读 VLM 的 KV cache；推理靠 prefix 一次前向 + KV 缓存复用，十步去噪只跑 suffix；流匹配训练一行速度场公式、推理一个欧拉积分循环；单卡微调的经济学靠 freeze_vision_encoder / train_expert_only 两个开关，缺相机时补黑帧 + mask=0 让行为平滑退化。一张表带走：
