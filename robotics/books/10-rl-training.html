RL 训练：奖励塑形、课程学习与域随机化

环境心跳（第 9 章）只是舞台，真正让策略「练出本事」的是三件套：奖励塑形给方向、课程学习给台阶、域随机化给鲁棒性。本章拆 LiftCube 奖励表的接力棒设计，看 curriculum 怎么随进度收紧难度、EventCfg 四种 mode 的随机化入口——最后看 rsl_rl 的 PPO 如何包住 4096 个环境批量采样。

10.1奖励塑形：接力棒设计

LiftCube 的 RewardsCfg 六个术语，各自负责一段接力（lift_env_cfg.py:138-164）：

术语函数参数权重塑形作用
reaching_objectmdp.object_ee_distancestd=0.1+1.0引导手靠近物体（连续塑形）
lifting_objectmdp.object_is_liftedminimal_height=0.04+15.0「抬起」达标记号（二值）
object_goal_trackingmdp.object_goal_distancestd=0.3, success_threshold=0.05+16.0粗跟踪目标位姿
..._fine_grainedmdp.object_goal_distancestd=0.05+5.0精跟踪（5cm 内才显著）
action_ratemdp.action_rate_l2 ‖aₜ−aₜ₋₁‖²—−1e-4抑制抖动
joint_velmdp.joint_vel_l2 ‖q̇‖²—−1e-4节能 / 护硬件
三个塑形心法：①密集引导 + 稀疏达标记号：reach 是连续指数塑形 exp(−d²/std²)——每一步都有梯度；lift 是二值标志 ×15——达成后持续给大额奖励。纯密集信号会被「贴着物体蹭」钻空子，补一个稀疏大额项防钻空。②std 即影响半径：exp(−d²/std²) 在 std=0.1 时 10cm 内梯度显著、30cm 外近乎为零；粗细两档跟踪的 std 差 6 倍，正是「远时粗、近时精」的接力棒。③惩罚项写负权重：action_rate 与 joint_vel 的 −1e-4 看似小，但课程后期会放大到 −1e-1（见 10.2）。

10.2课程学习：先宽后严

isaaclab_tasks/.../lift/lift_env_cfg.py:179 — CurriculumCfg
python@configclass
class CurriculumCfg:
    # 前 10000 步权重 -1e-4（探索期宽容）；10000 步后突变到 -1e-1（重罚抖动）
    action_rate = CurrTerm(func=mdp.modify_reward_weight,
                           params={"term_name": "action_rate", "weight": -1e-1, "num_steps": 10000})
    joint_vel   = CurrTerm(func=mdp.modify_reward_weight,
                           params={"term_name": "joint_vel",   "weight": -1e-1, "num_steps": 10000})
「先宽后严」范式：两个课程项都用 mdp 库现成的 modify_reward_weight——前 10000 步用配置原值 −1e-4 让策略自由探索（别怕抖），10000 步后突变到 −1e-1（放大 1000 倍），逼出平滑动作。触发时机：CurriculumManager.compute 在 _reset_idx 最前跑（9.3 节），以 common_step_counter（全局步数）判断是否到达 num_steps。课程也可以反向用——locomotion 任务常见「terrain_levels」地形课程：跑得好的机器人被分配更难地形。

10.3域随机化：EventCfg 与四种 mode

域随机化（Domain Randomization）的入口是 EventCfg。LiftCube 自带两项（lift_env_cfg.py:121-134）：

isaaclab_tasks/.../lift/lift_env_cfg.py — EventCfg（节选）
python@configclass
class EventCfg:
    # 每次重置：先归零到配置初始状态，再叠加随机偏移
    reset_scene_to_default = EventTerm(func=mdp.reset_scene_to_default, mode="reset")
    # 物体初始位姿随机化：x ±0.1m、y ±0.25m
    reset_object_position = EventTerm(
        func=mdp.reset_root_state_uniform,
        mode="reset",
        pose_range={"x": (-0.1, 0.1), "y": (-0.25, 0.25), "z": (0.0, 0.0)},
        asset_cfg=SceneEntityCfg("object"))
    # 更激进的 DR 需自己加：摩擦 randomize_rigid_body_material、质量 randomize_rigid_body_mass、
    # 执行器参数（刚度/阻尼）、actuator 延迟……mdp 库都有现成函数
四种 mode 对应四个随机化时机（9.1 节）：prestartup——场景实体存在前改 USD 级参数（如 USD 属性）；startup——启动一次性（如每环境固定质心偏移）；reset——每集重置重抽（最常用）；interval——episode 中途按时间间隔扰动，locomotion 招牌是「每隔几秒推一下机器人（push_robot）」。②「先归零再随机」：reset_scene_to_default 先把场景拉回 cfg 初始状态再叠加 pose_range 噪声，保证一万集之后不累积漂移——两个 EventTerm 的声明顺序即执行顺序，归零项必须写在前。③ LiftCube 没配 interval 项——抓取不需要中途扰动，但你的任务需要时应加。

10.4rsl_rl PPO：包住 4096 个环境

PPO（近端策略优化）一句话：反复「采样一批经验 → 按优势（比预期好多少）放大好动作、压制差动作的概率 → 但用 KL 散度限制每次更新的步长，防止一步走崩」。它是机器人 RL 的事实默认，rsl_rl 就是它的一个 GPU 高效实现。Isaac Lab 不自带 RL 算法——经 RslRlVecEnvWrapper（isaaclab_rl/rsl_rl/vecenv_wrapper.py:25）接入 rsl_rl：把五元组翻成 VecEnv 接口、把 extras["log"] 的逐项奖励/episode 长度喂给 TensorBoard。训练一行命令：

一键训练 LiftCube（agents/rsl_rl_ppo_cfg.py 提供超参）
bash./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/train.py \
    --task Isaac-Lift-Cube-Franka-v0 --num_envs 4096 --headless
isaaclab_tasks/.../franka/agents/rsl_rl_ppo_cfg.py:12 — LiftCubePPORunnerCfg（节选）
python@configclass
class LiftCubePPORunnerCfg(RslRlOnPolicyRunnerCfg):
    num_steps_per_env = 24          # 每环境采 24 步 → rollout 24×4096 ≈ 98k 帧
    max_iterations = 1500           # 外层迭代数
    actor = RslRlMLPModelCfg(hidden_dims=[256, 128, 64], activation="elu",
                             distribution_cfg=...GaussianDistributionCfg(init_std=1.0))
    algorithm = RslRlPpoAlgorithmCfg(
        clip_param=0.2, entropy_coef=0.006, num_learning_epochs=5, num_mini_batches=4,
        learning_rate=1.0e-4, schedule="adaptive", gamma=0.98, lam=0.95,
        desired_kl=0.01, max_grad_norm=1.0)
注意策略网络的「小」：actor 是 [256,128,64] 的三层 MLP——对比第 5-7 章的 VLA（亿级参数）差五个数量级。RL 策略学的是一个任务的特定技能（状态→动作映射），观测是低维向量（9 个关节位置 + 9 速度 + 3 物体位置 + 指令 + 上一步动作）；VLA 学的是跨任务的通用常识。第 12 章路线图会对比两条技术路线的取舍。adaptive 学习率：schedule="adaptive" 按 desired_kl=0.01 自适应——若一次更新后 KL 散度超阈，步长减半；太小则加倍。这是 rsl_rl 对「PPO 超参敏感」的标准解法。

10.6域随机化 vs 系统辨识：两种哲学

两种哲学：域随机化赌「世界够乱、真机只是其中一种乱法」——用 4096 个世界的方差覆盖真机方差，策略被迫学不变性（对摩擦、质量、延迟不敏感）。系统辨识（System Identification）反向而行：用真机数据把仿真参数校准到接近真实值。实践中组合拳常见：先用系统辨识把「大结构」对齐（质量/摩擦落在合理区间），再用 DR 覆盖残余不确定性。actuator 家族（8.5 节）是这条缝的第一道防线——ActuatorNet 直接用真机数据学力矩模型，属于「学出来的系统辨识」。第 11 章 sim2real 会把这条缝补完。

10.7小结

三件套配置入口一句话
奖励塑形RewardsCfg（weight ± 函数+参数）密集引导 + 稀疏达标记号，std 决定影响半径
课程学习CurriculumCfg（modify_reward_weight）难度随进度收紧（−1e-4 → −1e-1 @10000 步）
域随机化EventCfg（prestartup/startup/reset/interval）用 4096 个世界的方差覆盖真机方差
调试锦囊 训练不收敛先看 extras["log"]["Episode_Reward/*"] 逐项曲线：哪个正项一直不涨（如 lifting_object 一直 0）就说明策略卡在那段接力棒上——回去查塑形参数（std/minimal_height），而不是上来就改网络。
