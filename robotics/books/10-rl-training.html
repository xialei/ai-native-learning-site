RL 训练：奖励塑形、课程学习与域随机化

环境循环（第 9 章）只是提供了采样能力，真正让策略「练出本事」的是三件套。本章沿一条训练回路问下去：奖励表怎么设计才不把策略带沟里？课程怎么随进度收紧？域随机化从哪进配置、四种 mode 怎么用？PPO 怎么包住 4096 个环境批量采样？10.1–10.3 拆三件套的配置，10.4–10.5 看 rsl_rl 的 PPO 回路，10.6 对照两种哲学，10.7 收尾。

10.1① 奖励塑形：接力棒设计（contrib 旧版）

「让策略自己试出抓取」太难，「给个评分函数」就是全部的方向盘。3.0 起官方任务库把 Lift 任务拆成两代：contrib/lift/ 保留经典的 LiftCube 设计（gym id 前缀也改为 IsaacContrib-），新版设计在 core/lift/。旧版 RewardsCfg 六个术语，各自负责一段接力（contrib/lift/lift_env_cfg.py:135-161）：

术语函数参数权重塑形作用
reaching_objectmdp.object_ee_distancestd=0.1+1.0引导手靠近物体（连续塑形）
lifting_objectmdp.object_is_liftedminimal_height=0.04+15.0「抬起」达标记号（二值）
object_goal_trackingmdp.object_goal_distancestd=0.3, minimal_height=0.04, success_threshold=0.05+16.0粗跟踪目标位姿（须已抬起）
..._fine_grainedmdp.object_goal_distancestd=0.05, minimal_height=0.04+5.0精跟踪（5cm 内才显著）
action_ratemdp.action_rate_l2 ‖aₜ−aₜ₋₁‖²—−1e-4抑制抖动
joint_velmdp.joint_vel_l2 ‖q̇‖²—−1e-4节能 / 护硬件
三个塑形要点：①密集引导 + 稀疏达标记号：reach 是连续核函数塑形 1 − tanh(d/std)——每一步都有梯度；lift 是二值标志 ×15——达成后持续给大额奖励（源码注释自己写着 "tanh-kernel"）。纯密集信号会被「贴着物体蹭」钻空子，补一个稀疏大额项防钻空。②std 即影响半径：1 − tanh(d/std) 在 std=0.1 时 10cm 内梯度显著（d=0 给满 1.0，d=std 只剩 0.24，d=3·std 约 0.005）；粗细两档跟踪的 std 差 6 倍，正是「远时粗、近时精」的接力棒。注意跟踪项还乘了 is_lifted 门控——物体没抬起来时距离再近也不给分，避免「把方块推到位但没抓」骗奖励。③惩罚项写负权重：action_rate 与 joint_vel 的 −1e-4 看似小，但课程后期会放大到 −1e-1（见 10.2）。

10.2② 课程学习：两代设计

奖励管「每一步的评分」，课程管「难度随进度变化」。两代设计思路不同。contrib 旧版「先宽后严」：两个课程项都用 mdp 库现成的 modify_reward_weight——前 10000 步用配置原值 −1e-4 让策略自由探索（别怕抖），10000 步后突变到 −1e-1（放大 1000 倍），逼出平滑动作（contrib/lift/lift_env_cfg.py:176）：

isaaclab_tasks/.../contrib/lift/lift_env_cfg.py:176 — CurriculumCfg
python@configclass
class CurriculumCfg:
    # 前 10000 步权重 -1e-4（探索期宽容）；10000 步后突变到 -1e-1（重罚抖动）
    action_rate = CurrTerm(func=mdp.modify_reward_weight,
                           params={"term_name": "action_rate", "weight": -1e-1, "num_steps": 10000})
    joint_vel   = CurrTerm(func=mdp.modify_reward_weight,
                           params={"term_name": "joint_vel",   "weight": -1e-1, "num_steps": 10000})

core 新版 ADR（Automatic Domain Randomization）：课程对象从「改奖励权重」升级为「改整个任务配置」。入口是一个 DifficultyScheduler（core/lift/adr_curriculum.py:13）：

isaaclab_tasks/.../core/lift/adr_curriculum.py:13 — CurriculumCfg（节选）
python@configclass
class CurriculumCfg:
    # adr = automatic/adaptive domain randomization：难度 0→10 由成功率驱动
    adr = CurrTerm(func=mdp.DifficultyScheduler,
                   params={"init_difficulty": 0, "min_difficulty": 0, "max_difficulty": 10})
两代范式的差别：旧版在「固定任务里调惩罚权重」，新版在「同一任务里渐进放大随机化」——难度每升一级，ADR 课程就用 modify_term_cfg + initial_final_interpolate_fn 把 12 项配置朝「更难」方向插值一步：观测噪声逐级放大（关节位置/速度、指尖状态、物体四元数、点云共 5 处，各 min/max 成对）、越界终止的 z 下边界从 0.3 放宽到 0.0（重力进场后物体落在桌上，别误判成出界）、重力从零逐步倾斜到真实 −9.81。注意 ADR 不动质量与摩擦——那些是 startup 阶段一次性固定的。触发时机不变：CurriculumManager.compute 在 _reset_idx 最前跑（9.3 节）。课程也可以反向用——locomotion 任务常见「terrain_levels」地形课程：跑得好的机器人被分配更难地形。

10.3③ 域随机化：EventCfg 与四种 mode

课程给了台阶，域随机化给「同一个世界的一千种变体」。域随机化（Domain Randomization）的入口是 EventCfg。contrib 版 LiftCube 只有两项重置随机化（contrib/lift/lift_env_cfg.py:118-131）；core 新版在 startup 模式就铺了 6 项随机化（Franka 派生再加夹爪闭合速度 1 项）：

isaaclab_tasks/.../contrib/lift/lift_env_cfg.py:118 — EventCfg；core/lift/lift_env_cfg.py:237（节选）
python@configclass
class EventCfg:
    # --- contrib 旧版：两项，都在 reset 模式 ---
    # 每次重置：先归零到配置初始状态，再叠加随机偏移
    reset_all = EventTerm(func=mdp.reset_scene_to_default, mode="reset")
    # 物体初始位姿随机化：x ±0.1m、y ±0.25m
    reset_object_position = EventTerm(
        func=mdp.reset_root_state_uniform, mode="reset",
        params={"pose_range": {"x": (-0.1, 0.1), "y": (-0.25, 0.25)}, ...})

# --- core 新版：startup 模式批量随机化物理参数（节选） ---
    robot_physics_material = EventTerm(func=mdp.randomize_rigid_body_material, mode="startup",
                                       params={"static_friction_range": [0.5, 1.0], ...})
    joint_stiffness_and_damping = EventTerm(func=mdp.randomize_actuator_gains, mode="startup", ...)
    variable_gravity = EventTerm(func=mdp.randomize_physics_scene_gravity, mode="reset", ...)
四种 mode 对应四个随机化时机（9.1 节）：event_manager.py 的文档写明 prestartup——仿真启动前改 USD 级属性（如网格 collider）；startup——启动一次性（如新版 Lift 的摩擦/刚度/阻尼/质量随机化，每环境固定一套值贯穿训练）；reset——每集重置重抽（最常用）；interval——episode 中途按时间间隔扰动，locomotion 招牌是「每隔几秒推一下机器人（push_by_setting_velocity）」。②「先归零再随机」：contrib 版 reset_all 先把场景拉回 cfg 初始状态再叠加 pose_range 噪声，保证一万集之后不累积漂移——两个 EventTerm 的声明顺序即执行顺序，归零项必须写在前。③ core 版还有一项设计值得注意：conditional_reset——重置不是每次都从均匀分布抽，而是先按有效性判据（物体与机器人的网格间隙、物体与桌面的间隙）拒绝采样出一个初始状态库、之后冻住，再按实测成功率加权重采（SuccessMonitorCfg(target_success_rate=0.5)），让已掌握的和还不会的状态都得到练习。④ 两版都没配 interval 项——抓取不需要中途扰动，但你的任务需要时应加。

10.4④ rsl_rl PPO：包住 4096 个环境

三件套是训练的「内容」，最后一块拼图是「引擎」——哪段代码真正在跑。PPO（近端策略优化）概括成一句话：反复「采样一批经验 → 按优势（比预期好多少）放大好动作、压制差动作的概率 → 用概率比率裁剪限制单步更新的幅度：新旧策略对同一动作的概率比 r = π_new/π_old，目标函数里把 r 裁剪在 [1−ε, 1+ε]（rsl_rl 的 clip_param=0.2），一步更新最多把动作概率拉偏 20%，防止走崩」。它是机器人 RL 的事实默认，rsl_rl 就是它的一个 GPU 高效实现。注意 KL 散度在 PPO 里不是约束机制——原论文的 KL-penalty 变体用「KL 罚项加进目标函数」达到同样目的，如今更多只用于监控（训练曲线里盯 KL 是否超标）；rsl_rl 另辟一径，把 KL 用在自适应学习率上（本节稍后的 schedule="adaptive"，clip_param 管单步更新、KL 管学习率快慢，两者分工不同）。Isaac Lab 不自带 RL 算法——经 RslRlVecEnvWrapper（isaaclab_rl/rsl_rl/vecenv_wrapper.py:25）接入 rsl_rl：把五元组翻成 VecEnv 接口、把 extras["log"] 里的逐项奖励与终止计数喂给 TensorBoard（episode 长度由 rsl_rl 自己从 dones 统计，IsaacLab 侧的 log 里没有这个键）。两代任务的训练命令与超参都换了：

一键训练（脚本已上移一层；两代 id 都没有 -v0 后缀）
bash# contrib 旧版：前缀改为 IsaacContrib-，id 本身无后缀

10.6域随机化 vs 系统辨识：两种哲学

两种哲学：域随机化赌「世界够乱、真机只是其中一种乱法」——用 4096 个世界的方差覆盖真机方差，策略被迫学不变性（对摩擦、质量、延迟不敏感）。系统辨识（System Identification）反向而行：用真机数据把仿真参数校准到接近真实值。实践里两者常先后用：先用系统辨识把「大结构」对齐（质量/摩擦落在合理区间），再用 DR 覆盖残余不确定性。core 新版 Lift 的 ADR 把这套哲学推进一层：随机化幅度本身也是课程——难度 0 时重力偏移为零、噪声为零，随成功率爬到难度 10 时才逼近真实 −9.81 m/s² 与满幅噪声，相当于「边训练边系统辨识」。actuator 家族（8.5 节）在 sim2real 链路里先挡一层——ActuatorNet 直接用真机数据学力矩模型，属于「学出来的系统辨识」。第 11 章 sim2real 接着讲剩下的差距来源。

10.7收尾：三件套 + 一个引擎

10.1 开头的那串问题，答案收拢：奖励塑形用「接力棒」把大任务拆成六段可引导的子目标（contrib），或「进度奖励不回头」（core）；课程两代思路——旧版按步数突变权重，新版 ADR 按个体成败升降难度；域随机化入口是 EventCfg 的四种 mode（prestartup/startup/reset/interval，各管一拍）；PPO 由 rsl_rl 在 GPU 上包住 4096 个环境批量采样，概率比率裁剪限幅。三件套一张表：

三件套配置入口一句话
奖励塑形RewardsCfg（weight ± 函数+参数）contrib：密集引导 + 稀疏达标记号；core：进度奖励「到过的高度不再计分」
课程学习CurriculumCfg（modify_reward_weight / DifficultyScheduler）contrib 调惩罚权重（−1e-4 → −1e-1）；core 用 ADR 渐进放大随机化
域随机化EventCfg（prestartup/startup/reset/interval）用 4096 个世界的方差覆盖真机方差
排查次序 训练不收敛先看 extras["log"]["Episode_Reward/*"] 逐项曲线：contrib 版哪个正项一直不涨（如 lifting_object 一直 0）就说明策略卡在那段接力棒上——回去查塑形参数（std/minimal_height）；core 版看 ADR 难度曲线——难度是按个体升降的（episode 结束时该环境的 success 标志为真则 +1，否则 −1），曲线不涨说明多数环境没成功过，先调奖励再谈课程，而不是上来就改网络。
下一步 训练完成只是开始——策略要下真机：gRPC 异步推理、远程队列聚合、action chunk 消费，见 第 11 章：Sim2Real。
