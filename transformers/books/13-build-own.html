Chapter 13 · Build Your Own

自研路线:从库里拿什么,自己写什么

前 13 章把一个库拆成了部件:分词、注意力、缓存、生成循环、logits 加工、模板、工具调用、训练、装载。这一章换个方向——不拆,拼。第 0 章的三个问题都答完了,最后的问题是「我知道了这些,然后呢?」:想自己搭一套「模型 + Agent」的系统,哪些件直接从 transformers 拿,哪些件去它的邻居库里拿,哪些件必须自己写、写到什么程度。

这一章不做新拆解,做三张清单:按「库内(直接用)/半库内(扩展用)/库外(自己写)」给全部部件定位;按三种常见目标(单机 Agent、训练微调、服务化)给出取件顺序;最后把全书的「库内/库外」分界收成一张总表。

答案地图 四问的答案依次是:① 「用库」的默认姿势是 Auto 类 + from_pretrained + generate/chat template——这一层封装已经覆盖「单机单进程跑通一个模型」的全部需求,大多数自研第一步是承认「这层不用自研」(13.1);② 三张清单按使用深度分层:库内件(transformers 直接给)、半库内件(TRL/PEFT/accelerate 这些同门邻居)、库外件(Agent 循环、RL 后训练、多机服务),每件标了去哪拿、注意什么(13.2);③ 三条路线(单机 Agent、训练微调、服务化)是同一批件的三种拼法,差异在取舍——取舍的依据是前三问的答案(13.3);④ 全书的分界收成一句话:transformers 负责「把权重变成概率分布」这一段,这一段之前(数据、训练框架)和之后(执行、循环、服务)都有各自的库,自研的正确单位是「段」,不是「行」(13.4)。

13.1默认姿势:这一层不用自研

先说一个反直觉的结论:大多数「自研 LLM 系统」的项目,死在重新发明了 transformers 已经做对的部分,而不是死在没造出别人没有的部分。库的默认姿势就四行:

默认姿势(全书出现过的四行)
pythonfrom transformers import AutoModelForCausalLM, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("model")                  # 第 2 章:分词
model = AutoModelForCausalLM.from_pretrained("model", dtype="auto")  # 第 12 章:装载
out = model.generate(**tokenizer("hi", return_tensors="pt"))          # 第 5 章:生成循环

这四行背后站着全书拆过的所有东西:meta 设备建壳与权重流入(12.2)、KV Cache 的分配与复用(第 4 章)、停止条件与 logit 加工(第 5、6 章)、注意力后端路由(第 3 章)。自己写一个「最简推理循环」并不难——第 5 章的 5.1 节,裸 while 循环二十行——但第 5 章同时说了,从二十行到生产可用的距离是采样策略矩阵、投机解码、流水线异常处理,这些 generate 里都有。所以清单的第一行是负项:推理循环本身,不建议自研。值得自研的是它两侧的东西。

什么时候连 generate 都该绕开:需要逐 token 控制循环的场合——流式工具调用解析(第 9 章的 ResponseParser 配合自己的循环)、每步要改 KV 策略的研究代码、教学演示。这时用 model.forward + 自己管理 past_key_values,等于把第 5 章的循环展开手写。库支持这种用法(forward 本来就是公开接口),但你要自己补上停止条件、采样、长度管理——generate 里那 3252 行 logits_process 不是装饰。绕开与否的判断标准:你的循环里有没有「模型之外的状态」需要每步参与决策。有,绕;没有,用 generate。

13.2三张清单:库内、半库内、库外

第一张清单按「拿货渠道」分三列。「库内」直接 import;「半库内」是 HuggingFace 同门——接口与 transformers 咬合,装上就能用,但那是另一个库;「库外」是本站其他书覆盖的领域,transformers 只提供挂点。

部件渠道拿什么(pin)对应章节
分词与响应解析库内AutoTokenizer、parse_response(tokenization_utils_base.py:3414)2、9

「半库内」列的判断标准:不用它,你要重写的代码是「周边工程」(分布式脚手架、RL 循环、LoRA 注入)还是「模型语义」(注意力、缓存、采样)?前者去半库内拿——它们与 transformers 的接口是官方维护的;后者才值得留在自己手里。TRL 值得单独一句:第 11 章说过「解题能力主要靠后训练 RL 灌进去」,那个过程不在 transformers 里,但 TRL 的每个训练步调的还是 Trainer 的 training_step、算的还是本章的 loss——半库内的意思是「换引擎不换燃料」。

第二张清单是反面:哪些东西看起来该有、库里其实没有。这份「无」清单比第一张更省时间:

13.3三条路线,三种拼法

同一批件,按目标拼三次。每条路线给「最小组合」和「下一步加什么」,不展开代码——各章已拆过每件的内里。

路线最小组合下一步风险集中在
单机工具调用 AgentAutoModel + chat template(tools=)+ StopStringCriteria + ResponseParser + 自己写的执行循环流式解析上前端(9.3);多模型路由(第 1 章的 Auto 表按 config 选型);量化降显存(12.3)循环的会话状态与重试(库外);格式收敛(库内 9.3 的 _coerce)
领域微调 + 部署Trainer(SFT)+ PEFT(LoRA)+ 第 11 章的数据格式;部署走 from_pretrained + 量化要「教解题」再上 TRL;数据量小先用 11.4 的 return_assistant_tokens_mask 控制损失面数据质量(11.4 的教训:只在 assistant 段算 loss);精度计划(12.3b)
服务化(多人用)generate_batch + continuous batching(第 7 章);KV Cache 预算(7.3)并发过百换引擎(sglang/vLLM 书);量化选型(12.4 的「解压或不解压」账法)准入与换出策略(库外);GGUF/bnb 的精度损失(12.3b)
三条路线共用一个决策模板:先问「模型不行,还是系统不行」——第 0 章把这两个故障域分开过。格式错、重复、跑题 → 模型侧,查第 6 章的处理器链和第 11 章的数据;超时、排队、OOM → 系统侧,查第 7 章的预算和第 12 章的显存账。再问「这个行为是能力还是表达」——能力(该调不调工具、答案对不对)在权重,改它靠训练(11 章)或换模型;表达(格式对不对、停得对不对、约束生效没)在推理栈,改它靠 logits 加工(6 章)与停止条件(5 章)。两个问题问完,该动哪一层基本就定了。这套分诊逻辑是全书分界表的用法,比任何具体代码更值得带走。

13.4全书收口:一张分界总表

第 0 章承诺过「第 13 章把三问收口成一张清单」。三问各自的库内件,连同出处章节,合成最后一表——它同时是全书目录的另一种排法:

三问库内件(章节)库外件(去处)
怎么记住互联网分词入口与词表(2);注意力检索 + FFN 键值(3);KV Cache(4);RoPE(3);训练把语料写进权重(11)知识在权重里的具体形态(可解释性方向)
怎么调用工具schema 织入(9.1);模板控制符(8);停止截取 + 解析回参(9.3);工具调用的数据侧(11.4)执行循环、权限、多轮记忆(本站四本 agent 书)
能力从哪来解码策略与 logits 加工(5、6);训练循环(11);装载与量化(12)RL 后训练过程(TRL);奖励模型设计(独立方向)
收口的话:第 0 章把这本书定位成「transformer 怎么把整个互联网都记住、怎么支持 agent 调用工具、解决问题的办法从哪来」的三问之书。13 章走完,三个答案各自落在一小段代码上:记住,是 3 章的检索 + FFN 键值;调用,是 9 章的五环;解题,是 11 章的训练把模式写进权重、5/6 章的表达把模式读出来。库的边界也始终没动过——权重以里是它的全部,权重以外的循环、数据、奖励,由别的书接管。要继续深入模型侧,本站的 vLLM、sglang、on-device 三本书接着讲「这份权重怎么被高效地跑起来」;要深入循环侧,pi-agent、claude-code、deepseek-harness、langgraph 四本书讲「模型外面的那套系统怎么搭」。两边的书合起来,才是「AI 解决问题」的完整工程图。

本章小结

自研的正确单位是「段」,不是「行」。推理循环、分词、模板、工具协议、训练步、装载——这些「模型侧」的件直接从 transformers 拿;RL 后训练(TRL)、LoRA(PEFT)、分布式(accelerate)从同门半库内拿;Agent 循环、多机服务、数据流水线在库外,本站各有专书。三条路线(单机 Agent、微调部署、服务化)是同一批件的三种拼法,差异只在取舍。两个通用判断带走:「模型不行还是系统不行」分开故障域;「能力还是表达」分开改法——能力靠训练,表达靠推理栈。全书三个问题的最后归位:记住互联网的是权重(3 章机制 + 11 章写入),支持工具的是五环协议(9 章),解决问题的能力在训练里灌、在推理栈里表达(11 + 5/6 章)。
