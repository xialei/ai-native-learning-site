Codex 的设计哲学

Codex 自我定位是「安全、可控、可在终端里干活的编码 Agent」。下面把几条核心特色，对应到本站可以读到的源码章节——看完产品话术，再去看它怎么实现的。

↻

Turn 循环：采样 → 工具 → 再采样

一个 turn 就是一个 loop {}：构建 prompt、流式调用 LLM、解析工具调用、执行、把结果塞回历史、再循环——直到模型不再请求工具。重试、中断、steering 全在循环里。

工具系统：原语 + 注册表

ToolExecutor trait 定义工具运行时契约，ToolSpec 描述给模型的 JSON schema。shell、apply_patch、exec_command、view_image…… 一套注册表统一调度，支持并行工具调用。

第 7 章 · 工具系统 →
🛡

沙箱 + 审批：安全的默认值

三档沙箱（read-only / workspace-write / danger-full-access），macOS 用 seatbelt、Linux 用 bubblewrap。审批策略决定哪些命令要人确认。默认安全，按需放权。

真正的上下文工程

每个 turn 重新组装 prompt：base instructions、AGENTS.md 项目指令、developer/user 指令、工具结果、压缩摘要…… 全部是可组合的 Context Fragment，按需注入。

第 5 章 · 上下文构建 →
{ }

Op / Event 双向协议

客户端发 Op（提交、中断、审批），内核回 EventMsg（流式 token、工具调用、完成）。会话就是一串 ResponseItem。一套协议撑起 TUI、CLI、app-server 三种前端。

第 2 章 · 协议模型 →
⊕

MCP / 插件 / 技能扩展

原生 MCP 客户端接外部工具服务器，连接器（connectors）接 SaaS，插件（plugins）注入工具与上下文，技能（skills）按需载入指令。扩展点遍布各层。

第 10 章 · MCP 与扩展 →

✓ 它给你的，是分层 + 契约

  • 协议先行：codex-protocol crate 把所有类型（Op/Event/ResponseItem/SandboxPolicy）独立出来，内核与前端共享
  • 依赖注入：内核不直接调 LLM API，通过 ModelClientSession 抽象，provider 可替换
  • ToolExecutor trait：工具是接口，内置工具与 MCP 工具走同一套运行时
  • Context Fragment：上下文是可组合的片段，不是写死的字符串拼接

138 个 crate 的工作区，但真正理解 Agent 运行时，只需聚焦 core 与 protocol 两个 crate。

✗ 它把复杂度放在了哪

  • 沙箱复杂度：跨平台隔离（seatbelt/bwrap）+ 执行策略判定，是「安全默认」的代价
  • 会话复杂度：rollout 持久化 + 回放重建 + 压缩，保证崩溃可恢复与上下文不爆
  • 多前端复杂度：TUI/CLI/app-server/exec-server 四种外壳共享内核，协议层承担胶水
  • 扩展复杂度：MCP + 插件 + 连接器 + 技能，扩展点多意味着编排逻辑分散

Codex 追求「安全可控的生产级编码 Agent」，因此把大量精力放在沙箱、审批、持久化——这些正是自研时容易偷懒却最该学的地方。

学习路径

STEP 1

整体架构

Cargo workspace 的 138 个 crate 如何分层：protocol → core → tui/cli/app-server。一次 prompt 从哪里走到哪里。
STEP 2

消息与协议模型

ResponseItem（会话条目）、Op（客户端操作）、EventMsg（内核事件）三套类型，如何构成双向通信。
STEP 3

★ Turn 循环

核心中的核心：CodexThread → Session → run_turn → run_sampling_request 的 loop，流式、重试、中断、steering。
STEP 4

会话与 Rollout

Session 如何持有会话状态，rollout JSONL 如何持久化与回放，world state 追踪了什么。
STEP 5

★ 上下文构建

每个 turn 的 prompt 怎么拼：Context Fragment 体系、base instructions、AGENTS.md、context manager。
STEP 6

上下文压缩

token 预算、阈值触发、本地 vs 远程压缩、摘要生成、context window 管理。
STEP 7

★ 工具系统

ToolSpec / ToolExecutor trait、工具注册表、内置工具清单、工具调用从分发到执行的全生命周期。
STEP 8

审批与沙箱

审批策略（AskForApproval）、沙箱模式（SandboxPolicy）、execpolicy 命令判定、跨平台隔离实现。
STEP 9

配置系统

config.toml schema、requirements.toml、配置分层、权限档案（permission profiles）。
STEP 10

MCP 与扩展

MCP 服务器集成、连接器、插件、技能、动态工具与 tool_search。
STEP 11

多 Agent 与协作

Agent 角色、子 Agent 派生、agent 注册表、Agent 间通信、协作模式。
STEP 12

TUI 与 CLI

终端 UI 渲染、CLI 模式（交互 / exec / app-server）、客户端-服务端分离。
