Claude Code 是什么：从「补全」到「执行」的那一步

这一章不写代码，只把概念摆正：Claude Code 到底是什么形态的工具、它和聊天框 / 代码补全的本质区别在哪里、以及它为什么把「动手」当成第一公民。
官方定义 「An agentic coding tool that lives in your terminal, understands your codebase, and helps you code faster by executing routine tasks, explaining complex code, and handling git workflows.」 → 本站把它拆成「agentic + 在终端 + 理解代码库 + 执行」四个关键词逐一展开。

1.1一分钟版本

Claude Code 是一个 agentic 编码工具：你用自然语言提需求，它自己读代码库、改文件、跑命令、看结果、再继续，直到任务完成。它不是一个只会给建议的聊天框，也不是只在编辑器里补全一行的插件。本质上它在回答一个问题：「给定一个目标，模型如何调动工具一步步把它做出来？」

它能落地，靠四件事拼起来：

  • 模型：Claude，支持流式输出与原生工具调用（tool_use）。
  • 工具：Bash、读写文件、网络搜索/抓取——模型用函数调用驱动它们。
  • 权限 + Hooks：把「能动手」框在可拦截、可审计的边界里。
  • 上下文工程：系统提示 + CLAUDE.md 记忆 + 压缩，让模型每轮看到该看的。
心智锚点 后面所有章节都在围绕这四件事展开。如果你只能记住一句话：循环决定它怎么干，上下文决定它看到什么，权限与 Hooks 决定它能在哪条线上干。

1.3与聊天框 / 代码补全的本质区别

很多人把 Claude Code 类比为「更好的 Copilot」。这个类比会误导你。差别不在「质量」，而在交互范式：

图 1.1：补全 / 聊天 / Agentic 的本质差别在于「谁来执行」。
为什么这个区别重要： 一旦把执行权交给模型，设计重心就从「答得准」转向「循环、上下文、边界」三件套：循环让它能多步推进，上下文让它每步看对东西，边界让它别闯祸。这正是本站后续章节的全部主题。

1.4它能做什么 / 不做什么

✓ 擅长

  • 跨文件改动：理解一个需求涉及的多处，一并改
  • git 工作流：commit、push、开 PR、处理 review
  • 跑命令看结果：跑测试、读报错、据错再改
  • 解释复杂代码：在真实仓库里追调用链
  • 程序化批量任务：经 SDK 跑在 CI / 脚本里

✗ 边界 / 需谨慎

  • 不会替你拍板：架构取舍、产品决策仍要人定
  • 有权限墙：默认对写/执行要确认，不会偷偷动手
  • 上下文有限：超长仓库需靠子代理 / 压缩 / 按需读
  • 可能出错：会编造 API、改错地方——所以才有 Hooks 兜底
  • 不训练你的数据：使用数据有明确留存与访问限制

读法建议 内核机制（循环 / 上下文压缩）的描述以官方公开文档为准，本站引用的代码片段大多来自上述仓库实例（Hooks、插件、配置）——这些是可运行、可对照的部分，最适合边读边试。
