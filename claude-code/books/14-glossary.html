14.3真实范例：一个 slash 命令的定义

本仓库 .claude/commands/commit-push-pr.md 是一个真实命令定义——Markdown 带 frontmatter 声明允许的工具与描述，正文是给模型的指令：

.claude/commands/commit-push-pr.md（真实仓库内容，完整）
markdown---
allowed-tools: Bash(git checkout --branch:*), Bash(git add:*), Bash(git status:*), Bash(git push:*), Bash(git commit:*), Bash(gh pr create:*)
description: Commit, push, and open a PR
---

## Context

- Current git status: !`git status`
- Current git diff (staged and unstaged changes): !`git diff HEAD`
- Current branch: !`git branch --show-current`

## Your task

Based on the above changes:
1. Create a new branch if on main
2. Create a single commit with an appropriate message
3. Push the branch to origin
4. Create a pull request using `gh pr create`
5. You have the capability to call multiple tools in a single response. You MUST do all of the above in a single message. Do not use any other tools or do anything else. Do not send any other text or messages besides these tool calls.
读懂这段（命令的三大要素）： ① allowed-tools——命令级最小权限，只放行这几条 git/gh 子命令（呼应第 6 章），模型干不了别的。② !`...` 反引号插值——命令展开时先跑这些 shell 片段，把 git 状态/diff/分支注入到提示里（上下文工程的体现，第 4 章）。③ 明确的步骤指令——告诉模型分几步、且要一次性并发完成。一个 .md 文件就把「权限 + 上下文 + 指令」三件事说清了，这就是命令原语的简洁。

14.4CLI 参数速查

参数作用
claude启动交互式会话
claude -p "<prompt>"一次性打印模式（headless，输出结果即退出）
--model指定模型
--dangerously-skip-permissions跳过所有权限确认（仅可信/隔离环境）
--allowed-tools限定可用工具（驼峰 --allowedTools 同义）
--max-turns循环轮次上限
--output-format json结构化输出（脚本友好）
提示 -p 打印模式是 CLI 里的 headless 入口，等价于 SDK 的最简用法——适合在 shell 脚本里调一行就拿到结果。复杂自动化还是用 SDK（第 11 章）更可控。

14.5关键文件路径速查

路径是什么
~/.claude/CLAUDE.md全局项目记忆（个人）
./CLAUDE.md项目记忆（团队共享）
~/.claude/settings.json用户配置
.claude/settings.json项目配置
.claude/settings.local.json本地配置（不提交）
managed-settings.json企业托管配置（MDM 下发）
.claude/commands/*.md项目自定义 slash 命令
.mcp.jsonMCP 服务器声明
plugins/*/.claude-plugin/plugin.json插件元数据
注意区分： 上表中 ~/.claude/CLAUDE.md、~/.claude/settings.json、.claude/settings.json、.claude/settings.local.json、managed-settings.json 是 Claude Code 运行时读取的路径（你机器上的配置文件），不是 anthropics/claude-code 仓库里自带的文件——仓库的 .claude/ 只含 commands/。仓库里可对照的配置范例在 examples/settings/ 与 examples/mdm/，可对照的插件源码在 plugins/ 与 mods/（见 §14.6）。
