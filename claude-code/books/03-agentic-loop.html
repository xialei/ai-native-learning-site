Agentic 循环：让模型自己决定下一步的那台机器

★ 重点。这一章拆开 Claude Code 的「心脏」：提示进入后，模型如何被反复调用、工具结果如何回灌、循环何时停。理解了它，你就理解了「agentic」的全部含义。
核心机制 模型不再只回答一次，而是「回答 → 调用工具 → 看结果 → 再回答」直到任务完成。 → 这就是 ReAct（Reason + Act）模式在真实产品里的落地。

3.1一分钟版本：什么是 agentic 循环

普通聊天是单轮：你问 → 模型答 → 结束。Agentic 循环是多轮自驱动：模型答的时候可以附带「我要调用某个工具」，系统执行该工具、把结果塞回去，模型再基于结果继续答——如此往复，直到模型不再要求调用工具，循环结束。

单次推理变成有状态的推进。 停的条件：模型这轮不再要求调用任何工具（任务完成或无法继续）。 人为停：用户随时可中断（Esc / abort）；SDK 可设 maxTurns 等上限。
图 3.1：Agentic 循环。模型与工具交替推进，工具结果回灌成下一轮的上下文。
这一张图胜过千言： 整个 Claude Code 的「agentic」就浓缩在这条回路里。后面所有机制——上下文（第 4 章）、工具（第 5 章）、权限与 Hooks（第 6、8 章）——都是挂在「执行工具」这个节点上的：上下文决定模型看到什么，权限决定工具能不能跑，Hooks 决定跑前后插什么逻辑。

3.2turn 与 tool_use：循环的两个粒度

循环里有两个粒度要分清：

  • turn（轮）：一次「调用模型 → 拿到它的回复」。一个 turn 里模型可能产出文本，也可能产出若干个 tool_use。
  • tool_use（工具调用）：模型在回复里声明「我要调 Bash，参数是 …」。系统执行后，把 tool_result 作为新的 user 角色消息回灌，触发下一个 turn。
图 3.2：三个 turn 的序列。每个 tool_result 都成为下一个 turn 的输入。
为什么必须回灌成 user 消息 在 Anthropic 的消息 API 里，tool_result 以 user 角色出现，且必须紧跟在对应的 tool_use 之后。这解释了一个常见约束：对话不能以 assistant 的 tool_use 结尾——否则模型在等一个永远不会到来的结果。循环必须把结果补上，或主动结束。

3.3工具结果如何变成模型可读的东西

循环执行工具后，原始输出（文件内容、命令 stdout、报错）要被格式化成 tool_result 喂回模型。这一步决定了模型「看得清不清楚」：

概念示例：tool_result 的结构（Anthropic 消息格式）
json{
  "role": "user",
  "content": [
    {
      "type": "tool_result",
      "tool_use_id": "toolu_01ABC...",      // 必须对应模型声明的 tool_use_id
      "content": "文件全部内容 / 命令输出 / 错误信息",  // 字符串或结构化块
      "is_error": false                        // 工具失败时标 true，模型会据此调整
    }
  ]
}
读懂这段： 两个细节决定循环质量。① tool_use_id 配对——模型一轮可能并发多个 tool_use，结果必须按 id 配对回灌，否则模型会混乱。② is_error——工具失败（如命令非零退出、文件不存在）不是悄悄吞掉，而是明确告诉模型「这一步失败了」，模型会在下一轮换策略。这就是 agentic 循环能「看报错再改」的根基。

3.4循环在哪里停：终止条件

终止情形谁触发说明
自然完成模型某轮不再产出 tool_use，仅文本回答 → 循环结束
用户中断人交互模式下 Esc 中断当前 turn；SDK 可 abort
达到上限系统SDK 可设 maxTurns，防失控
工具被拒权限 / Hooks关键工具被 deny，模型可能放弃或换路
出错系统API 错误、不可恢复异常 → 终止并报错
要点 「自然完成」是最被低估的信号：模型选择不再调工具，意味着它认为任务做完了或做不动了。在 agentic 工作流里，区分「做完了」和「卡住了」要靠后续判断（测试 / review / Hook 校验），而非相信模型的自述。这也是为什么 Hooks 常被用来兜底验证。

3.5流式：循环不是「等完才给」

循环里每一次「调用模型」都是流式的——文本一个 token 一个 token 地吐，工具调用也是增量解析。这带来两个体验上的关键点：

  • 实时反馈：你在 TUI 里看到模型边想边写，而不是干等几秒后整段蹦出。
  • 可中断：流式意味着你可以在模型还在吐的时候 Esc 打断，已吐的部分不丢。

在 SDK 里，流式表现为一个事件流：文本增量、工具调用开始 / 结束、消息结束等事件依次到达，程序按需消费。这正是第 11 章的核心。

SDK 概念示例：消费流式事件（伪代码）
typescriptfor await (const message of query({ prompt, options })) {
  for (const block of message.content) {
    if (block.type === "text")        process.stdout.write(block.text);  // 文本增量
    else if (block.type === "tool_use") console.log("调用工具:", block.name); // 工具调用
  }
}
// 循环在 query() 迭代器耗尽时结束——背后就是 agentic loop
读懂这段： 表面是一段 for await，背后是完整的 agentic 循环在转：每次模型要调工具，SDK 自动执行并把结果回灌，再继续产出下一个 message——你消费的是循环的输出流，循环本身被 SDK 封装了。这就是「同一内核，SDK 外壳」的含义。

3.7对使用与扩展的启示

要点 ① 循环让「看报错再改」成为默认——所以别怕让模型跑测试，它的价值在失败后那一轮。② 停止信号要靠外部验证——模型说「完成」不等于真完成，用 Hook / 测试兜底。③ 流式 + 可中断是体验关键——做 SDK 自动化时记得消费事件流而非死等。④ 每个工具调用都是一个可拦截决策点——这是权限与 Hooks 的立足之地。
