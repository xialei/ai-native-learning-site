SDK 与程序化集成：把内核当库用

交互式 TUI 只是外壳之一。Claude Agent SDK 让你把同一个 agentic 内核当库嵌进自己的程序——无人值守、流式消费、注入自定义工具与 MCP。这一章拆 SDK 的查询/流式模型、headless 自动化，以及云网关部署。
定位 同一内核，SDK 外壳：驱动者是代码，结果是事件流。 → 对应第 2 章架构图 L1 的 SDK 形态。

11.1一分钟版本

Claude Agent SDK 把 agentic 内核暴露成可编程接口：你发一个 prompt，它返回一个异步迭代器，逐个 yield 出消息。背后就是第 3 章那套循环在转——SDK 自动执行工具、回灌结果、继续推进——你只管消费输出。

它和 TUI 的差别在四点：驱动者是代码而非人、确认通常跳过或自定义、输出是结构化事件而非终端打印、场景是 CI/脚本/批处理而非交互。

11.2查询与流式：消费事件流

SDK 概念示例：发起一次 agentic 查询并消费流（伪代码；包名 @anthropic-ai/claude-agent-sdk，旧入口 @anthropic-ai/claude-code 已移除）
typescriptimport { query } from "@anthropic-ai/claude-agent-sdk";

const conversation = query({
  prompt: "修复 src/api 下所有失败的测试，跑通为止",
  options: {
    maxTurns: 20,                  // 循环上限，防失控
    allowedTools: ["Bash", "Read", "Edit"],  // 限定可用工具
    permissionMode: "bypassPermissions"   // headless 自动化，按需
  }
});

for await (const message of conversation) {
  for (const block of message.content) {
    if (block.type === "text")
      process.stdout.write(block.text);          // 文本增量
    else if (block.type === "tool_use")
      console.log(`[工具] ${block.name}`);    // 工具调用
  }
}
读懂这段： 表面是 for await，背后是完整 agentic 循环。三个关键点：① maxTurns——SDK 没有人在场按 Esc，必须设循环上限防失控（呼应第 3 章终止条件）。② allowedTools——程序化场景应收窄工具集，最小权限。③ permissionMode——无人值守要么跳过确认（仅限可信环境），要么自定义确认逻辑。你消费的是循环的输出流，循环本身被 SDK 封装。

11.3消息块类型

流里 yield 出的 message，其 content 是若干块。常见的块类型：

块类型含义
text模型的文本回答（增量）
tool_use模型声明要调某工具
tool_result工具执行结果
thinking / 推理模型的中间思考（若开启）

程序按需过滤这些块——比如只关心 tool_use 做审计日志，或只取 text 拼最终答案。

11.4注入自定义工具与 MCP

SDK 不只能用内置工具，还能注入自定义工具（你的函数）和MCP 服务器（第 12 章）。这让 Claude Code 成为「嵌进任意系统」的引擎：

  • 自定义工具：注册一个函数，模型可以像调 Bash 一样调它——比如调你内部的部署 API。
  • MCP 注入：接上 MCP 服务器，模型获得访问数据库 / 内部系统的新工具集。
真实范本 plugins/agent-sdk-dev 就是「用 SDK 搭应用」的开发套件——带 /new-sdk-app 命令交互式搭建新 Agent SDK 项目，还有 agent-sdk-verifier-py/ts 两个子代理校验你的 SDK 应用是否符合最佳实践。它本身就是 SDK 用法的产品级示范。

11.5headless 自动化场景

场景怎么用 SDK
CI 里自动修测试失败时跑一次 query，maxTurns 限死，结束取结果
批量代码迁移对一批文件循环调 query，脚本驱动
构建自定义助手SDK 做内核，外面包你自己的 UI/CLI
GitHub 上 @claude事件触发 SDK 跑，结果回写 PR 评论
自动化的安全 无人值守 = 没人拦。务必：① 收窄 allowedTools；② 跑在隔离环境（容器/VM）；③ 设 maxTurns 防失控；④ 谨慎用 bypassPermissions，能用沙箱就用沙箱（第 6 章）。

11.6云网关部署（examples/gateway）

把 Claude Code 跑到云端、给团队共享，需要一道网关。本仓库 examples/gateway/ 提供了 GCP 与 AWS 的真实部署工件：

云工件架构
GCPDockerfile / setup.sh / gateway.yaml.example / terraform/Cloud Run 或 GKE + Cloud SQL + Secret Manager，上游接 Agent Platform
AWS同上结构对应的 AWS 资源 + Terraform

网关把 claude gateway 二进制跑成服务，配上游 IdP 与模型供应方。这是「把 SDK 内核做成多用户服务」的工程化范本——适合组织内集中托管。

读法： 这些是参考部署而非受支持的产品（README 原话：「working example rather than a supported production deployment」）。意思是结构可学、细节要按自己环境改——Terraform 两遍 apply 的注释就是典型「真实工程坑」的提示。

11.7对使用的启示

要点 ① SDK = 可编程的同一内核——交互能做的，程序化都能做，且更适合批处理。② 消费事件流而非死等——流式让你边跑边处理、随时 abort。③ 自动化要戴护具——限工具、限轮次、跑沙箱。④ 网关是团队化的下一步——从「单机 SDK」到「组织共享服务」，仓库的 gateway 示例是起点。
