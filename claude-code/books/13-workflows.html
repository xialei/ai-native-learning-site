实战工作流：把原语串成招式

前面十二章是零件。这一章把它们组装成可落地的工程招式：TDD 循环、PR 审查、大型重构、CI 自动修复——每个都对应到具体的原语组合与仓库里的官方插件。
心法 好的工作流 = 让模型在循环里「试错—验证—再试」，并用外部信号（测试/Hook/审查）兜底。 → 招式不是写死的功能，而是原语的编排。

13.1招式一：TDD 循环

让模型「写测试 → 跑 → 看红 → 写实现 → 跑 → 看绿」。循环天然适合 TDD，因为它的价值在失败后那一轮。

图 13.1：TDD 循环。模型用 Bash 跑测试，is_error 的失败结果驱动它继续。
  • 原语：Bash（跑测试）+ Edit/Write（改实现）+ 循环（失败自动重试）。
  • 关键：测试命令非零退出 → tool_result 标 is_error → 模型看到报错继续改。
  • 护栏：用 PreToolUse Hook 拦住「跑测试前没先写测试」，或限定 allowedTools。
为什么好用： TDD 把「完成」的判定权从模型自述外包给了测试——绿了才算完。这正好治第 3 章说的「模型说完成不等于真完成」。任何能用客观信号验收的任务，都该套这个循环。

13.2招式二：PR 审查（fan-out 并行）

审查一个 PR 单线做容易漏维度。用子代理 fan-out，每维度一个专职代理并行审：

  • 原语：子代理（第 7 章）+ 专职 agents（如 pr-review-toolkit 的 6 个代理）。
  • 真实范本：plugins/code-review 审查阶段跑 4 个并行代理（2 个 Sonnet 审 CLAUDE.md 合规、2 个 Opus 审 bug/历史）；plugins/pr-review-toolkit 有 comment-analyzer/pr-test-analyzer/silent-failure-hunter/type-design-analyzer/code-reviewer/code-simplifier 六个维度代理。
  • 关键：每个代理独立窗口、只盯一维、产出结论汇总；置信度过滤掉误报。
组合点 审查完可以接 plugins/commit-commands 的 /commit-push-pr 把修复推上去——审查与修复在同一条流水线里。这就是「插件即招式组件」的体现。

13.3招式三：大型重构（子代理探查 + 主代理执行）

跨仓库的大重构，主线容易被探查噪声撑爆。范式：子代理探查 → 主代理据结论动手。

  1. 派 code-explorer 子代理（plugins/feature-dev 真实角色）全仓库搜索受影响处，回传「影响清单 + 关键文件」。
  2. 主代理据清单逐个 Edit，保持主线上下文干净。
  3. 用 Bash 跑测试/类型检查验收，失败则循环修。
为什么这样分： 探查阶段读文件多、噪声大，适合塞进子代理窗口（第 4、7 章）；执行阶段要全程可观测、要逐步确认，留在主线。这是「脏活隔离、细活留主线」的标准分工。

13.4招式四：CI 自动修复（headless SDK）

CI 跑挂了，自动让 Claude Code 修：

  • 原语：SDK（第 11 章）headless 跑，maxTurns 限死、allowedTools 收窄、跑在容器里。
  • 流程：CI 失败 → 脚本把报错喂给 query() → 模型改码 → 重跑测试 → 绿则推修复分支，红则记日志。
  • 护栏：bypassPermissions 只在隔离环境用；用 PostToolUse Hook 校验改动不越界。
边界 自动修复适合确定性高、可客观验收的失败（测试、类型、lint）。架构性问题、需求歧义别交给自动修——那是人的决策。让客观信号当裁判，是所有自动化工作流的共性。

13.5招式五：自迭代循环直到完成

让模型反复处理同一任务直到完成：plugins/ralph-wiggum 就是这个范式——一个 Stop Hook 拦截退出尝试，让 Claude 继续迭代，配 /ralph-loop 与 /cancel-ralph 控制启停。

设计启示： 这是「用 Hook 改变循环终止行为」的极端案例——第 3 章说循环在「无 tool_use」时停，而这里的 Stop Hook 在退出点介入，把它再推回去。可见 Hook 不只做护栏，还能重塑循环的控制流。当然要配 maxTurns 或显式 cancel 防无限循环。

13.6通用心法

✓ 该做的

  • 用客观信号验收：测试/类型/lint 当裁判
  • 脏活隔离：探查派子代理
  • 并行独立维度：fan-out 审查
  • 护栏前置：Hook 拦危险、限工具
  • 写 CLAUDE.md：固化项目约定

✗ 别做的

  • 信模型自述「完成」：要验收
  • 把仓库塞进提示：用工具按需读
  • 无人值守不设限：maxTurns/工具/沙箱
  • 架构决策交给自动：留给人
  • 重要信息只留对话历史：压缩会丢，落文件
