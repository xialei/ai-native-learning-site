MCP 外接工具：扩展模型能触达的世界

内置工具（Bash/文件/网络）只够做通用编码。要把数据库、内部 API、业务系统接进来，靠 MCP（Model Context Protocol）。这一章拆 MCP 在 Claude Code 里的角色、配置方式，以及它和插件/权限的关系。
定位 MCP 是「工具的 USB 接口」——任何系统能按这个协议暴露成工具与资源，模型就能用。 → 它是扩展层（第 2 章 L2）连接外部世界的标准通道。

12.1一分钟版本

内置工具是固定的（Bash、Read、Edit、WebSearch…）。MCP 让你按一个标准协议接入任意外部系统，把它们的能力变成模型可调用的工具、可读取的资源。一个 MCP 服务器可以是一个本地进程，也可以是远程服务。Claude Code 通过 .mcp.json 声明要接哪些。

12.2MCP 在循环里的位置

图 12.1：MCP 工具与内置工具并列，模型一视同仁地调用。
关键认知： 对模型而言，MCP 工具和内置工具没有本质区别——都是 tool_use，都过权限与 Hooks（第 6、8 章）。MCP 的意义在于接入方式标准化：你不用改内核，写个符合协议的服务器，模型就能用上你暴露的能力。

12.3配置：.mcp.json

MCP 服务器在 .mcp.json 里声明。它可放在插件目录里（随插件分发），也可项目级/用户级配置：

概念示例：.mcp.json 声明一个 MCP 服务器
json{
  "mcpServers": {
    "my-db": {
      "type": "stdio",                       // 本地进程：通过 stdin/stdout 通信
      "command": "node",
      "args": ["./tools/db-mcp-server.js"],
      "env": { "DB_URL": "..." }
    },
    "internal-api": {
      "type": "sse",                         // 远程：通过 HTTP/SSE 通信
      "url": "https://internal.corp/mcp"
    }
  }
}
读懂这段： 两种传输：① stdio——本地子进程，Claude Code 拉起它、用标准输入输出对话，适合自带工具脚本；② sse/HTTP——远程服务，适合共享的企业 MCP 服务器。env 可注入连接信息（注意别把密钥提交进仓库，用本地覆盖或密钥管理）。
传输类型补充 MCP 远程传输有两套："type": "http"（Streamable HTTP，当前推荐）与 "type": "sse"（旧版 SSE）。本地进程则用 "type": "stdio"。新部署的远程服务器优先选 http。

12.4MCP 暴露的三种能力

能力是什么模型怎么用
Tools（工具）可调用的函数tool_use 调用，拿 tool_result
Resources（资源）可读取的数据（文件、记录）按需读取注入上下文
Prompts（提示模板）预定义的提示直接展开使用

最常用的是 Tools——把「查订单」「部署服务」「搜内部知识库」暴露成工具，模型就能在你的业务系统上动手。

12.5MCP 与权限 / 插件的关系

  • 权限：MCP 工具同样受 allow/ask/deny 约束（第 6 章）。注意沙箱不适用于 MCP——要拦 MCP 得用权限规则。
  • 插件：插件目录可带 .mcp.json，把 MCP 服务器随插件一起分发（第 10 章）——装插件即接工具。
  • 企业控制：enableAllProjectMcpServers 等键控制是否自动信任项目级 MCP；企业策略可限制只允许受信 MCP。
安全提醒 MCP 把外部系统变成模型的「手」，也扩大了攻击面。务必：只接受信服务器、用权限规则限定敏感 MCP 工具、密钥走环境变量/密钥管理而非提交。一个恶意的 MCP 工具结果可能包含提示注入——模型应把它当不可信数据处理。

12.6对使用的启示

要点 ① MCP 是连接业务系统的标准通道——不用改内核，写个服务器即可扩展模型触达。② 与内置工具一视同仁——同样过权限与 Hooks。③ 随插件分发——把 MCP 配置打包进插件，团队一键接入。④ 安全在外围收口——受信来源、权限限定、密钥管理、警惕提示注入。
