DeepSpeedEngine：三行训练循环背后的三百个分支

从这一章进入 DeepSpeed 半场。用户写的循环只有三行：forward、backward、step。DeepSpeedEngine 把这三行展开成：GAS 边界判断、loss 缩放、梯度分区归约、优化器子组步进。这一章先看引擎骨架，第 7、8 章再深入 ZeRO 各 stage 在这三行里的挂点。

6.1initialize()：一行调用背后的装配线

用户入口是一行 deepspeed.initialize()：

deepspeed/__init__.py — initialize()（签名摘录）
pythondef initialize(args=None,
                model,
                model_parameters,
                training_data=None, ...,
                config=None, config_params=None,
                mpu=None,                  # 外部并行信息注入点（Megatron-DeepSpeed 融合）
                dist_init_required=None, ...):
装配顺序（engine.py 里逐步展开）：① 解析 config json → ② distributed_init（若进程组未初始化）→ ③ 用 mpu 参数接入外部并行信息（第 2 章 2.2 节的插头——Megatron-DeepSpeed 融合走这里）→ ④ 按 zero_stage 选择优化器包装（stage 0/1/2/3 对应不同的 ZeroOptimizer 类）→ ⑤ 注册 hook 与梯度累积器。返回的 engine 才是后续训练的主角：engine.backward(loss) / engine.step() 是引擎的方法，不是 torch 原生——这是所有 DS 用户代码的统一姿势，也是容易出 bug 的地方（绕过引擎直接 loss.backward() 会跳过全部缩放与归约逻辑）。

6.2forward / backward / step 三部曲

deepspeed/runtime/engine.py — 三部曲（摘录，注释为译注）
python# backward（engine.py:3286 附近）
def backward(self, loss, allreduce_gradients=True, release_loss=False):
    # ① GAS：microbatch 间的 loss 先除以累积步数（平均而非求和）
    loss = self.scale_loss(loss)
    if not self.is_gradient_accumulation_boundary():
        return  # 不会走到这里——除法总是做的，见下文
    # ② 反传（scale 内部已乘 loss scale）
    loss.backward()
    # ③ 收尾：ZeRO-1/2 的梯度分桶归约挂在 epilogue
    self._backward_epilogue()

# step（engine.py:3471 附近）
def step(self):
    if not self.is_gradient_accumulation_boundary():
        return              # 非边界：no-op，继续累积
    self._take_model_step() # 边界处：真正执行
逐行读：backward 里最关键的一行在 scale_loss 内部：loss = loss / self.gradient_accumulation_steps()——除法必须在 backward 之前，因为 fp16 下还有 loss scale 乘回来，除和乘的次序决定最终梯度是「平均」还是「平均后再缩放」。实际代码把「除 GAS」与「乘 loss scale」都放进 scale_loss 链条里一次完成。step 的关键：非边界直接 return——「step 被调 N 次、真正执行 1 次」由 GAS 边界决定，用户循环里每 microbatch 调 step 也完全正确，正确性不依赖用户数对步数。_take_model_step 里依次是：overflow 检查 → optimizer.step()（ZeRO 语义在这一步，第 7/8 章）→ 更新 lr schedule → zero grad buffer。
deepspeed/runtime/engine.py — is_gradient_accumulation_boundary（摘录）
pythondef is_gradient_accumulation_boundary(self):
    return self.global_steps % self.gradient_accumulation_steps() == 0 or self.is_last_step()
一切节拍的总开关：microsteps 计数器到 GAS 即边界。GAS、数据 dataloader 步进、梯度归约、优化器 step 全部挂在这一个判定上——引擎替用户管理「什么时候真的 step」，这是 DS 相对裸 PyTorch 最省心的地方。

6.4配置与启动器

DS 的全部行为由一个 json 驱动，启动器负责多进程：

deepseek 融合配置示例（ds_config.json，示意）
json{
  "train_batch_size": 1024,          // = micro_batch × DP × GAS，引擎反推各值
  "gradient_accumulation_steps": 4,
  "zero_optimization": { "stage": 2 },
  "optimizer": { "type": "Adam", "params": { "lr": 3e-4 } },
  "fp16": { "enabled": true, "loss_scale_window": 1000 }
}
三个必懂的键：① train_batch_size 与 GAS/micro_batch 互相约束——给两个引擎推第三个，冲突直接报错（很多新手在这报错里打转）；② zero_optimization.stage 是第 7/8 章的全部内容；③ fp16.enabled 决定 scaler 类型（动态 vs 静态，第 7 章对比 Megatron 的选择器）。启动用 deepspeed --num_gpus=8 train.py——launcher 负责把 rank/env 立起来，用户脚本里 deepspeed.init_distributed() 或 initialize() 隐式完成。

6.5小结 + 自研启示

用户代码引擎内部展开对应章节
initialize(model, ...)装配 config/mpu/optimizer 包装/hook本章
engine.forward(...)GAS pre-forward 清理、ZeRO-3 fetch第 8 章
engine.backward(loss)loss/GAS → loss scale → backward → epilogue 归约第 7 章
engine.step()边界外 no-op、边界处 _take_model_step第 7/8 章
save/load_checkpointuniversal checkpoint第 12 章
自研启示 DeepSpeed 的用户契约只有五件事：initialize / forward / backward / step / config。自研 trainer 值得抄的是「边界判断集中在引擎」：用户每 microbatch 调 step()，每次都被边界挡回去，正确性不依赖用户数对 microbatch 数。另外记住次序：loss 先除 GAS 再 backward——backward 之后除是错的，梯度已经固化进缓冲。
