流水线并行：1F1B 调度怎么排

PP 把模型按层切成阶段，各阶段占一张（组）卡。朴素的 GPipe 填满后再统一反传，激活显存随 microbatch 数线性涨；1F1B（one-forward-one-backward）改成「做一次前向就做一次反向」，激活只与阶段数相关。这一章同时看 Megatron 的实现和 DeepSpeed pipe 的另一条路——显式命令列表。

4.1一分钟版本

PP 的核心矛盾：microbatch 越多吞吐越高，但每个 in-flight 的 microbatch 都要在每个阶段留一份激活。

  • GPipe：全部前向 → 全部反向。激活 = microbatches × stages 内激活量，microbatch 一多显存爆。
  • 1F1B：warmup 阶段先堆若干前向，之后严格一前一后交替。in-flight 数被钉在 stages − stage_id − 1，显存只跟阶段位置相关，microbatch 数随便加。
  • Interleaved（虚拟流水线）：一张卡拿多个不连续的层段（virtual model chunks），进一步把气泡砍半，代价是通信次数变多。
气泡公式 1F1B 的空闲率 ≈ (pp − 1) / (num_microbatches + pp − 1)。pp=8、microbatch=32 时约 18%；pp=8、microbatch=8 时 47%——所以 PP 必须配大 microbatch，而 microbatch×DP 又决定全局 batch，三者的耦合在 2.5 节的选型表里。

4.2用代码看｜warmup 步数从哪来

megatron/core/pipeline_parallel/schedules.py — forward_backward_pipelining_without_interleaving（摘录，注释为译注）
python# warmup 步数：越靠后的阶段 warmup 越少（最后一个阶段 0 步，直接 F1B1）
num_warmup_microbatches = p2p_communicator.total_stages - p2p_communicator.current_stage - 1
num_warmup_microbatches = min(num_warmup_microbatches, num_microbatches)

# warmup：只做前向，发激活给下一阶段
for i in range(num_warmup_microbatches):
    input_tensor = recv_forward(...)
    output_tensor = forward_step(input_tensor, model_chunk, ...)
    send_forward(output_tensor, ...)

# steady：1F1B——前向发出后立刻收反向梯度
for i in range(num_microbatches - num_warmup_microbatches):
    if forward_only:
        input_tensor, output_tensor = forward_step_with_...
    else:
        output_tensor_grad = recv_backward(...)      # 先挂上反向的接收
        input_tensor, output_tensor = forward_step(...)
        send_forward(output_tensor, ...)
        send_backward(input_tensor_grad, ...)
        recv_backward(...)

# cooldown：剩下的全是反向
for i in range(num_warmup_microbatches):
    output_tensor_grad = recv_backward(...)
    input_tensor_grad = backward_step(...)
    send_backward(input_tensor_grad, ...)
三段式结构：warmup（堆前向）→ steady（F/B 交替）→ cooldown（清反向）。代码里最值得注意的是 steady 段的收发配对顺序：recv_backward 先挂上异步接收，前向算完立刻 send_forward + send_backward + recv_backward，让相邻阶段的通信全部异步飞着。另一个细节：enable_grad_sync 只在最后一个 microbatch 打开——梯度 all-reduce 不必每个 microbatch 都做，攒到最后一次即可（配合 DDP 的 grad buffer，第 7 章展开）。

4.3Interleaved：一张卡跑多个不连续段

1F1B 的气泡仍与 pp−1 成正比。Interleaved 让每张卡持有 virtual_pipeline_model_parallel_size 个互不相邻的层段（如 8 卡 32 层，每卡拿第 0、4、8、12 层那段和第 2、6、10、14 层那段），阶段逻辑数翻倍、每段更薄，气泡近似减半：

megatron/core/pipeline_parallel/schedules.py — forward_backward_pipelining_with_interleaving（结构摘录）
python# 两个约束：模型块数必须是流水线阶段数的整数倍
assert model_parallel_size % pipeline_parallel_size == 0
# 且 num_microbatches 必须是 pp 的整数倍——否则斜纹排不齐
if num_microbatches == pipeline_parallel_size:
    chunk_and_microbatch_id = ...

# 同一时刻一张卡上多个 chunk 交替 F/B；通信对象不再只是相邻阶段
# （本卡 chunk0 的下一阶段可能在别的卡上 chunk1）→ p2p 通信对数成倍增加
for k in range(num_model_chunks):
    input_tensor, output_tensor = ...
trade-off：气泡从 (pp−1)/(m+pp−1) 降到约 (pp−1)/(2·v·m) 量级（v = virtual size），但 p2p 消息次数 ×v——小消息多了，带宽便宜延迟贵的机器（跨机网线）反而变慢。所以 interleaved 通常只在机内 TP 大、跨机 PP 小的拓扑下收益为正。这也是为什么默认配置不开。

4.4DeepSpeed pipe：把调度写成命令列表

DeepSpeed 的 pipe 引擎走了另一条路：不把 F/B 糅在循环里，而是先生成一张显式命令表，再逐条执行。用户可以自定义调度（继承 PipeSchedule 重写 steps()）：

deepspeed/runtime/pipe/schedule.py — TrainSchedule.steps()（结构摘录，注释为译注）
pythondef steps(self):
    # 与 Megatron 同样的 warmup 公式
    for step_id in range(self.total_steps()):
        cmd = self._valid_micro_batch(prev_micro_batch_id)  # …
        yield LoadMicroBatch(prev_micro_batch_id)
        yield RecvActivation()          # 非首阶段
        yield ForwardPass()
        yield SendActivation()          # 非末阶段
        yield BackwardPass()            # warmup 结束后
        yield SendGrad() / RecvGrad()   # 对应方向
    # 收尾：ReduceTiedGrads / ReduceGrads / OptimizerStep 由引擎统一追加
两种调度哲学：Megatron 把 1F1B 写死在 forward_backward_func 里（性能路径，不可换）；DeepSpeed 把它抽象成命令序列（可读、可换，引擎逐条解释执行）。DeepSpeed 还有 num_pipe_buffers = max(2, min(stages − stage_id, micro_batches))——每阶段只需这么多个缓冲区来接力。代价是抽象层开销与功能边界：DS pipe 不支持 ZeRO-2/3（engine.py 的 assert zero_optimization_stage() < ZeroStageEnum.gradients），所以真要把 PP 和 ZeRO-3 组合，得走 Megatron 主导的 MCore-DeepSpeed 路线（第 1 章 1.5 节的模式 C）。
数据对比 同样是 1F1B，Megatron 的 schedules.py 约 2500 行（含 interleaved、只前向、CP 融合等全部分支），DS 的 schedule.py 约 500 行。前者是生产主路径，后者是教学友好的参考实现——读懂后者，前者只是多了工程细节。

4.5小结 + 自研启示

维度Megatron 1F1BDeepSpeed pipe TrainSchedule
调度表达过程式循环，写死在 schedule 函数yield 命令流，可自定义
通信时机recv 先行 + async send，通信藏在 F/B 步内命令显式列出 Send/Recv
梯度同步最后一个 microbatch 才开 grad_syncReduceGrads 命令统一收尾
虚拟流水线支持（interleaved）不支持
ZeRO 兼容配合 DistributedOptimizer（ZeRO-1 等价）仅 ZeRO-0/1
自研启示 自研 PP 的最小正确路径：先实现 GPipe（保证数值对），再改成 1F1B（保证显存），warmup 公式照抄 stages − 1 − stage_id。最容易错的两点：① p2p 通信必须非阻塞且 recv 先于 send 挂起，否则相邻阶段互相等待直接死锁；② 梯度对 input_tensor 的反向要 retain_graph=False 且 activation 只保留 in-flight 那几个——测试方法是同一 batch 分别用 GPipe 和 1F1B 跑，逐 step 比对 loss 与梯度范数。
