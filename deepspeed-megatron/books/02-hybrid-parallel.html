3D 并行：五种切法怎么组合

并行有哪几种切法，各切什么对象、付什么通信代价？一组卡怎么变成 TP/PP/DP 组（rank 映射）？DeepSpeed 侧怎么接进来？组合时先算哪笔账。

2.1三堵墙与五种切法

为什么非要并行？把单卡撞到的墙数一数就明白了。放不下（显存墙）：第 6 章会算的账——混合精度下每个参数 16 字节状态，671B 模型仅模型状态就 10 TB 量级，任何单卡都装不下。算不动（算力墙）：即便放得下（如 7B 模型 + ZeRO-2 offload），单卡每秒浮点数有上限，吞吐上不去。等不起（时间墙）：就算吞吐够，一次训练动辄数周，容错和迭代速度都要求把时间维也并行掉。

三种约束对应三类切法，再叠加两种特种切法，构成五种并行：

并行切的对象每步通信通信量级卡间带宽要求
TP 张量并行单层权重矩阵每层 2 次（f/g 共轭）∝ 层数×激活大小极高 → 限单机 NVLink
SP 序列并行TP 层间激活（沿序列）与 TP 合并成 RS/AG同上（换了通信原语）极高
PP 流水线并行层段每 stage 边界 2 次（激活+梯度）∝ 边界激活大小低 → 可跨机
DP 数据并行什么都不切（复制）每步 1 次梯度规约∝ 参数量中（可被 ZeRO 压缩）
CP 上下文并行序列维注意力内部 ring 交换∝ 序列长/CP 数中高
EP 专家并行MoE 的专家all-to-all ×2∝ 派发的 token 数中高
这张表有个规律可记：切「层内权重」= TP（通信最贵，只能在 NVLink 域内）；切「层间」= PP（通信最便宜，可跨机）；切「数据」= DP（什么都不切，所以才有冗余可优化——那是 ZeRO 的事，第 6–8 章）；切「序列」= CP/SP；切「专家」= EP。记住这个对应，后面每章的切分方案都能对号入座。

2.2world_size 与并行组是怎么定义的

墙和切法都清楚了，接下来的问题更具体：真给你 64 张卡，框架怎么知道谁和谁是一个 TP 组、谁和谁是一个 DP 组？答案集中在 Megatron 的一个函数里。initialize_model_parallel() 的签名就是全书的坐标系：

megatron/core/parallel_state.py — initialize_model_parallel（摘录）
pythondef initialize_model_parallel(
    tensor_model_parallel_size: int = 1,
    pipeline_model_parallel_size: int = 1,
    virtual_pipeline_model_parallel_size: Optional[int] = None,
    context_parallel_size: int = 1,
    expert_model_parallel_size: int = 1,
    expert_tensor_parallel_size: Optional[int] = None,
    order: str = "tp-cp-ep-dp-pp",   # rank 的排列顺序！
    ...
):
这个签名值得停一停： 首先，总卡数 = 各轴之积：docstring 明确写出 world_size = TP × CP × PP × DP（EP/GTP 是叠在上面的细分轴）。配置 64 卡可以拆成 TP=4×PP=4×DP=4，也可以 TP=8×DP=8——没有唯一解，第 4 章的 bubble 公式和带宽决定取舍。 然后，order 参数决定 rank 映射：默认 "tp-cp-ep-dp-pp" 意思是相邻的 rank 先构成一个 TP 组（这样 TP 的 all-reduce 走机内 NVLink）；PP 组则由跨机器的 rank 构成。改 order 就改变「哪一维吃机内带宽」。 最后一点贯穿所有并行组：每个组都是一种「窄通信域」——TP 组内每层通信、PP 组只有 stage 边界通信、DP 组每步规约一次。把通信限制在最小集合里，这是所有并行组设计的共同动机。

签名读完了，先把它落到一张全量图上。64 卡、TP=4×PP=4×DP=4（单机 8 卡 × 8 台机器），这是最容易把「三堵墙各堵一截」的配法：TP 吃机内带宽、PP 跨机、DP 做副本。图 2.1a 是全 64 卡的布局，图 2.1b 是其中一个 TP×PP 组的放大——两张图对着读：

图 2.1a：64 卡总览（TP=4×PP=4×DP=4，单机 8 卡 × 8 台）。每个小方块是一个 rank（上排数字 = 全局 rank，下排 = TP 位次）；同色一行是一个 TP 组，虚线框一列是一个 DP 组，PP 沿机器对横向传递。order 改变时这张图的行列含义整体重排。
同一个 TP 组（相邻 rank） 同一 stage 的其它 DP 副本 下一 stage（跨机）

2.3DeepSpeed 侧的世界：它只认 DP，其余靠搭档

Megatron 把并行结构包办了。DeepSpeed 的世界观简单得多——引擎只看到「数据并行组」，模型切分交给搭档。但它有两个入口能感知并行结构：

deepspeed.initialize() 的 mpu 参数（摘录，注释为译注）
pythonmpu: Any = None,
# A model parallelism unit object that implements
# get_{model,data}_parallel_{rank,group,world_size}()
mpu 就是两库协作的插销：把 Megatron 的 mpu 模块传进来，DeepSpeed 的梯度规约就知道「我的数据并行组是哪些 rank」，不会把 TP 组里的梯度也规约了。BLOOM-176B 的训练脚本正是这样接线的。而 DeepSpeed 自己的流水线（runtime/pipe/）与 Ulysses 序列并行（runtime/sequence_parallel/）则是它自带的切分实现，适用于不带 Megatron 的场景。

2.4PP 气泡：组合前必须先算清的账

插头接好了，最后还有一笔账：两库组合时，PP 的气泡账决定你敢不敢开 PP。流水线并行用「分段接力」换低通信，代价是时间线上的气泡（bubble）。经典 1F1B 调度下，气泡占比有一个干净的下界公式：

图 2.2：1F1B 气泡示意。理想气泡率 ≈ (pp−1)/(num_microbatches + pp − 1)；pp=8、micro-batch=32 时约 18%，靠加大 micro-batch 只能稀释到一定程度——interleaved 调度（第 4 章）才是根治手段。
回到 64 卡：若换成 4D（加 CP/EP） 图 2.1a 是 3D（TP/PP/DP）。真实大模型常开 4D 甚至 5D：例如 64 卡 = TP=2 × CP=2 × PP=2 × DP=8，或 MoE 模型再叠 EP。规则不变——world_size 仍等于各轴之积，order 里排在越前面的轴，相邻 rank 越近、越吃机内带宽。CP 排在 tp 之后（"tp-cp-…"），所以 CP 组也是机内相邻；EP 组横跨 DP 维的机器（专家分散在不同机器上，all-to-all 走机间）。第 5 章讲 CP 的 zigzag 切分，第 13 章讲 EP 的 all-to-all。

这笔账直接决定组合方案：先算 PP 需要的 micro-batch 数 → 气泡率可接受时才开 PP；剩下的卡给 TP×DP。Megatron 默认建议 TP ≤ 单机卡数（NVLink 域），PP 拿跨机带宽，DP 用 ZeRO 砍显存。

2.5选型速查

这一章的信息量不小，收个尾：三堵墙各对应一类切法，加上 CP/EP 两种特种切法凑成五种并行；rank 怎么分组由 initialize_model_parallel 的 order 参数一次性定型——TP 相邻（吃机内 NVLink）、PP 跨机（吃机间带宽），改 order 就改「哪一维吃机内带宽」；DeepSpeed 只认 DP 组，靠 mpu 插头接入 Megatron 的并行结构。真要组合，先算 PP 气泡账——气泡率可接受才开 PP，剩下的卡给 TP×DP。落到选型，就是下面这张表：

你的处境第一步理由
单卡放得下，只是想快TP=2/4（机内）通信全走 NVLink，收益线性
权重放不下单卡，但激活放得下TP + ZeRO-1TP 切权重，ZeRO 砍副本冗余
层数多、跨机带宽差PP（跨机段）+ TP（机内）PP 通信量小，天然适配跨机
超长序列（>32K）CP=2/4 + TP注意力激活按序列切，ring 交换 K/V
MoE 大模型EP + TP（非专家层）专家按卡摊，路由通信交给 all-to-all
几百亿以上、任意条件3D + ZeRO-1 + 重算三条轴各管一维，缺一不可
自研启示 五种并行的实现难度差距极大：DP 一周、TP 一月、PP 一季、CP/EP 更久。且它们的通信模式互不相同——先定「每种并行用哪个进程组、在哪插通信」的接口约定（Megatron 的 parallel_state 就是这个约定的参考实现），再写任何切分代码。下一章进入 TP 的分块数学。
