模型与数据：张量怎么在 3D 并行下流动

前两章讲了怎么切（TP/PP/DP），这一章看切完之后模型代码长什么样、数据怎么喂进去。重点三件事：模型代码如何对并行透明、混合精度如何包裹模型（Float16Module）、数据管线如何让 TP/PP/CP 组内拿同一批样本而 DP 组间不重叠、序列维如何切给 CP。

5.1TransformerLayer 的组装：并行透明的关键

模型代码完全不写 torch.distributed——切分发生在模块的构造函数里。看一个 transformer 层的拼装：

megatron/core/transformer/transformer_layer.py — 组装链（结构摘录，译注）
pythonclass TransformerLayer(BaseTransformerLayer):
    def __init__(self, config, submodules, ...):
        self.input_layernorm = build_module(
            submodules.input_layernorm,
            config.hidden_size,
            ...,
        )                                    # TP+SP 感知 LN
        self.self_attention = build_module(
            submodules.self_attention, config, ...
            attention_type=AttentionType.self_attention,
        )
        self.pre_mlp_layernorm = build_module(...)
        self.mlp = build_module(
            submodules.mlp, config, submodules=MLPSubmodules(
                linear_fc1=TELayerNormColumnParallelLinear,   # LN+列并行融合
                linear_fc2=TERowParallelLinear,               # 行并行
            ),
        )
        # TP 切分写进算子的构造参数——模型代码零切分逻辑
读懂组装链：「切分写进构造参数」是 Megatron 模型代码干净的根本原因：MLP 的 fc1 用 TELayerNormColumnParallelLinear（LN+列并行融合算子），fc2 用 TERowParallelLinear——换 TP=1 时只需换算子类（非 TE 路径对应 ColumnParallelLinear/RowParallelLinear，并行度 1 时自动退化为普通 Linear）。层内还可以包 checkpointed_forward（配置 --recompute-granularity full 时），在第 10 章展开。

GPTModel.forward：3D 并行下的输入形态

megatron/core/models/gpt/gpt_model.py — GPTModel.forward 签名（摘录）
pythondef forward(
    self,
    input_ids: torch.Tensor,
    position_ids: torch.Tensor,
    attention_mask: torch.Tensor,
    decoder_input: torch.Tensor = None,       # PP 非首阶段：直接吃上一阶段的激活
    inference_context: InferenceContext = None,
    packed_seq_params: PackedSeqParams = None,  # 变长序列打包（THD 格式）
    ...,
):
三个特殊参数：① decoder_input——PP 非首阶段不需要 embedding 输出，直接以「上一阶段传来的激活」为输入（首阶段则先过 embedding）；② packed_seq_params——变长 packing 后的段边界信息，配合 FA2 的 varlen 路径；③ inference_context——推理时携带 KV cache 状态。训练主路径里它们多半为 None，但签名本身就是 3D 并行下的输入全景。

5.2混合精度包裹：Float16Module

megatron/core/transformer/module.py — Float16Module（摘录，译注）
pythonclass Float16Module(torch.nn.Module):
    """Wrap the module with fp16/bf16 conversion in forward pass"""

    def forward(self, input):
        if isinstance(input, (tuple, list)):
            return [self.forward(i) for i in input]
        if torch.is_autocast_enabled():     # autocast 已接管 → 不重复 cast
            return input
        return input.to(self.config.params_dtype)  # 强制转到 fp16/bf16
位置与作用：Float16Module 是模型外层的一层壳：pretrain() 里 setup_model_and_optimizer 时，fp16/bf16 配置下模型被包住，forward 时把输入 cast 到半精度。权重在模块内部本身就是 params_dtype 存储，而真正的 fp32 master 权重属于 optimizer（第 7 章）——Float16Module 只管前向 cast，不管缩放。loss scaling 也属于 optimizer（scaler），这条边界在自研时很容易划错。

5.3数据管线：组内同批、DP 间不重叠

3D 并行下数据加载有两个特殊要求：① 同一 TP/PP/CP 组内各卡必须拿到同一批样本（它们在算同一个模型的同一段）；② 不同 DP 副本拿到不重叠的样本。Megatron 用 rank 算偏移：

megatron/training/data_samplers.py — MegatronPretrainingSampler.__iter__（摘录，译注）
pythondef __iter__(self):
    batch = []
    # start/end 由 consumed_samples + 全局 batch 推出；组内各卡算出同一个区间
    for idx in range(start, end, self.data_parallel_rank_delta):
        batch.append(idx)
        if len(batch) == self.micro_batch_times_data_parallel_size:
            yield batch[batch_start:batch_end]  # 每张 DP 卡切走自己的 microbatch
            batch = []
批大小公式：global batch = micro_batch × DP × grad_accum。TP/PP/CP 不影响全局 batch——它们切的是模型不是数据。采样器一次产出的区间覆盖整个 DP 组（micro_batch_times_data_parallel_size），再按 DP rank 切走各自那份。这行公式是新手最常搞错的地方：把 micro_batch × TP 误当成全局 batch，然后困惑「loss 曲线和论文对不上」。

5.4CP 切序列：get_batch_on_this_cp_rank

第 2 章 2.4 节讲过 PP 气泡；CP 的 zigzag 原理（因果注意力载荷是三角形，连续切会让首卡闲、尾卡忙）。这里看数据侧实现：

读代码要抓的两点：① 切的是 batch 里每一个 key（tokens/position_ids/labels 必须同步切，错一个 key 就是 label 对不上的静默错误）；② zigzag 的实现是「第 i 段 + 第 cp_size·2−1−i 段」的配对，保证每卡两侧合计工作量相等。per-document 变体在文档数量多且长短不均时更优（避免跨文档 padding），hybrid CP 则服务于不同注意力后端的通信形态差异。哪个变体生效由配置选择，数据侧只负责按选定的方式切。

5.5小结 + 自研启示

部件切分方式关键机制
TransformerLayerTP 切分写进构造参数build_module + submodules
GPTModel.forwardPP 边界体现在 decoder_input 参数首阶段过 embedding，其余吃激活
Float16Module只做前向 cast，不碰缩放fp32 master 属于 optimizer
数据采样组内同 batch、DP 间不重叠consumed_samples 算偏移
CP序列维 zigzagget_batch_on_this_cp_rank
自研启示 「切分写进构造参数」是自研可复用的最强模式：换并行度 = 换算子类，模型代码不动。测试基线同样简单：同一配置下 TP=1 与 TP=2 的 loss 曲线必须重合（第 3 章 3.6 节初始化一致性的坑）。数据侧先写死 global = micro_batch × DP × grad_accum 这条公式再写代码——CP 加入后它变成 micro_batch × DP × CP × grad_accum（CP 也是一种数据切分），但 TP/PP 永远不进这条公式。
