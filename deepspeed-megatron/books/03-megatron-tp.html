张量并行：一层权重怎么切给多张卡

TP 是 Megatron 的起点（2019 年那篇论文的核心贡献）。核心结论只有一句话：attention/MLP 的两个矩阵乘，一个按列切、一个按行切，就能让通信从每层 4 次降到 2 次。这一章从代码看这两个算子怎么写、通信怎么与计算重叠。

3.1一分钟版本

线性层 Y = XA，把 A 切成两半有两种切法，通信代价完全不同：

  • 列并行（A = [A₁, A₂] 按列切）：每个卡拿自己的 Aᵢ 算 Yᵢ = XAᵢ——不需要通信就能算，只是输出比完整 Y 窄。把结果拼起来（all-gather）或留给下一个行并行层（免通信）即可。
  • 行并行（A 按行切，X 也按列切）：每个卡算部分和，必须 all-reduce 才能得到完整 Y。

transformer 的 FFN 是两个连续矩阵乘：把第一个（h→4h）按列切、第二个（4h→h）按行切，则两层的输出天然就是「切开的」——中间不需要任何通信，只在最后做一次 all-reduce。每个 transformer 层通信 2 次，而不是朴素做法的 4 次，这是 Megatron 论文的核心观察。注意力按头切同理：多头天然可分。

命名 Megatron 把这两次通信抽象为共轭算子 f 与 g：f = 前向恒等/反向 all-reduce；g = 前向 all-reduce/反向恒等。所有 TP 算子的前后向通信都挂在这对共轭算子上。

3.2用代码看｜Column 与 Row 并行线性层

megatron/core/tensor_parallel/layers.py — 两个基石算子（docstring 摘录，译注）
pythonclass ColumnParallelLinear(torch.nn.Module):
    """Linear layer with column parallelism.

    The linear layer is defined as Y = XA + b. A is parallelized along
    its second dimension as A = [A_1, ..., A_p]."""
    # gather_output: 若 True 则 all-gather 出完整 Y；FFN 中间层恒为 False（留给下一层）

class RowParallelLinear(torch.nn.Module):
    """Linear layer with row parallelism.

    The linear layer is defined as Y = XA + b. A is parallelized along
    its first dimension and X along its second dimension.
    A = transpose([A_1 .. A_p])  X = [X_1, ..., X_p]"""
    # input_is_parallel: 输入已是各卡分片（接在列并行后）→ 免切分直接算
读懂这对算子：Column 并行切 A 的列 → 每卡输出是 Y 的一段特征维；Row 并行切 A 的行、同时要求 X 也按特征切 → 每卡输出是完整 Y 的部分和，需要 all-reduce。两者相接处不需要通信（列并行的输出本来就是行并行想要的输入分片）——这就是「MLP 两次 GEMM 只通信一次」的实现基础。配置里 gather_output=False + input_is_parallel=True 就是在声明「保持分片不落地」。
图 3.1：FFN 的列-行切分。前向每层只有一次 all-reduce（g）；反向对应一次（f）。Sequence parallel（3.5 节）把这两次合并进 reduce-scatter/all-gather，通信量再减半。

3.3用代码看｜通信是 autograd 的一部分

TP 最精妙的设计：通信写在 autograd.Function 里，前向反向自动取共轭操作，用户层完全无感：

megatron/core/tensor_parallel/mappings.py — f/g 共轭算子（摘录，注释为译注）
pythonclass _CopyToModelParallelRegion(torch.autograd.Function):
    """f 算子：前向恒等（复制），反向 all-reduce"""
    @staticmethod
    def forward(ctx, input_, group):
        return input_
    @staticmethod
    def backward(ctx, grad_output):
        return _reduce(grad_output), None      # 反向才通信

class _ReduceFromModelParallelRegion(torch.autograd.Function):
    """g 算子：前向 all-reduce，反向恒等"""
    @staticmethod
    def forward(ctx, input_, group):
        return _reduce(input_, group)
    @staticmethod
    def backward(ctx, grad_output):
        return grad_output, None              # 反向直接回传
为什么这样设计：把通信藏进 autograd，模型代码 ColumnParallelLinear(...) 用起来跟普通 Linear 一样——切分对模型作者透明。代价是「通信发生的确切时机」被 autograd 间接化，所以 Megatron 提供 forward_backward_func（第 4 章）在更外层统一编排，并且靠 CUDA_DEVICE_MAX_CONNECTIONS=1 保证通信先于计算的 stream 顺序（下一节）。

逐行读：每个卡只存词表的一段（vocab_start/end_index 由 rank 算出）。所有卡对所有 token 都查表——查不到的填 0，然后一次 all-reduce。看起来浪费，但换来了「无需路由、无需动态通信」的静态实现。all-reduce 的量 = embedding 输出大小，与词表切法无关。输出层 output_layer（词表投影）同构：logits 按词表分段，cross-entropy 有对应的并行实现（core/tensor_parallel/cross_entropy.py）避免把完整 logits all-gather 出来。

3.4通信与计算的重叠：一行 CUDA 环境变量

LinearWithGradAccumulationAndAsyncCommunication 的 backward 是 TP 性能的心脏——dgrad 的 all-reduce 与 wgrad 的 GEMM 重叠执行：

megatron/core/tensor_parallel/layers.py — backward（摘录，注释为译注）
pythonif ctx.allreduce_dgrad:
    # 异步 all-reduce：不等结果，直接排下一个计算
    handle = torch.distributed.all_reduce(grad_input, group=tp_group, async_op=True)
    # 这里依赖 CUDA_DEVICE_MAX_CONNECTIONS=1 保证 all-reduce 排在 wgrad 之前

if ctx.gradient_accumulation_fusion:
    # wgrad 直接累加进 fp32 main_grad 缓冲（fused kernel），不产生 .grad
    fused_weight_gradient_mlp_cuda.wgrad_gemm_accum_fp32(total_input, grad_output, weight.main_grad)
两行代码两篇论文： ① allreduce_dgrad：dgrad all-reduce 发出去后不等待，继续算 wgrad——通信躲在计算后面。这要求 NCCL 的通信 stream 与计算 stream 正确排队，Megatron 文档明确要求启动时设 CUDA_DEVICE_MAX_CONNECTIONS=1，否则 kernel 调度乱序、结果错误。这是「一个环境变量决定正确性」的著名坑。 ② gradient_accumulation_fusion：wgrad 不写到 param.grad，而是融合进参数旁边那块 fp32 的 main_grad 缓冲——省一次梯度存储，也避免了 fp16 累加误差。main_grad 机制在第 7 章还会出现（Megatron DDP 与 ZeRO 的共同底座）。

3.5Sequence Parallel：把 TP 的激活也切了

纯 TP 下，LayerNorm/Dropout 的激活每个卡仍是完整序列的副本。序列并行（SP）把它们沿序列维切开，代价是 TP 通信的形态变化：

图 3.2：SP 的本质——通信原语换形。all-reduce = reduce-scatter + all-gather，SP 把这两步拆到层的两端，顺带把非 TP 区的激活也切了。等于「同样的通信，白赚一半激活显存」，所以现代 Megatron 配置几乎总是 TP+SP 成对开启。

3.6小结 + 自研启示

算子切法前向通信反向通信
ColumnParallelLinear权重按列切无（gather_output=False 时）all-reduce dgrad（可重叠）
RowParallelLinear权重按行切all-reduce 输出（或 reduce-scatter）无（输入已是分片）
VocabParallelEmbedding词表分段all-reduce（mask 补零）同结构
Pair（FC1→FC2）列+行配对中间点零通信合并为 RS/AG
自研启示 TP 的可复用资产是三样：① f/g 共轭算子（通信进 autograd）；② 列-行配对消除中间通信；③ 初始化一致性（同层权重各卡必须按完整矩阵初始化，_initialize_affine_weight_cpu 先在 CPU 造全量再切）。第三点最容易踩坑：直接在分片上随机初始化，各卡的有效权重与单卡不等价，模型训不出来还查不出原因。
