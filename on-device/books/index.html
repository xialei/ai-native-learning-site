学习路径

STEP 1

整体架构

on-device 推理的问题定义：显存/内存墙、带宽墙。llama.cpp 的分层（ggml 后端 / llama_model / llama_context / tools）与 FreeToken 的分层（server / scheduler / engine / moe / kernel）。
STEP 2

GGUF 与模型加载

GGUF 元数据与张量布局、量化格式全表（Q4_0 → K-quants → IQ → MXFP4）、mmap 直读、n_gpu_layers 如何按 free memory 切层。
STEP 3

decode 循环

llama_context::decode 全流程：ubatch（n_batch 逻辑 / n_ubatch 物理）、memory 状态机（FAILED_PREPARE 重试）、logits 提取与输出重排。
STEP 4

KV cache 家族

kv_unified vs 分序列、iswa 双缓存、cells 槽位管理、find_slot、context shift 与 K-shift 图、defrag 为何被移除。
STEP 5

计算图与调度

ggml_cgraph 构图、can_reuse 图复用、galloc 原地复用、backend_sched 三段 reserve 与 split 划分、flash attention 接入点。
STEP 6

多设备与显存适配

后端注册表与动态加载、split-mode layer/tensor、fit-params 无卡模拟测内存、统一 llama 二进制的子命令表。
STEP 7

采样链

llama_sampler 链式架构、默认链组装顺序（penalties → dry → top_k → … → dist）、grammar 约束、mirostat 与 adaptive。
STEP 8

投机解码

草稿-验证框架、draft-simple/eagle3/mtp/dflash/dspark 五种草稿模型、ngram 系列免草稿模型、词表差异限制。
STEP 9

服务入口

llama-server：slot/task 模型、prompt cache 前缀复用、多 slot 状态拷贝、server_tokens 多模态占位、统一二进制的 serve 子命令。
STEP 10

FreeToken：边侧 MoE 引擎

为什么 MoE 在消费级 GPU 上是另一道题：290B+ 参数、专家激活稀疏性。引擎分层、进程模型（supervisor/tokenizer/scheduler）、overlap 调度循环。
STEP 11

MoE 专家缓存

OffloadMoeCache：flat id 槽池、8 种量化 bank schema、全局 LRU、prefill 全层双缓冲流式、hit-D2D 分流、FTW 快速权重格式。
STEP 12

CPU/GPU 带宽协同

带宽自适应 q* 策略：fetch 比例 = pcie/(pcie+cpu-overlap)。CPU executor 的 memop 握手、pinned host bank、pin-after-fill、CUDA graph 兼容。
ROADMAP

双引擎对照 · 自研路线

llama.cpp 与 FreeToken 在每个子系统上的对照表；从零写一个 on-device 引擎的六个里程碑。

全书词表

各章反复出现的术语收拢在这里，按学习路径顺序排列。「详见」指向讲得最透的章节；读正文遇到陌生词，先回来查这一张表。

术语含义详见
两堵墙（容量墙/带宽墙）on-device 与数据中心的分界：显存装不下大模型是容量墙，decode 每生成一个 token 都要把全部权重读一遍是带宽墙01
GGUFllama.cpp 的单文件模型容器：键值元数据 + tokenizer + 张量表，配 mmap 直读（llama.cpp 侧）02
量化用更低的比特存权重/KV 换显存：llama.cpp 从 Q4_0 到 IQ 一路排下来，FreeToken 的 bank 另配 8 种量化格式02
mmap把权重文件页直接映射进地址空间的加载方式：CPU 层张量指针就是映射地址本身，GPU 层从映射地址发起拷贝（llama.cpp 侧）02
n_gpu_layers「第几层之后搬进 GPU」的开关；多卡时默认按每块设备的 free memory 占比自动分（llama.cpp 侧）02
FTWFreeToken 自研的权重格式：张量 4096 对齐、单文件装下整个模型，专为 O_DIRECT 整块读盘设计（FreeToken 侧）11
decode 循环每步只进一个新 token 的生成主循环，带宽密集；与一次算入整个 prompt 的 prefill 相对——FreeToken 用 chunked prefill 把长 prompt 切块，不让它阻塞 decode03
ubatch真正一次送进计算图的 micro batch：n_batch 是逻辑上限，n_ubatch 是物理上限（llama.cpp 侧）03
KV cache（键值缓存）注意力「回看历史」的凭据：每个 token 每层存 K、V 两组向量，随对话变长变大，是权重之外显存的大头04
cellllama.cpp KV 的「格子本」：每格记占用状态与所属 seq_id，找槽入口是 find_slot（llama.cpp 侧）04
context shift生成逼近 n_ctx 时保住开头、丢掉中段，再把后面的位置号整体前移——无限生成的诀窍（llama.cpp 侧）04
iswa滑窗模型的双缓存：非滑窗层进 base cache，滑窗层进 swa cache，各按各的规律增长（llama.cpp 侧）04
计算图（ggml_cgraph）llama.cpp 每次推理现建的张量 DAG，decode 第二步起整图复用；backend_sched 负责把它切给多个后端（llama.cpp 侧）05
CUDA GraphFreeToken 把 decode 前向整段录制成图，运行时一次 replay 消掉上千次 kernel launch 的 CPU 开销（FreeToken 侧）05
split-modellama.cpp 多卡三选一：不切 / 按层切（layer）/ 按张量切（tensor，旧 row 模式已弃用）（llama.cpp 侧）06
采样链一串 sampler 依次加工候选数组：penalties → dry → top_k → … → dist，便宜的过滤器放前面（llama.cpp 侧）07
投机解码（speculative）草稿模型猜 k 个 token、target 模型一次验证：用小模型的算力换大模型的带宽；FreeToken 侧没有对应实现08
slotllama-server 并发的基本单位：一条请求占一个 slot，选槽按「id 直选 → LCP 相似度 → LRU」兜底（llama.cpp 侧）09
前缀复用（cache_reuse）新 prompt 与 slot 现有 tokens 求公共前缀，公共长度记作 n_past，KV 从前缀末端接着算（llama.cpp 侧）09
MoE（混合专家）每 token 只激活少数专家的架构：总参数巨大、激活稀疏，是 FreeToken 整本书的靶子10
overlap_loopFreeToken 调度主循环：调度与执行双流重叠，prefill 和 decode 谁都不闲着（FreeToken 侧）10
offload放不进显存的专家（或层）搬到 CPU 内存/SSD，算到谁再把谁拉过来——两个引擎各有一种解法11
OffloadMoeCacheFreeToken 的专家缓存：host 侧 pinned 内存 bank 作源，GPU 侧槽池作缓存，两本映射账记去向（FreeToken 侧）11
bank专家权重的存储单元：host 侧是 pinned（锁页）内存，GPU 侧是显存槽池，每个 bank 配一种量化 schema（FreeToken 侧）11
q*（fetch 比例）hybrid decode 的切分比例：缺失专家多少走 PCIe 拉上 GPU、多少留在 CPU 算，按两边实测带宽比推出（FreeToken 侧）12
memop 握手CPU 执行器的 GPU-CPU 门铃：标志位轮询替代回调派发，每层省 30-50us 派发延迟（FreeToken 侧）12
