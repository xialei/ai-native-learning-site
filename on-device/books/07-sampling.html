采样：logits 到 token 的最后一公里

llama.cpp 把采样做成「责任链」：每个 sampler 看一遍候选数组，或截断、或改概率、或直接选中。链的组装顺序不是随意的——便宜的过滤器放在前面，浪费的工作更少。

7.1责任链：一个数组走到底

llama.cpp 采样的核心数据结构只有一个：llama_token_data_array（id、logit、p 三元组数组）。每个 sampler 实现 apply(cur_p)，按序施加。链的组装在 common/sampling.cpp：

common/sampling.cpp:340-400 — 链的组装（摘录，注释为译注）
c++if (params.mirostat == 0) {

                break;

读懂这段： 三个容易忽略的点。① 链头还有 logit_bias：合并用户偏置与模型 suppress tokens（置 -INFINITY），在 mirostat==0 分支之前 push；② dist 是链尾默认值——过滤链只改数组不选 token，总得有人掷骰子；③ mirostat 分支直接替换整条链：mirostat v1/v2 各自与 temp 组成两件套，不走过滤链。

读懂这段： ① backend sampler：新版把部分采样搬进 GPU 计算图（llama-context.cpp:253 注释「Initialize backend samplers here so they are part of the sampling graph」）——链在 CPU 走完之前 GPU 可能已出 token，grammar 相关逻辑被完全跳过；② grammar 的默认模式是「先采样后校验」：链选出 token，grammar 只说行/不行，不行就重置 logits 重新走链；③ reasoning budget（控制思考长度）永远最先施加——它管「思考块抑制」，是逻辑层不是分布层。

7.3三个新 sampler 的算法

近年加入的几个 sampler 各有巧思，值得单独看一眼。

top_n_sigma（src/llama-sampler.cpp:3237）：按统计截断——

src/llama-sampler.cpp — top_n_sigma（摘录，注释为译注）
c++if (ctx->n <= 0.0f || cur_p->size <= 1) { return; }

// 找 max logit 与均值（跳过 -INFINITY）
float max = cur_p->data[0].logit;
...
float mean = valid_count > 0 ? logits_sum/valid_count : 0;
// 算标准差，只保留 [max - n*sigma, +inf) 的候选

mirostat v2（src/llama-sampler.cpp:2573）：自适应截断，目标「把每次选择的意外度钉在 tau」：

src/llama-sampler.cpp — mirostat v2（摘录，注释为译注）
c++llama_sampler_softmax_impl(cur_p, true);

// 意外度 = -log2(p)：大于 mu 的候选全部截掉
cur_p->size = std::distance(cur_p->data,
    std::find_if(cur_p->data, cur_p->data + cur_p->size,
        [&](const llama_token_data & candidate) {
            return -log2f(candidate.p) > ctx->mu;
        }));

if (cur_p->size == 0) { cur_p->size = 1; }   // 至少留一个
...
const int idx = llama_sample_dist(cur_p, ctx->rng);
cur_p->selected = idx;

// 观察意外度与目标 tau 求差，按学习率 eta 更新 mu
float observed_surprise = -log2f(cur_p->data[idx].p);
float e = observed_surprise - ctx->tau;
ctx->mu = ctx->mu - ctx->eta * e;
读懂这段： mirostat v2 就是一个一维控制器：mu 是「当前容忍的意外度上限」，实际意外度高于目标就调低 mu（变保守）、低于就调高（变奔放）。对比固定 top_p 的问题：不同位置的概率分布尖锐程度天差地别，固定比例截断时而过严时而过松——mirostat 用反馈回路替代静态阈值。

DRY（Don't Repeat Yourself，src/llama-sampler.cpp:3317 起）：针对逐字重复——最近输出里出现过的序列若正被延续（重复长度超过 allowed_length），按指数衰减惩罚其下一个 token。与 penalties 的区别：penalties 惩罚 token 出现次数（不管上下文），DRY 惩罚「正在形成重复序列」——所以它需要 sequence breakers（换行、章节号等「合理重复」的分隔符）。

adaptive-p（src/llama-sampler.cpp:3727 起）：比 mirostat 更新的思路——按目标 p 值直接挑「累计概率刚好达到目标」的候选集，无需训练地把输出分布的熵稳定在目标附近。

7.4对照：FreeToken 的批量采样

llama.cpp 的采样是 CPU 上对整个词表的标量循环；FreeToken 把它做成一个 GPU kernel（python/freetoken/engine/sample.py:25-51）：

python/freetoken/engine/sample.py:25-51 — sample_impl（摘录，注释为译注）
pythondef sample_impl(logits, temperatures, top_k, top_p) -> torch.Tensor:
    # flashinfer 装了用 flashinfer，否则自研 triton kernel
    if is_flashinfer_installed():
        import flashinfer.sampling as sampling
    else:
        import freetoken.kernel.triton.sampling as sampling

    probs = sampling.softmax(logits, temperatures, enable_pdl=is_sm90_supported())
    if top_k is None and top_p is None:
        return sampling.sampling_from_probs(probs)
    if top_p is None:
        return sampling.top_k_sampling_from_probs(probs, top_k)
    if top_k is None:
        return sampling.top_p_sampling_from_probs(probs, top_p)
    return sampling.top_k_top_p_sampling_from_probs(probs, top_k, top_p)

上层接口把「每个请求一份采样配置」压成批量张量：

python/freetoken/engine/sample.py:59-86 — Sampler.prepare（摘录，注释为译注）
pythondef prepare(self, batch: Batch) -> BatchSamplingArgs:
    params = [r.sampling_params for r in batch.reqs]
    is_greedy = [p.is_greedy for p in params]
    if all(is_greedy):
        return BatchSamplingArgs(temperatures=None)  # 全 greedy → argmax 特例

    MIN_P = MIN_T = 1e-6
    # greedy 行不靠低温逼近 argmax，由 sample() 里显式选定；
    # 这里给它们填中性参数（温度 1.0、无截断）
    ts = [1.0 if g else max(p.temperature, MIN_T) for p, g in zip(params, is_greedy)]
    top_ks = [p.top_k if not g and p.top_k >= 1 else self.vocab_size
              for p, g in zip(params, is_greedy)]
    top_ps = [1.0 if g else min(max(p.top_p, MIN_P), 1.0)
              for p, g in zip(params, is_greedy)]
    ...
    greedy_mask = make_device_tensor(is_greedy, torch.bool, self.device) if any(is_greedy) else None
    return BatchSamplingArgs(temperatures, top_k=top_k, top_p=top_p, greedy_mask=greedy_mask)

sample 侧对混合批的处理——概率采样照跑，greedy 行最后用 argmax 覆写：

python/freetoken/engine/sample.py:88-99 — Sampler.sample（摘录，注释为译注）
pythondef sample(self, logits, args) -> torch.Tensor:
    if args.temperatures is None:  # 全 greedy：argmax 短路
        return torch.argmax(logits, dim=-1)
    tokens = sample_impl(logits.float(), args.temperatures, args.top_k, args.top_p)
    if args.greedy_mask is not None:
        # 混合批对全部行跑概率采样，但 greedy 行必须走 argmax 的确定性并列裁决
        greedy_tokens = torch.argmax(logits, dim=-1).to(tokens.dtype)
        tokens = torch.where(args.greedy_mask, greedy_tokens, tokens)
    return tokens
对照读： ① 全 greedy 特例：temperatures is None → 直接 argmax，连 softmax 都省；② 混合批的 greedy 行：旧版把 greedy 行塞成「低温 + 数值地板」去近似 argmax，但低温采样对并列最高分 token 的选择是随机的，argmax 是确定性的——同一个 prompt 前缀两次跑出不同续写。#471（2026-09）改成概率采样照跑、greedy 行最后用 argmax 覆写（torch.where 一次向量化完成），另把 is_greedy 的定义收窄（去掉 top_p == 1.0 条件——top_k=1 时分布只含一个 token，top_p 无所谓）；③ 条件上传：没有任何请求用 top_k 时这个张量根本不上传——batch 里 4 个请求全默认参数时 GPU 采样只剩 softmax + multinomial。llama.cpp 的可组合责任链 vs FreeToken 的固定 kernel 菜单：前者灵活（grammar/mirostat/DRY 随意组合），后者快（一个 kernel 一件事）且没有 CPU↔GPU 往返——但 grammar 约束在 GPU 采样下无从谈起，FreeToken 的 grammar 支持在 API 层做（第 9 章对照）。

7.5小结

  • 责任链：过滤链改数组，dist/adaptive-p/mirostat 选 token；链序 = 加工顺序。
  • 后端 sampler 让 GPU 图直接出 token；grammar 与它互斥，走 CPU 链时用「采样后校验 + 重采样」。
  • mirostat v2 = 意外度反馈控制器；DRY 惩罚「正在形成的重复」；top_n_sigma 按统计截断。
  • FreeToken：greedy argmax 特例（混合批用 greedy_mask 覆写）+ flashinfer/triton kernel + per-request 参数压成批量张量。
