目标读者：想理解 SGLang 内部、并最终写出自己推理引擎的工程师。

图 0：SGLang 的高层数据流。HTTP 进程、Scheduler 子进程、Detokenizer 子进程通过 ZMQ 相连；调度与 KV 管理（RadixCache + 分页内存池）都在 Scheduler 里。

学习路径

STEP 1

整体架构与进程模型

SRT 的四个进程：HTTP 服务、TokenizerManager、Scheduler（每 TP rank 一个）、DetokenizerManager，以及连接它们的 ZMQ 通道。
STEP 2

请求全生命周期

从 /generate 到流式输出的完整链路：分词 → 入队 → 调度 → 前向 → 采样 → 反分词；含重叠调度（CPU 调度与 GPU 前向并行）的两套事件循环。
STEP 3

RadixCache 前缀缓存

SGLang 的招牌：用基数树管理 KV 前缀。match_prefix / insert / evict / 锁引用，页对齐与命名空间隔离，多轮对话为什么快。
STEP 4

调度器与调度策略

PrefillAdder 的三本预算账（总 token / chunk / 输入 token）、cache-aware 排序策略、chunked prefill、retract 抢占回收。
STEP 5

内存池与显存预算

ReqToTokenPool、TokenToKVPool（MHA/MLA）、分页分配器；mem_fraction_static 如何通过启动 profiling 定出 KV 池大小，alloc_extend 的向量化三段式。
STEP 6

ModelRunner 与 CUDA Graph

ForwardBatch 如何从 ScheduleBatch 派生；forward 的三级路径：decode graph 回放 → prefill 分段图 → eager 回退；capture 与 replay。
STEP 7

注意力后端

注册表机制、MHA 与 MLA 两条路线、AttentionBackend 的三个初始化钩子契约（eager / out-of-graph / in-graph），flashinfer 与 fa3 例解。
STEP 8

采样与结构化输出

Sampler 的贪心/概率两条路径、top-k / top-p / min-p、logit_bias 与禁止 token；grammar 约束生成（xgrammar 等）与 function call 解析。
STEP 9

服务入口

http_server 的 ~40 条路由、/generate 的 SSE 流式协议、OpenAI 兼容层、离线 Engine 的进程编排；ServerArgs 与 runtime_context 配置体系。
STEP 10

分布式推理

TP / PP / DP / EP 四个维度的正交组合；DataParallelController 的四种负载均衡；dp_attention 的 MLP 同步；自定义 allreduce。
STEP 11

HiCache 分层缓存

KV cache 出了 GPU 之后放哪：L1 显存 / L2 主机内存 / L3 存储后端（file、mooncake、hf3fs…），HiRadixTree、预取与回写。
STEP 12

PD 分离部署

Prefill 与 Decode 拆成独立实例：bootstrap 房间握手、KV 传输（Mooncake / NIXL）、两套专用事件循环与三个队列。
STEP 13

投机解码

EAGLE-2/3 的草稿-验证结构、MTP 权重复用、NGRAM 提示内 n-gram 草稿；草稿 worker 如何挂在 overlap 调度上（spec v2）。
说明 本站基于 SGLang 主仓库（sgl-project/sglang）的 SRT（SGLang Runtime）编写，所有代码片段从当前仓库摘录并标注了真实文件路径（python/sglang/srt/...）。 代码对应 gateway-v0.3.1-9358-gf618022b73（git describe --tags，HEAD f618022b73）。 仓库持续演进，若某处路径/函数名对不上，以仓库最新代码为准 —— 那本身就是最好的学习材料。
与 vLLM 对照 如果读过本站《深入浅出vLLM》：两者解决同一问题（连续批处理 + 分页 KV + 前缀缓存），但切法不同。SGLang 的调度与 KV 管理集中在 Scheduler 单进程内（vLLM 是 EngineCore + KVCacheManager），前缀缓存用的是基数树（vLLM 是哈希块表），进程间用 ZMQ ipc 通道（vLLM v1 用 ZMQ tcp）。对照着读能更快看清「哪些设计是本质的、哪些是工程取舍」。
