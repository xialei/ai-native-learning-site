采样：logits 如何变成 token

模型前向的终点是一个 vocab 大小的 logits 向量,但它还不是答案。采样层负责把它「翻译」成一个（或多个）具体的 token id，再交给 detokenizer 变成文本。这一章我们把 logits → token → 文本的整条链路拆开。

6.1为什么需要采样

Transformer 输出层（LM Head）给每个位置吐出一个形状为 [vocab_size] 的向量，叫 logits。它只是「分数」：分数越高的 token 越像合理的下一个词，但它本身不是 token。要拿到一个可读的 token id，必须经过采样。

  • 贪心（greedy）：直接取 logits 最大的下标，即 argmax。确定性高，但容易重复、呆板。
  • 随机（random）：先把 logits 转成概率分布，再按概率随机抽。温度越高分布越平、越随机。

在 vLLM 里，这两种行为由 temperature 决定：temperature=0（严格来说 < 1e-5）走贪心，否则走随机。这正是下一节看到的字段与采样代码的分水岭。

图 6.1：采样即「把 logits 变成 token id」。贪心可跳过 softmax，随机才需要完整概率分布。

6.2SamplingParams：请求怎么描述「我要怎么采样」

每个请求都要带上一组采样参数。vLLM 用 vllm/sampling_params.py 里的 SamplingParams 描述。下面只摘和我们本章相关的字段（原文件字段顺序如此）：

vllm/sampling_params.py — SamplingParams（字段摘录，含默认值与官方注释）
pythontemperature: float = 1.0
# 控制随机性。低值更确定，零值即贪心采样。
top_p: float = 1.0
# 累积概率截断：只考虑累积概率到 top_p 的最优 token。=1 表示考虑全部。
top_k: int = 0
# 只考虑概率最高的 top_k 个 token。0（或 -1）表示全部。
max_tokens: int | None = 16
# 每个输出序列最多生成的 token 数。
stop: str | list[str] | None = None
# 生成到这些字符串时停止。返回内容不含 stop 串。
stop_token_ids: list[int] | None = None
# 生成到这些 token id 时停止。
ignore_eos: bool = False
# 是否忽略 EOS 继续生成。
n: int = 1
# 为同一个 prompt 返回几个输出（即旧版 best_of 的继承者）。
读懂默认值：默认 temperature=1.0、top_p=1.0、top_k=0 表示「全开」——不截断、按原始分布随机。而一旦你设置 temperature=0（贪心），SamplingParams.__post_init__ 会把 top_p、top_k、min_p 一并重置为「禁用」，并校验必须用贪心。

值得一提：V0 时代的 best_of 在 V1 里被语义拆开了。n 对应「一个 prompt 出几条独立输出」，而真正的束搜索则是一个单独的 BeamSearchParams（见 6.6），字段是 beam_width、max_tokens、length_penalty、temperature=0.0。

6.3logits 后处理链：顺序很重要

vLLM 的 Sampler（vllm/v1/sample/sampler.py）把整条链路写得很直白。类 docstring 列出了严格顺序：先做 allowed-token-ids 白名单、bad-words 排除、可影响贪心的 logits processor，再施加各类 penalty，然后才进 sample() 做温度缩放、top-k/top-p、softmax 与采样。

vllm/v1/sample/sampler.py — Sampler.forward（主干摘录）
pythondef forward(self, logits, sampling_metadata, ...):
    # 1) 用原始 logits（未惩罚、未缩放）算 top-k logprobs
    raw_logprobs = self.compute_logprobs(logits)   # log_softmax
    logits = logits.to(torch.float32)
    # 2) 白名单 / bad words / penalties
    logits = self.apply_logits_processors(logits, sampling_metadata, ...)
    # 3) 温度 / top-k / top-p / softmax / 采样
    sampled, processed_logprobs = self.sample(logits, sampling_metadata)
    ...
    return SamplerOutput(
        sampled_token_ids=sampled.unsqueeze(-1),  # [num_requests, 1]
        logprobs_tensors=logprobs_tensors,
    )

核心的 sample() 方法：先看是否全贪心（all_greedy）——是就直接 greedy_sample（即 logits.argmax(dim=-1)）返回；否则先 apply_temperature 做 logits.div_(temp.unsqueeze(1))，再跑 argmax 不变的 logits processor，最后交给 topk_topp_sampler。而温度内部对贪心请求把分母换成 1（避免除零）。

vllm/v1/sample/sampler.py — sample 中温度与 topk/topp
python# 温度：logits /= temperature（贪心请求分母换 1）
logits = self.apply_temperature(logits, sampling_metadata.temperature,
                                sampling_metadata.all_random)
# 只作用于随机采样的 logits processor（argmax 不变）
for processor in sampling_metadata.logitsprocs.argmax_invariant:
    logits = processor.apply(logits)
# top-k 与 top-p 截断 + softmax + 采样
random_sampled, _ = self.topk_topp_sampler(
    logits, sampling_metadata.generators,
    sampling_metadata.top_k, sampling_metadata.top_p)
注意一个细节：vLLM 的随机采样并没有显式调用 torch.multinomial，而是用「指数噪声技巧」——定义在 vllm/v1/sample/ops/topk_topp_sampler.py，先把 top-k/top-p 之外的 logits 打成 -inf，softmax 后 probs.div_(q).argmax() 得到采样结果。之所以绕开 multinomial，是为了避免它带来的 CPU-GPU 同步开销。

6.4Sampler 与采样元数据：一整个 batch 一次算完

采样层的关键设计是把所有请求并成一个 batch 向量化算。为此需要一个描述「这个 batch 各自怎么采样」的结构——SamplingMetadata（vllm/v1/sample/metadata.py）：

vllm/v1/sample/metadata.py — SamplingMetadata（字段摘录）
pythontemperature: torch.Tensor | None   # 每请求一个温度（batch 向量）
all_greedy: bool                       # 整批都是贪心？可跳过整段随机逻辑
all_random: bool
top_p: torch.Tensor | None
top_k: torch.Tensor | None
generators: dict[int, torch.Generator] # 有 seed 的请求的 PRNG
no_penalties: bool                     # 无 penalty → 跳过惩罚分支
frequency_penalties: torch.Tensor
presence_penalties: torch.Tensor
repetition_penalties: torch.Tensor
output_token_ids: list[list[int]]        # 已生成的 token，供 penalty 参考

这些字段几乎全是对齐 batch 的 tensor：temperature、top_k、top_p、各类 penalty 都是每请求一个值。于是 Sampler.forward 一次就能对整个 batch 的 logits 做后处理并采样，返回 SamplerOutput（形状 [num_requests, 1] 的 sampled_token_ids）。性能优化点：no_penalties、all_greedy 这类「整批布尔」让常见简单场景直接走快捷路径，不动 penalty 分支。

读懂采样元数据：它是「逐请求采样参数 → 对齐 batch 的 tensor」这一转换的产物。自研引擎哪怕只做单请求，也从一开始就按 batch 向量的形状组织采样参数，为后续并发铺路。

6.5解码与停止：token 怎么变成文本、请求怎么结束

采样给出的是 token id 序列，要让用户看到文本，得解码（detokenize）。vLLM 的 vllm/v1/engine/detokenizer.py 提供 IncrementalDetokenizer —— 增量解码：每来一个新 token 只解这段、拼进已有的文本，而不是每次都重解整条序列。它分两类：快路径 FastIncrementalDetokenizer（走 tokenizers 库的 DecodeStream）和慢路径 SlowIncrementalDetokenizer。

vllm/v1/engine/detokenizer.py — IncrementalDetokenizer.update（摘录）
pythondef update(self, new_token_ids, stop_terminated):
    # 1) 增量解码新 token，拼进 output_text
    for new_token_id in new_token_ids:
        self.token_ids.append(new_token_id)
        self.output_text += self.decode_next(new_token_id)
    # 2) 在此之后还要对 stop 字符串做匹配（见 update 返回的 stop 串）

请求怎么结束？有三道闸门，任一命中即终止本次生成：

  • EOS / stop_token_ids：采到了 EOS 或 stop_token_ids 里的 id。引擎会把这些 id 合并进 SamplingParams.all_stop_token_ids（见 update_from_generation_config）。
  • stop 字符串：需要先解码才能判断「文本里出现 stop 串」。这也是为什么 stop 只在 detokenize=True 时被允许。__post_init__ 里还专门算了个 output_text_buffer_length，把末尾可能构成 stop 前缀的那几个字符「扣住」不吐给用户。
  • max_tokens：达到上限强制结束（兜底保证不无限生成）。

ignore_eos=True 则忽略 EOS 继续生成（但仍受 max_tokens 约束）。

6.6束搜索与多路采样 | n / best_of

除了单路随机/贪心，还有两类「一次出多条候选」的能力：

  • 多条独立采样（n）：同一个 prompt 独立跑 n 条序列，各自随机，互相不共享信息。用于多次采样取最佳、或做诸如「多次尝试」的对比。
  • 束搜索（beam search）：真正的启发式搜索——每一步保留概率最高的 beam_width 条序列，权衡「长度惩罚」后择优。vLLM 用独立的 BeamSearchParams（vllm/sampling_params.py），字段为 beam_width、max_tokens、length_penalty、temperature=0.0。
vllm/sampling_params.py — BeamSearchParams（字段摘录）
pythonclass BeamSearchParams(msgspec.Struct, ...):
    beam_width: int          # 每步保留几条序列
    max_tokens: int
    ignore_eos: bool = False
    temperature: float = 0.0   # 束搜索通常是贪心的扩展
    length_penalty: float = 1.0
辨析：n 是「独立并行」，beam 是「共享搜索树」——两者要的显存/算力都随路数成倍上涨。绝大多数在线服务用 n=1 单路就够，beam 更适合离线评测。

6.7小结与自研启示

概念vLLM 实现你的引擎可以做
贪心greedy_sample → argmax先做这个，最简单、最好 debug
温度apply_temperature（logits/temp）第二版加温度，复用同一份 logits 路径
top-k / top-papply_top_k_top_p → -inf 掩码top-k 最便宜（一次 topk），top-p 要排序，后加
penalty / bad wordsapply_all_penalties 等明确不需要就先跳过，靠 all_greedy 快路径
多路 / beamn / BeamSearchParams最后再加；fallback 到跑 n 次即可
自研启示 最小引擎只需要：argmax + 温度采样 + top_k 三个足矣跑通一条对话链路。penalty、bad-words、beam 全是增量优化——把采样参数、采样元数据从一开始就按「batch 向量」的形状设计，未来加功能才不会返工。
