学习路径

STEP 1

整体架构

v1 引擎的层次划分：Engine / Executor / Core / Scheduler / Worker / Model Runner，以及它们如何拼成一台「机器」。
STEP 2

请求全生命周期

从 LLM.generate() 到流式输出的完整旅程，逐层传参，SVG 泳道图；含重叠调度（CPU 调度与 GPU 执行并行）。
STEP 3

PagedAttention & KV cache

分页管理 KV cache：BlockPool / KVCacheManager 如何按块分配、复用与回收。
STEP 4

调度器 Scheduler

continuous batching、统一调度、优先级/抢占、PD 分离（prefill/decode 分离式部署）。
STEP 5

Model Runner

把一批请求组装成 GPU 张量、喂给模型、CUDA Graph 捕获与 KV cache 传递。
STEP 6

采样 Sampling

SamplingParams、logits 后处理、Sampler、beam search，以及投机解码的草稿-验证与 rejection sampler。
STEP 7

Kernel 层

注意力后端（FlashAttention / FlashInfer）、GEMM、自定义算子入口 _custom_ops.py，为什么快。
STEP 8

内存与 KV 预算

显存如何被划分：model + KV cache + activation，max_num_seqs、前缀缓存 prefix caching。
STEP 9

服务入口

OpenAI 兼容 API Server、AsyncLLMEngine、并发与流式输出、EngineCore 分离部署；含性能指标（TTFT/ITL/Prometheus/MFU）。
STEP 10

分布式推理

TP / PP / DP / EP、Executor（uniproc / ray / multiproc）、张量并行通信。
ROADMAP

自制推理引擎路线图

把前面学到的拆成可落地的里程碑：最小单请求引擎 → 连续批处理 → 调度 → 并行。
实战

实战：模型权重加载

vLLM 是怎么把 DeepSeek-V4 / GLM-5.2 / Kimi-K2 这些开源权重加载起来、并让它跑得快又好：注册表 → loader → load_weights 重映射 → 量化/稀疏调优。
实战

实战：Agentic 网关

拆解 vllm-project/agentic-api：一个坐在 vLLM 前面的有状态 Rust 网关——previous_response_id 状态恢复、服务端工具循环（≤10 轮）、工具所有权路由、SSE 流重组、compaction 压缩。
实战

实战：国产开源模型架构变迁

追踪 DeepSeek-V4/V4.1、GLM-5.2/5.3-Flash、Kimi-K2.6/K3、Qwen3.8/Flash-Next 的架构演进：稀疏索引省法（共享/池化/块级）、残差流变体（mHC/GatedResidual/AttnRes）、线性注意力混合，以及每项创新在引擎侧留下的新机制（KVCacheSpec、model_states、CacheDType）。
