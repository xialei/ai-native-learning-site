自制 Agent Runtime：十章所学，一张施工图

这是本站的终点，也是你目标的起点。前面十一章把 Pi 的运行时拆成了清晰的分层与机制；这一页把它们反着拼回去——给你一条「从零造一个自己的 Agent Runtime」的演进式施工路线，每阶段都引用学过的概念与可直接借鉴的 Pi 源码。

12.1战略：别一口吃成 Pi

Pi 的老玩家一看就懂：它不是一天写出来的，而是从一个纯循环，逐层长出会话、压缩、harness、工具。所以自制 Runtime 的最大战略是阶段化演进——先让「能跑」，再让「能聊与能记」，再让「能自救」，最后才「能动手、能接万物」。

关键纪律：每一阶段结束时，它都是一个能独立运行、被验证过的正确小系统。不要为了「提前支持分叉」而在还没有会话记忆时硬写。这比 Pi 的成熟分层的最大优势是——每个里程碑都有可运行的东西。

12.2阶段 ①：一个最小但「完整」的循环

从第 3 章的 runAgentLoop 提炼。别急着做全部，先做一个能自洽循环的最小核心：prompt → 模型流式 → 若有 toolCall 则执行 → 把结果回填 → 再 prompt，直到 assistant 不再要求工具。这是后面一切的骨架。

最小循环雏形（ts 伪码，借鉴第 3 章）
async function runTurn(messages, tools, streamFns) {
  // ① 把消息投给模型，流式收 assistant 分块
  const assistant = await streamAssistant(messages, tools);

  // ② 若模型要调工具 —— 逐条执行并把结果回填
  for (const tc of assistant.toolCalls) {
    const result = await tools[tc.name].execute(tc.id, tc.arguments);
    messages.push({ role: "toolResult", toolCallId: tc.id, toolName: tc.name, content: result });
  }

  // ③ 若刚执行了工具，就继续让模型看结果 —— 这就是「内层循环」
  if (assistant.toolCalls.length > 0) return runTurn(messages, tools, streamFns);
  return assistant; // 没有工具调用 → 本轮回答完成
}

阶段①验收标准（每条都要真能跑通）：

  • 文本回复能流式/完整返回。
  • 模型请求调一个工具，工具能执行，结果能回填，模型能基于结果继续。
  • 工具不存在 / 抛异常时，能把错误当消息喂回给模型（抄第 9 章的 `immediate` 错误策略），而不是崩掉。
现在就开始做「错误进流」：阶段①就养成「错误当消息不抛出」的习惯（第 10 章的黄金纪律）。它在后面对齐重试/压缩时你会感激自己——因为你的循环从一开始就「读得了错误」，而不用后面大规模改写。

12.3阶段 ②：让对话活到下次启动

阶段①的 messages 住在内存里，一关就没了。阶段②加入持久化。这里不必照抄 Pi 的 Lane/Entry 树全量机制（第 4 章很重），但要点是相同的三件事：

  1. 消息顺序稳定：每条消息有单调递增的 id/seq，顺序不可靠的 append 会毁掉一切上下文。
  2. 追加不可变：历史一旦写入不再原地改（除非明确地做「替换/分叉」）。这保住了「上下文为什么是对的」。（第 4 章的 append-only 纪律）
  3. 恢复重建：启动时读回历史 → 重建 messages 数组 → 直接复用阶段①的循环。这就是「会话即状态」——模型选择、系统提示也能跟着恢复（第 11 章 createAgentSession 的模型恢复）。
最简 JSONL 会话（借鉴第 4 章 append-only）
// 每条消息追加一行 JSON，天然 append-only；id 递增
{"id": 1, "role": "user", "content": "你好"}
{"id": 2, "role": "assistant", "content": "你好！"}
// 启动时逐行读回并 push 进内存数组，即可恢复对话

这个阶段你也许会想滑向「多会话、分叉」——先忍住。先保证「单会话能持久、能恢复」，多会话只是换一个文件名的扩展。

12.4阶段 ③：上下文会「太长」，得会压缩

任何长对话都会撞上 contextWindow。阶段③的功课来自第 5、6 章，但可以简化到「自动触发 + 摘要替换」两点：

  • 何时触发：算 token（估算即可，不必精确），超过阈值或模型报「上下文溢出」时触发。抄第 6 章 shouldCompact 的思想。
  • 怎么压：把最早的一批消息喂给「摘要模型」讨一句总结，用摘要消息替换掉那批原始消息，保留尾部最近的若干条原文（retainedTail）。
  • 溢出怎么办：被截断的回复先剥掉，压缩后再让模型重试一次（第 8 章 _overflowRecoveryAttempted 只试一次的防循环）。
最小压缩策略（借鉴第 6 章）
function shouldCompact(contextTokens, contextWindow, settings): boolean {
  return settings.enabled &&
    contextTokens > (contextWindow - settings.reserveTokens);
}
// 触发后：
// 1) findCutPoint：找到「该压的边界」
// 2) generateSummary：旧消息 → 摘要（用 streamSimple 轻量调用）
// 3) compact：摘要替换 + 保留尾部原文，重写消息数组
压缩是「能力天花板」：没有压缩，你的 Agent 只能在短对话里正常工作；有了它，才能接长任务。这是从「demo」走向「能干活」的分水岭。注意「只试一次」的防抖——宁可透明地失败提示，也不要静默死循环。

12.5阶段 ④：把它变成真正的「Harness」

到阶段③，你的系统还是「一次一轮」的拉模式。阶段④引入 Pi 第 7、8 章的核心：操作状态机 + 事件驱动 + 队列 + 钩子。这是让它从「库」变成「运行时/平台」的关键升级。

  1. 操作状态机：明确定义「run / compact / navigate」等操作及其 outcome。这让外部（UI、调用方）知道此刻系统在干什么、下一步能干什么（第 7 章）。
  2. 事件驱动：把内部变化（message_update / tool_execution_update / agent_settled）广播出去，UI 只订阅事件、只调方法。核心与外壳就此解耦（第 11 章的外壳红利在此兑现）。
  3. 双队列：引入 steer（打断）与 followUp（跟随）——先做 followUp（简单），再做 steer。两者让「运行中还能安全地追加/打断输入」成为可能（第 8 章）。
  4. 钩子体系：在关键节点留钩子（before_run、transform_context、before_tool、after_tool…）。这一步把「框架给你实现」变成「你能给别人扩展」（第 8 章 event bridge）。
Harness 化之后的最小形态
// 外部接口（抄第 7、8 章 AgentLane / AgentSession）
harness.prompt(text, { streamingBehavior: "followUp" })  // 运行或排入 followUp 队列
harness.steer(text)       // 打断当前动作，注入新输入
harness.abort()          // 中止并妥善持久化未决状态
harness.on("message_update", render)  // 订阅事件
这就是「你的 Agent Runtime」诞生的节点：当外部可以通过统一方法 + 统一事件驱动它，而不再直接戳内部数据结构时，你就拥有了一件「装备好了的运行时」，而非一堆函数。

12.6阶段 ⑤：工具三板斧与多 Provider

最后加上「能动手」与「接万物」两件事，然后你就会自然长成与 Pi 类似的形态：

  • 工具三阶段管线：prepare（校验+权限钩子）→ execute（含 signal 可中止 + 流式 update）→ finalize（可改写+terminate）（第 9 章）。给工具统一的 signal，你的「打断」才能落到真实 IO 上。
  • 多 Provider 抽象：定义你自己的 Model 值对象（窗口/输出/能力）与 stream() 契约，Anthropic/OpenAI/本地网关各自实现（第 10 章）。「错误进流、签名回传、默认采样」这些细节越早定越好。
  • 会话替换与分叉：当你能稳定跑完 ①-④，再补 /new /fork 的严格拆装协议（abort→shutdown→置換→rebind，第 8 章），让「运行中换会话不丢数据」。

到这一步，你的结构已经和 Pi 是同一个骨架，只是细节深度不同。剩下的就是让每一个「轮子」更圆——更多的工具、更多的钩子、更稳的压缩。

12.7结语：你现在拥有了一幅完整地图

到这里，你从「我要做一个 Agent Runtime」出发，已经完成了三段旅程：

  1. 概念：掌握了循环、会话、上下文、压缩、harness、工具、AI 层的完整心智模型。
  2. 源码验证：每一章都对应 Pi 中真实存在、可打开读的代码。
  3. 施工图：一条五阶段演进路线，每一步都有可运行输出与可借鉴的源码。

现在，打开你的编辑器，从阶段①那十几行循环开始。当你真的想把 session 落盘、真的想处理上下文溢出、真的想支持打断时——你已经知道该往哪看、该抄谁了。祝造出自己的 Agent Runtime。
