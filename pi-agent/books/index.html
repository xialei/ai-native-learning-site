Pi 特色与设计哲学

Pi 自我定位是「极简、可改、不替你决定工作流」。下面把 pi.dev 产品页的几条重点特色，对应到本站可以读到的源码章节——看完产品话术，再去看它怎么实现的。

▦

极简 Harness，原语而非功能

Pi 开箱即用却不内置子 Agent、计划模式、权限弹窗——这些「功能」被拆成可由扩展自建的原语。改 harness，不改你的工作流。

✓ 它给你的，是原语

  • 扩展 Extensions：TypeScript 模块，能拿到工具 / 命令 / 快捷键 / 事件 / 整个 TUI
  • 技能 Skills：带指令和工具的能力包，按需载入，渐进披露而不破提示缓存
  • 提示模板 Prompt templates：Markdown 写成、/name 展开
  • 主题 Themes、动态上下文（每轮前注入消息 / 过滤历史 / RAG / 长期记忆）

打不成包就装包：pi install npm:@foo/pi-tools，或 pi install git:github.com/.../pi-doom——它甚至能玩 DOOM。

✗ 我们故意没做的

  • No MCP——用带 README 的 CLI 工具（见 Skills），或写个扩展加 MCP 支持
  • No 子 Agent——经 tmux 拉起 Pi 实例，或用扩展自建
  • No 权限弹窗——跑容器里，或用扩展搭你自己的确认流
  • No 计划模式 / No 内置 to-do / No 后台 bash——写文件里、用 tmux，全可观测可直连

Pi 狂热地追求可扩展，是为了不必替你规定工作流：别的工具烤进内核的东西，你都能自己搭，或装个合你脾气的包。

学习路径

STEP 1

整体架构

monorepo 各包的关系，两层运行时（基础层 pi-agent-core 与生产层 pi-coding-agent），一次 prompt 从哪里走到哪里。
STEP 2

消息与类型体系

AgentMessage（可扩展）如何桥接到 LLM 真正认识的 Message；convertToLlm 的过滤与转换。
STEP 3

基础 Agent 循环

agentLoop / runLoop：turn、streaming、工具执行、steering/follow-up 队列、完整事件时序。
STEP 4

会话与存储模型

Lanes / Entries / Records / Facts，append-only 会话树，SessionState，内存与 SQLite 后端，fork。
STEP 5

上下文构建 Context

★ 重点。buildSessionContext：条目如何投影成 LLM 消息，compaction 前置、扩展点、状态派生。
STEP 6

上下文压缩 Compaction

token 预算、阈值触发、让模型生成 summary、尾部保留、分支摘要。
STEP 7

Harness 运行时骨架

★ 重点。契约 vs 同包 runtime 实现、Result 化的操作结果、accept+drive 两段驱动、13 个持久化状态叶子。
STEP 8

生产 Harness

生产级 agent-session：真实 run 循环、hooks 生命周期、崩溃恢复/挂起、steer/followUp/nextRun 队列。
STEP 9

内置工具

AgentTool 接口、ToolContext、read/write/edit/edit-diff、file-mutation-queue、bash、参数校验。
STEP 10

AI 抽象层 pi-ai

统一多 provider API、Models/Model、流式、重试、usage 与 prompt caching。
STEP 11

编码 Agent 组装

CLI/TUI、技能 skills、提示词模板、扩展、遥测、会话导出。
ROADMAP

自制 Agent Runtime 路线图

把前面学到的一切拆成可落地的里程碑：最小循环 → 会话模型 → 上下文/压缩 → 工具 → 持久化 → 恢复。
BOUNDARY

安全·本地模型·程序化集成

在外围收好三个边界：项目信任与沙箱隔离、把 llama.cpp 本地模型接成 Provider、以及 SDK / RPC / JSON 事件流三种程序化嵌入方式。
COMPARE

Pi vs LangGraph 逐项对比

把 Pi 和「图优先」的 LangGraph 沿六个维度并排：设计哲学、核心能力、适用场景、开发体验、灵活性、生产就绪——看清各自把复杂度放在哪。
