Steer 或 Follow up

Agent 跑着的时候照样能插话：Enter 发 steering（当前工具后送达、打断余下工具），Alt+Enter 发 follow-up（等它跑完再说）。

✓ 它给你的，是原语

  • 扩展 Extensions：TypeScript 模块，能拿到工具 / 命令 / 快捷键 / 事件 / 整个 TUI
  • 技能 Skills：带指令和工具的能力包，按需载入，渐进披露而不破提示缓存
  • 提示模板 Prompt templates：Markdown 写成、/name 展开
  • 主题 Themes、动态上下文（每轮前注入消息 / 过滤历史 / RAG / 长期记忆）

打不成包就装包：pi install npm:@foo/pi-tools，或 pi install git:github.com/.../pi-doom——它甚至能玩 DOOM。

✗ 我们故意没做的

  • No MCP——用带 README 的 CLI 工具（见 Skills），或写个扩展加 MCP 支持
  • No 子 Agent——经 tmux 拉起 Pi 实例，或用扩展自建
  • No 权限弹窗——跑容器里，或用扩展搭你自己的确认流
  • No 计划模式 / No 内置 to-do / No 后台 bash——写文件里、用 tmux，全可观测可直连

Pi 狂热地追求可扩展，是为了不必替你规定工作流：别的工具烤进内核的东西，你都能自己搭，或装个合你脾气的包。

全书词表

各章反复出现的术语收拢在这里，按学习路径顺序排列。「详见」指向讲得最透的章节；读正文遇到陌生词，先回来查这一张表。

术语含义详见
两层运行时基础层 pi-agent-core 是无 UI、无内置工具的纯「运行时引擎」；生产层 pi-coding-agent 把它接上真实工具与 TUI——你平时用的 pi 是后者。01 §1.2
Harness包在 Agent 循环外的那一层：Context 决定模型看到什么，Harness 决定这一切如何被驱动、持久化、并在崩溃后重生。07 §7.1
AgentMessage / Message「宽」的运行时消息类型（可扩展）与「窄」的 LLM 消息类型；运行时里流转前者，发给模型前窄化成后者。02 §2.2
convertToLlmAgentMessage → Message 的唯一窄化出口，是两套类型体系之间唯一的那座桥。02 §2.3
Agent 循环（agentLoop）内层 turn 循环 + 外层 follow-up 循环的主循环：turn 跑到底（含工具循环），有跟问消息就再开新 turn。03 §3.2
turn（轮）循环的内层单位：一次「调模型 → 拿回复 → 跑完它要的工具」的完整过程。03 §3.2
steering（操纵）Agent 跑着的时候插进去的话：当前工具执行完后送达、打断余下还没跑的工具；与 follow-up 分住 Agent 类里的两个队列。03 §3.5
follow-up（跟问）排队的跟问消息：等当前 run 跑完再开新 turn；流式时与 steering 分走两条消息队列。08 §8.3
会话树（append-only）会话不是「消息数组」，而是一棵只追加（append-only）的 Entry 树；回溯把 tip 指针拨回历史节点，再追加就长出新分支。04 §4.2
Entry / 簿记值会话树节点，装可进 LLM 的内容（四个 type）；旁边还有一组不进 LLM 的带类型地址簿记值（branch tip、lane 配置、usage 行等）。04 §4.2
Lane（车道）「分支怎么长」的指针：存储层叫 Branch，运行层叫 AgentLane，每条 lane 记着自己停在哪个叶子上。04 §4.3
fork（分叉）从一棵会话树复制一条路径长出另一棵：副本继承源树的 seq 与 lane 配置，两边此后互不干扰。04 §4.5
存储后端（Storage）内存 / JSONL / SQLite 三种实现共用一个 Storage 接口；所有写入在一个事务里按 seq 严格递增提交。04 §4.6
Context（上下文构建）每轮调模型前，把分支里的 Entry 挑选、重排、投影成一串能发给 LLM 的消息——Agent 的「记忆」真正呈现在模型面前的地方。05 §5.2
投影（projection）「一条 Entry 变成几条 LLM 消息」的规则：普通消息一条对一条，compaction 条目展开成「摘要 + 尾巴」多条。05 §5.3
stopReasonassistant 消息自带的「为什么停」标记；error / aborted / deferred 的消息在投影时被丢弃，不进上下文。05 §5.3
Compaction（压缩）把旧历史交给 LLM 生成一份结构化摘要、用 compaction 条目替换，同时保留最近一小段「尾巴」——模型永远只看到「摘要 + 最近细节」。06 §6.1
token 预算压缩何时触发的两笔账：token 涨过「窗口 − 预留」即触发 shouldCompact，切割点由「保留最近 keepRecentTokens」反推。06 §6.2
accept + driveHarness 的两段驱动：accept() 准入操作、只写盘不动手；drive() 沿状态叶子一步步推到结算——两步之间进程随时可以死。07 §7.3
持久化状态叶子任意时刻的运行现场被归纳成恰好 13 个状态叶子；崩溃恢复就是从盘上最后一个叶子继续 drive。07 §7.4
挂起（deferred）run 没跑完就先停下：结果不是 success / failed，而是一条可 resume 的 SuspendedRun 记录，之后从现场接着跑。07 §7.2
AgentSession生产 harness：把 agentLoop 包成「有记忆、能恢复、可排队、可扩展」的会话对象——它不是另一个循环，而是循环外面的一层壳。08 §8.1
abort（中止）打断当前 run 的操作；收尾有讲究：abort 先把当前 turn（含工具结果）妥善落盘，再发 session_shutdown 事件给扩展留清理钩子。08 §8.6
扩展（Extension）TypeScript 模块，经 ExtensionRunner 拿到工具 / 命令 / 快捷键 / 事件，能挂进生命周期的每个环节，包括每轮前注入消息、过滤历史。08 §8.4
AgentTool工具契约：继承 pi-ai 的 Tool，核心是 label、parameters schema（给模型的说明书）和 execute（真正动手），另有 prepareArguments / replay 等可选增强。09 §9.1
pi-ai（AI 层）摸到模型的统一手掌：一个 Model 值对象 + 一套 stream() 契约，把 15+ Provider、数百个模型统一成上层循环只认的一种流协议。10 §10.1
