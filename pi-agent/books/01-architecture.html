整体架构：Pi 这台「Agent 机器」由哪些部件组成

Pi 是一个 monorepo，但真正重要的是它把「Agent 运行时」拆成了两层：可复用的基础层与自带 UI/工具的生产层。下面把整台机器拆开，看清每个包各管什么。

1.1一分钟版本

一个 Agent 运行时，本质上是在回答三个问题：① 模型下一轮该看到什么（Context）？② 这一轮要做什么（调用 LLM / 执行工具）？③ 这一切如何被记住、并能在崩溃后重建（Session）？ Pi 把这三个问题的答案分别落在三个包里：

  • @earendil-works/pi-ai — LLM 抽象：多 provider 统一 API、模型注册、流式、重试。
  • @earendil-works/pi-agent-core — Agent 内核：状态的 agent-loop、会话树/存储模型、上下文构建、压缩。
  • @earendil-works/pi-coding-agent — 生产 harness：把内核接上真实工具（bash/读写文件）、TUI/CLI、技能、扩展、遥测。

关键洞察：基础层是无 UI、无内置工具的纯「运行时引擎」；生产层才是你平时用到的 pi。 想自己做 Agent Runtime，你真正要消化的是前两个包——尤其是 agent 包里的 session 与 harness。

1.3用代码看｜最简内核怎么用

基础层（pi-agent-core）暴露一个 Agent 类。它是「有状态的事件循环 + 工具执行」的封装，完全不知道文件系统或终端长什么样。

packages/agent/README.md — 最简 Agent 用法
typescriptimport { Agent } from "@earendil-works/pi-agent-core";
import { createModels } from "@earendil-works/pi-ai";

const models = createModels();
models.setProvider(anthropicProvider());          // 注册一个 provider
const model = models.getModel("anthropic", "claude-sonnet-4-6");

const agent = new Agent({
  initialState: { systemPrompt: "You are a helpful assistant.", model },
  streamFn: models.streamSimple.bind(models),      // 注入"怎么把消息发给模型"
});

agent.subscribe((event) => {
  if (event.type === "message_update") {
    process.stdout.write(event.assistantMessageEvent.delta); // 流式输出文本
  }
});

await agent.prompt("Hello!");
读懂这段： 两件事值得注意。① streamFn 是「依赖注入」点——内核不直接调 API，而是调用你给的 StreamFn，把「如何与 LLM 对话」完全外包给 pi-ai。② AgentMessage 是设计核心——循环全程用 AgentMessage，只在每次调 LLM 前一刻转换为 Message。这一点在 第 2 章 展开。

1.4基础层 vs 生产 harness：谁是「正主」

可能让你意外的是：packages/agent/src/harness/agent-harness.ts 里那个 AgentHarness 类只是一个接口基类——大部分方法直接抛 HarnessNotImplemented。真正可用的实现住在 coding-agent/src/core/agent-session.ts。

packages/agent/src/harness/agent-harness.ts — 基类 vs 实现的分工（节选）
typescriptexport class AgentHarness implements AgentLane {
  // 定义好"一条会话车道"该有什么能力（接口契约）
  async prompt(text: string): Promise<RunResult> {
    return this.unavailable("prompt");   // 基类：抛 HarnessNotImplemented
  }
  async compact(): Promise<CompactionResult> { return this.unavailable("compact"); }
  // ... 大量方法都是基类占位，真正的逻辑在 coding-agent 的 agent-session
}
为什么这么设计： 把「运行时该长什么样」的契约放在最核心、最不依赖平台的地方（agent-harness.ts 定义了 AgentLane 接口、操作状态机、Outcome 类型），而把实现留给更上层的包。这也是你自研时的范本：先定接口契约，再分层实现。第 7、8 章会彻底拆开这条线。

1.6对自研与使用的第一个启示

要点 别一上来就做 TUI 和一堆工具。自研 Runtime 的 MVP 只需三件事串起来：① 一个最朴素的「LLM 调用 + 工具执行」循环；② 一个「这块会话该记住什么」的存储模型；③ 一个能构建 Context 并做压缩的函数。 这三件事恰好就是本章后面对应的 agent-loop + session + context/compaction。
