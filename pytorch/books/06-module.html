nn.Module：注册树、hook、state_dict 的三层来源

写模型时 self.linear = nn.Linear(...) 这行赋值背后，是一套注册机制在工作。这章拆 Module 的三个侧面：赋值时发生了什么（__setattr__ 的分流）、调用时发生了什么（_call_impl 的快慢路径）、checkpoint 靠什么格式（state_dict 的拼装）。

6.1self.linear = ... 那一瞬间

Python 赋值语句默认只是写 __dict__，但 Module 重写了 __setattr__，把每次赋值按类型分拣进三本账：参数（_parameters）、子模块（_modules）、缓冲（_buffers）。分类逻辑的第一段：

torch/nn/modules/module.py — __setattr__ 的参数分支（摘录，注释为译注）
pythondef __setattr__(self, name: str, value: Union[Tensor, "Module"]) -> None:
    def remove_from(*dicts_or_sets) -> None:
        for d in dicts_or_sets:
            if name in d:
                if isinstance(d, dict):
                    del d[name]
                else:
                    d.discard(name)

    params = self.__dict__.get("_parameters")
    if isinstance(value, Parameter):
        if params is None:
            raise AttributeError(
                "cannot assign parameters before Module.__init__() call"
            )
        remove_from(
            self.__dict__,
            self._buffers,
            self._modules,
            self._non_persistent_buffers_set,
        )
        self.register_parameter(name, value)

往下还有两个分支：value 是 Module 就进 self._modules[name]（顺带触发全局注册 hook），是普通 tensor 且名字已占用就进 buffers。三本账是 Module 一切能力的根——parameters() 能递归出全部参数、to(device) 能搬动整个模型、state_dict 能序列化，都是遍历这三本账。

读时的那半边：读取走 __getattr__——只在常规属性查找失败后才被调用，依次翻 _parameters、_buffers、_modules 三本账。这个顺序解释了一个日常细节：给子模块起名 training 或 forward 会出诡异行为——那些名字在常规查找就命中了，根本轮不到账本。另有一处容易忽视的报错也出自这里：在 __init__ 之前赋值参数会得到 "cannot assign parameters before Module.__init__() call"，因为 _parameters 字典还没建。

6.2调用：_call_impl 的快慢路径

前向调用 model(x) 实际调的是 _wrapped_call_impl → _call_impl。这个函数有个关键的分支：

torch/nn/modules/module.py — _call_impl（摘录，注释为译注）
pythondef _call_impl(self, *args, **kwargs):
    forward_call = (self._slow_forward if torch._C._is_tracing() else self.forward)
    # If we don't have any hooks, we want to skip the rest of the logic in
    # this function, and just call forward.
    if not (self._backward_hooks or self._backward_pre_hooks or self._forward_hooks or self._forward_pre_hooks
            or _global_backward_pre_hooks or _global_backward_hooks
            or _global_forward_hooks or _global_forward_pre_hooks):
        return forward_call(*args, **kwargs)

    result = None
    called_always_called_hooks = set()

    def inner():
        nonlocal result, args, kwargs
        ...
        result = forward_call(*args, **kwargs)
        if _global_forward_hooks or self._forward_hooks:
            for hook_id, hook in (
                *_global_forward_hooks.items(),
                *self._forward_hooks.items(),
            ):

开头一长串 or 是热路径的守卫：没有任何 hook 时直接 forward_call(*args)，连函数调用的壳都不多套一层。这个判断每层每次前向都要做一遍，所以在小模型、高频调用的场景下，hook 的存在与否是可测量的——「随手注册个 forward hook 调试」在大模型里不是免费的。注册了 hook 才进入 inner() 的慢路径：pre-hooks 改输入、forward_call、post-hooks 改输出，全套按注册顺序执行。

演进痕迹 源码里还有一行 torch._C._is_tracing() 的分支：在 torch.jit.trace 模式下走 _slow_forward。它是最早一代「图捕获」的痕迹——比第 9 章的 Dynamo 早了六年。今天写新代码不该再依赖它，但这行代码解释了为什么 Module 的调用协议里要预留「可替换的 forward」这个缝：后来的 compile、量化、并行都从这里进出。

6.3state_dict：名字是拼出来的

checkpoint 的通用格式是 state_dict——「参数名 → 张量」。这个名字不是存的时候起的，是 Module 树的路径：

图 6.1：state_dict 键名的来源。Module 树（__setattr__ 注册的）+ 属性名拼接 = checkpoint 里的键。这就是「加载别人的 checkpoint 时报 missing key / unexpected key」的机制根源：键名不匹配，本质是两边 Module 树的形状或命名不一致。

第三方的权重文件能直接 load 进 PyTorch 模型，靠的从来不是格式兼容，而是「名字对得上」。社区里大量的权重转换脚本（HF checkpoint → 自定义模型）本质都在做同一件事：把两边的拼名规则对齐。分布式时代这个机制升级成了 DCP（第 13 章），但「名字即契约」的原则没变。

6.4Module 层的三个实用推论

把机制换算成日常动作的解释：

  • 列表里放子模块会失效：self.layers = [nn.Linear(...)] * n 里的模块没进 _modules（Python list 不是 Module），parameters() 找不到它们。要用 nn.ModuleList/nn.ModuleDict——它们就是「把容器操作翻译成注册」的适配器。
  • to(device) 之后的参数多半还是同一批：Module._apply 对每个参数先算 fn(param)，再由 compute_should_use_set_data（module.py）决定怎么落账：新旧张量浅拷贝类型兼容时走 param.data = param_applied（第 2 章的 set_data 路径），Parameter 对象身份不变、autograd 元信息保留，hook 不用重挂；类型不兼容（如量化、DTensor 包装）或打开了 overwrite 开关时则换新 Parameter 对象，甚至 swap_tensors 整体置换。这也解释了「有人持有旧 param 引用时 to() 不生效」的传言：只有引用旧 TensorImpl 的情形才踩得到，普通 to() 走 set_data 并不换对象。
  • 训练/评测的开关是遍历：train()/eval() 就是把整棵树的 self.training 逐个置位。任何没注册进树的自定义结构（又见第一条）不会被切换——BN 层行为不对时先查这里。
要点 Module 的全部机制都源于重写的 __setattr__/__getattr__ 与三本账。记住「注册决定一切」：参数、子模块、buffer 注册了才存在，state_dict 名字、device 迁移、train/eval 切换全都以注册树为准。
